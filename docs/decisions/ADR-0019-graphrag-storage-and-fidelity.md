# ADR-0019: GraphRAG storage and fidelity

Date: 2026-11-13
Status: Accepted (owner approval 2026-11-13)

## Context
R38 (entity graph retrieval) and R39 (community summaries, global search) need a stored entity graph per index version. The graph is generated by a model, so it is derived data and never evidence by itself; every entity mention and relation carries a source span.

## Decision
- Migration 0011 (P7.2-03) adds four tables. Each row carries `tenant_id, project_id, index_version_id, graph_key`, and every child FK uses all four scope columns.
- `entity_graphs`: PK `(index_version_id, graph_key)`, global `UNIQUE (graph_key)`, `UNIQUE (tenant_id, project_id, index_version_id, graph_key)`, FK to `index_versions`, and a ready-only insert trigger.
- `graph_entities` and `graph_relations`: PK `(index_version_id, graph_key, entity_id | relation_id)` plus a 5-column scope unique, and a 4-column scope FK to `entity_graphs`. Relation `source_id` and `target_id` are FKs to `graph_entities`.
- `graph_spans`: PK `(index_version_id, graph_key, owner_kind, owner_id, ordinal)`, a scope FK to `entity_graphs`, FK to `chunks` and FK to `index_version_views`.
- Checks: ID patterns (`ent_`/`rel_` plus 16 hex, 64-hex key), `char_length(quote) = end_cp - start_cp`, label length 1-200, name 1-500, type 1-64.
- Trigger `graph_spans_validate_insert` checks (a) span view equals the chunk's view, (b) offsets inside the chunk, (c) quote equals the chunk text slice, (d) the owner exists in the same graph and scope.
- No-update triggers on all four tables reuse `reject_index_update()`, which migration 0003 owns; the downgrade must keep it.
- Rows are immutable, so incremental update is not supported. A change means a new graph.
- Provenance: `graph_spans` stores the extraction view and code-point offsets (the stable anchor) plus `chunk_id`, an index-local link. Rechunking creates a new index version and therefore a new graph.
- Deletion follows the index version, because the graph is derived data.
- The `EntityGraph` JSON (`rag_foundry.entity_graph/1`) is the export form, not the store.
- Community summaries are not persisted in P7.2. This is an open item.
- The port is `EntityGraphStore`, separate from `IndexRepository`, with an in-memory store and shared checks that SQL must pass unchanged.
- R38 and R39 are `retriever` plugins; the graph builders are helpers. Stdlib only, no new dependency.

## Consequences
Graph rows are scoped, immutable and traceable to source text. A new generator or chunking gives a new graph instead of edits.
