# ADR-0020: RAPTOR tree and KAG adaptation

Date: 2026-11-22
Status: Accepted (owner approved persistence 2026-11-22)

## Context
R37 (RAPTOR recursive summary tree) and R48 (schema-constrained KAG) need stored derived structures per index version. Both are generated by a model, so they are derived data and never evidence by itself; evidence is always original chunk text.

## Decision
- Persistence (owner approved 2026-11-22): migration `0012_summary_trees` adds `summary_trees`, `tree_nodes`, `tree_edges`; migration `0013_knowledge_graphs` adds `knowledge_graphs`, `kg_entities`, `kg_facts`, `kg_spans`. The SQL specs are P7.3-01b and P7.3-05b.
- Rows carry the scope columns; FKs go to `index_versions`, `index_version_views` and `chunks`. Inserts are ready-only, span triggers check quotes against chunk text, rows are never updated, and deletion follows the index version (as in ADR-0019).
- The JSON forms (`rag_foundry.summary_tree/1` and the KAG form) stay as the export format, not the store.
- Ports `SummaryTreeStore` and `KnowledgeGraphStore` are separate from `IndexRepository`, each with an in-memory store and shared checks that SQL must pass unchanged.
- RAPTOR summaries are synthetic and route retrieval only. Hits and citations are original leaf chunks. Summaries are not sent as answer context (owner decision 2026-11-22). Summaries hold child IDs only; lineage to leaf spans is computed on demand.
- KAG has its own model (`knowledge.py`), not `EntityGraph`: that model is R38-only, has no typed literals and no schema. KAG reuses `GraphSpan`. The KAG schema is validated in the domain, not in SQL.
- KAG planning: one plan call plus at most one re-plan on a defined failure status. There is no fallback to chunk retrieval. KAG returns a cited answer through `AnswerService` (owner decision 2026-11-22).
- No OpenSPG code, dependency or service; this is an original adaptation. Clustering is stdlib only (no numpy, sklearn or umap).
- R37 and R48 register as `retriever` plugins; the builders are helpers.
- Error codes for both are registered once in `IndexingError.CODES` (`tree_*`, `raptor_summary_invalid`, `kag_*`).

## KAG fidelity

## Consequences
Trees and graphs are scoped, immutable and traceable to source text. A new generator, embedding or chunking gives a new tree or graph instead of edits. Incremental update is not supported.
