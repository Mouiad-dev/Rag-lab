# ADR-0001: Provider-agnostic model layer

Date: 2026-10-26
Status: accepted (library choice re-verified 2026-11-02; P2.2 uses a direct Ollama adapter, see Update 2026-11-02)

## Context
Users must be able to pick any LLM, embedding or reranking provider: paid APIs (Anthropic, OpenAI, Google, Mistral, Cohere and others), free or open-weight models, and local runtimes (Ollama, LM Studio, vLLM). Kimi models from Moonshot are also wanted. The request said "km3"; we assume this means the Kimi K-series served by Moonshot's OpenAI-compatible API or as open weights through vLLM/Ollama. Confirm the exact model. A public install must work with zero paid keys. The old plan tied model access to LangChain integrations.

## Decision
1. **Own ports** in `packages/providers`: `ChatModel`, `EmbeddingModel`, `Reranker`, each with sync/async calls, streaming for chat, structured output where supported, and a `Usage` record (provider, model, tokens in/out, latency, estimated cost).
2. **Registry and model profiles.** A profile = provider + model ID + base URL (optional) + capability flags: `tool_calling`, `structured_output`, `vision`, `streaming`, `context_window`, `max_output_tokens`, `embedding_dim`, `token_embeddings`, `multivector`, `local`, `cost_per_mtok_in`, `cost_per_mtok_out`. Flags are declared in config and verified by an opt-in probe.
3. **Per-pipeline choice.** Each stage (generator, embedder, reranker, query_transform, judge, chunk_llm, scout) references a profile ID. The resolver rejects a pipeline whose stage needs a capability its profile lacks, before a job starts.
4. **Configuration.** Secrets only from env vars (for example `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`); profiles from `config/providers.yaml` (example: `config/providers.example.json`) and later the settings UI, which shows key presence, never values.
5. **Default adapter: LiteLLM**, wrapped by our ports. Native SDK adapters (for example the Anthropic SDK) may implement the same ports when a feature (prompt caching, extended thinking, batch) is not exposed well enough.
6. **Defaults.** Local: Ollama chat + Ollama embeddings. Paid example: Anthropic. Rerankers: a local cross-encoder plugin plus API rerankers through the port.
7. **Embedding identity** = provider + model + revision + preprocessing + dimension; changing any of these creates a new index (see PROJECT_ARCH.md §9).

## Alternatives
- **LangChain chat-model integrations only.** Rich ecosystem and already used for LangGraph, but one package per provider, uneven feature parity, frequent API churn, and framework types leaking into domain code. Kept as a consumer of our ports (a thin LangChain wrapper around `ChatModel`) for LangGraph workflows.
- **LiteLLM as default (chosen).** One dependency covers 100+ providers including Ollama, any OpenAI-compatible server (LM Studio, vLLM, Moonshot), Anthropic, Gemini, Mistral; unified chat, embedding and rerank calls; a maintained model cost map; optional proxy mode for teams. Risks: a broad, fast-moving dependency surface and occasional lag on new provider features. Mitigation: pin exact versions with hashes, wrap behind ports, keep native adapters possible, run a provider contract suite.
- **Native SDK per provider only.** Maximum fidelity but the most code to maintain; used selectively.
- **OpenAI-compatible HTTP only.** Simple and covers many local servers, but not every provider's native features or embeddings/rerank APIs.

## Consequences
- Domain and technique code never imports a vendor SDK (rule in `.claude/rules/10-architecture.md`).
- Cost and usage are measured uniformly, enabling budgets for experiments and the Tech Scout.
- Contract tests run against a fake provider in CI; live tests are opt-in and skipped without keys.
- Capability flags can be wrong; the probe and explicit errors are the guard. Cost estimates are estimates, not invoices.

## Evidence
To verify at P2.1 against current official docs: LiteLLM provider list, embedding/rerank support, cost map, async/streaming APIs; Ollama and LM Studio OpenAI-compatible endpoints; Moonshot API compatibility.

### Verified 2026-11-02 (P2.3-01), Anthropic Messages API
All access dates are 2026-11-02. Every source is an official page fetched with a plain HTTP GET (the `.md` rendering of the platform.claude.com docs, which `docs.claude.com` redirects to) or the official PyPI and GitHub APIs. Nothing was installed and no API call was made; no key was used. Doc base: `https://platform.claude.com/docs/en/` (written `D/` below). I did not fetch anthropic.com/pricing; the docs pricing page below is the full price list the docs themselves name.

1. **Endpoint and headers.** `POST https://api.anthropic.com/v1/messages`. Required: `anthropic-version` (current value `2026-10-21`, the newest in the version history), `content-type: application/json`, and auth. The overview lists `Authorization: Bearer <key>` as the primary header and `x-api-key` as a "legacy fallback ... still supported". Optional `anthropic-workspace-id` (needed only for keys not scoped to one workspace). Sources: `D/api/overview`, `D/api/versioning`, `D/api/messages` (retrieved 2026-11-02).
2. **Request.** `max_tokens` is required (a number, minimum 0). `messages` roles are `user` and `assistant` only; the system prompt is the top-level `system` (string or text blocks). Consecutive same-role turns are combined into one turn. A final `assistant` message is prefill; Claude Haiku 5.5 rejects prefill with 400 even with thinking off. **`temperature`, `top_p`, `top_k` are removed in `anthropic-version: 2026-10-21`: sending any returns 400 on every model, even at the default.** Haiku 5.5 and Sonnet 5.5 also return 400 for them (their migration guides say to omit them; for Sonnet 5.5 "Setting `temperature`, `top_p`, or `top_k` returns a 400 error"). The port field `temperature` must therefore not be sent to these models. **Thinking is ON by default for both models (adaptive)**, so output tokens include hidden thinking and a small `max_tokens` can end with `stop_reason: max_tokens` and no text. Haiku 5.5 accepts `thinking: {"type": "disabled"}` at effort `high` or below (default effort `medium`). Sonnet 5.5 rejects `disabled` with 400; use `thinking: {"type": "between_tools"}` (accepted at effort `high` or below). Thinking tokens are billed even when `display` is `omitted`. Sources: `D/api/messages`, `D/api/migration-2026-10-21`, `D/models/haiku-5-5/migration-guide`, `D/models/sonnet-5-5/migration-guide`, `D/build-with-claude/thinking` (retrieved 2026-11-02).
3. **Response.** Content block types in a non-streaming reply: `text`, `thinking`, `redacted_thinking`, `tool_use`, `server_tool_use`, plus server-tool result blocks (`web_search_tool_result`, `web_fetch_tool_result`, `code_execution_tool_result`, `bash_code_execution_tool_result`, `text_editor_code_execution_tool_result`, `tool_search_tool_result`) and `container_upload`. `stop_reason` values: `end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `pause_turn`, `refusal`, `model_context_window_exceeded` (non-null when not streaming; null in `message_start`). Also `stop_sequence` and `stop_details`. `usage` fields: `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `cache_creation.{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}`, `output_tokens_details.thinking_tokens` (a subset of `output_tokens`, which stays the billed total), `server_tool_use.{web_search_requests, web_fetch_requests}`, `service_tier` (`standard`, `priority` or `batch`), `inference_geo`. The reference says "Total input tokens in a request is the summation of `input_tokens`, `cache_creation_input_tokens`, and `cache_read_input_tokens`", so `input_tokens` excludes cached tokens. Source: `D/api/messages` (retrieved 2026-11-02).
4. **Streaming.** Flow: `message_start` (a Message with empty content; its `usage` carries the input counts), then per block `content_block_start`, `content_block_delta` (one or more), `content_block_stop`, then one or more `message_delta`, then `message_stop`. `ping` may appear anywhere; `error` may arrive mid-stream after a 200 (for example `overloaded_error`); unknown event types must be tolerated. "The token counts shown in the `usage` field of the `message_delta` event are cumulative." The reference types `MessageDeltaUsage` with cumulative `input_tokens` (nullable), `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`; the docs example shows only `output_tokens`, so treat the others as optional. Delta types: `text_delta`, `input_json_delta`, `thinking_delta`, `signature_delta`. Sources: `D/build-with-claude/streaming`, `D/api/messages` (retrieved 2026-11-02).
5. **Errors.** 400 `invalid_request_error` (also other 4xx, and spend-limit hits); 401 `authentication_error`; 402 `billing_error`; 403 `permission_error`; 404 `not_found_error`; 409 `conflict_error`; 413 `request_too_large` (Messages limit 128 MB); 429 `rate_limit_error` (a spend-cap 429 has no `retry-after` and keeps failing); 500 `api_error`; 504 `timeout_error`; 529 `overloaded_error`. Body: `{"type":"error","error":{"type":"...","message":"..."},"request_id":"req_..."}`. Every response has a `request-id` header with the same value. Source: `D/api/errors` (retrieved 2026-11-02).

**Verdict: FITS with direct httpx.** All facts needed for 03..05 were confirmed from official pages. Two changes versus the planning assumptions: `temperature` must not be sent, and thinking is on by default, so the adapter and the live test must set `thinking` explicitly (Haiku: `disabled`).

**Decision for P2.3: direct httpx adapter** (`rag-foundry-providers[anthropic]` using the already locked `httpx==0.28.1`; send `anthropic-version: 2026-10-21`). Reasons: no new dependency (the SDK would add `httpx2`, `anyio`, `jiter`, `opentelemetry-api` and others); `token_source` stays `PROVIDER` because the adapter reads the raw `usage` object including cache fields; no hidden retries (the SDK retries twice by default) and no logging switch to police; same pattern as the P2.2 Ollama adapter. No P2.3-scope feature needs the SDK. LiteLLM is not recommended: no pin is both 2 weeks old and outside every advisory range until 2026-11-11, it has a large dependency surface, and it would hide the raw usage fields.

**Live-run cost estimate (05), Haiku tier, about 8 calls, at most 64 output tokens and about 30 input tokens each.**
- Formula: cost = calls * (in_tokens * 0.10 + out_tokens * 0.50) / 1,000,000 = 8 * (30 * 0.10 + 64 * 0.50) / 1e6 = 8 * 35 / 1e6 = USD 0.000280 (input 0.000024 plus output 0.000256).
- Upper bound with `inference_geo: "us"` (1.1x): USD 0.000308.
- Thinking tokens count inside `max_tokens` and are billed as output, so the 64-token cap still bounds the cost. Send `thinking: {"type":"disabled"}` or the reply may contain no text.
- For reference, the same load on `claude-sonnet-5-5` is 8 * (30 * 2 + 64 * 10) / 1e6 = USD 0.005600.
- The newer tokenizer makes "about 30 input tokens" approximate; this is an estimate, not an invoice.

**Open points for 03..05 (not blockers).** (1) The version header is set to `2026-10-21`. The docs still describe `2023-06-01` as the previous version, but I found no sunset date for it (not confirmed). (2) The adapter must drop or reject the port's `temperature` field for these models. (3) Streaming `message_delta` `input_tokens` is nullable; take input counts from `message_start` and cumulative values from the last `message_delta`. (4) `Authorization: Bearer` and `x-api-key` are both documented; the spec names `x-api-key`, which the docs call "still supported".

**Owner decisions 2026-11-02 for 03..05.** Send `Authorization: Bearer <key>` (primary per the API overview; no `x-api-key`) and `anthropic-version: 2026-10-21`. A request that sets `temperature` is refused with a typed error, never silently dropped. Thinking is set explicitly: Haiku 5.5 profiles send `thinking: {"type": "disabled"}` (effort, if ever set, goes in `output_config.effort`); Sonnet 5.5 cannot disable thinking, so its default `max_tokens` leaves room for billed thinking tokens. Streaming takes input counts from `message_start` and cumulative counts from the last `message_delta`.
