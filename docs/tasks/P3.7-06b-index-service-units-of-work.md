## Goal
`IndexService` takes a `UnitOfWorkFactory`; view rows, index version, each chunk batch, `mark_ready` and `mark_failed` use separate short UoWs; no UoW is open during `embed` or payload reads. A failed build ends `failed` with the earlier batches kept, exactly as the 00 test pins.

## Change
- `IndexService(store, uow, anchors, *, batch_size, max_views)`:
  - Read all view rows in one read UoW, close it, then `read_payload` for each (no UoW during object-store reads).
  - Write UoW `create_index_version`, committed.
  - Per batch: `embed` with no UoW open; then `async with self._uow() as uow: await uow.indexes.add_chunks(...); await uow.commit()`.
  - Write UoW `mark_ready`, committed.
  - The `try` / `except BaseException` that calls `mark_failed` wraps the whole batch loop and sits outside every `async with`, so the failing UoW has exited (rolled back, its FOR UPDATE lock released) before a fresh write UoW runs `mark_failed` and commits; then re-raise. Code comment cites ADR-0015 D6 and the nested-write guard test in `tests/domain/test_uow.py` (a `mark_failed` inside the open UoW would raise there instead of waiting on its own lock).
  - Final `get_index_version` in a read UoW. `inspect_chunks`: read UoW for `list_chunks`, closed before anchor work.
- Wiring: `index_cli.py` and `tests/live/test_index_live.py`, `tests/indexing/test_index_db.py`, the 00 `_build` construct `IndexService` with `db.uow` (no `per_call_indexes` / `per_call_extractions` left for it; `index_cli` settings reads stay as they are until 07).
- Tests `tests/indexing/test_index_service.py` (constructions via `InMemoryUnitOfWorkFactory`; assertions unchanged) plus: `open_now == 0` inside every `embed` call and every object-store read; `embed` failing in batch 2 -> committed UoWs for create and batch 1, no UoW for batch 2, then one separate committed `mark_failed`; `add_chunks` failing in batch 2 -> that UoW rolled back and exited before the `mark_failed` UoW opens (assert via counters/ordering), state `failed`, batch-1 chunks present.
