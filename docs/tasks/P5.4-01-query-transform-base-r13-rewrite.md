## Goal
A shared module records every query transform the same way: the exact original question, each generated query marked synthetic, every chat `Usage`, the prompt sha256 and any lost hard constraints. R13 rewrites a question with one metered chat call, detects lost numbers/identifiers/quotes/negations, and never retrieves with a lossy rewrite unless told to fail.

## Change
- `errors.py`: append `"constraint_loss"`, `"invalid_dependency"`, `"too_many_queries"` to `QueryTransformError.CODES`.
- Create `rag_foundry_indexing/query_transform.py` (frozen, `extra="forbid"` models):
  - `GeneratedQuery`: `role: Literal["original","rewrite","variant","subquestion","step_back","hypothetical_document"]`, `text`, `synthetic: bool`, `id: str | None = None`, `depends_on: tuple[str, ...] = ()`, `lost_constraints: tuple[str, ...] = ()`.
  - `QueryTransformTrace`: `technique_id`, `status: Literal["applied","rejected","constraint_loss"]`, `reason: str | None`, `original_question`, `generated` (index 0 always role `original`, `synthetic=False`, text == original), `retrieval_queries: tuple[str, ...]` (exact strings sent to the retriever, in order), `usage: tuple[Usage, ...]`, `prompt_sha256`, `raw_text` (<= 500 chars), `lost_constraints`, `duplicates_dropped: int = 0`.
  - `TransformedRetrieval`: `trace`, `result: RetrievalResult`, `per_query: tuple[RetrievalResult, ...] = ()`.
  - `check_chat(chat)` (`missing_model`, `wrong_model_kind`), `check_question(q)` (`empty_query`, >2000 chars `query_too_long`).
  - `async call_json(chat, *, system, payload, schema, max_output_tokens, temperature) -> tuple[dict, ChatResult]`: one `ChatRequest` (system + user `json.dumps(payload, ensure_ascii=False)`), `response_schema` only if `structured_output is True`; `finish_reason == "length"` or unparsable gives `invalid_model_output` (same parsing as `self_query.py`).
  - `hard_constraints(text) -> tuple[str, ...]` (NFC, casefold, order of appearance, unique):
    - identifiers: tokens matching `[^\W_]+(?:[-./][^\W_]+)*` that contain a Unicode decimal digit (digits mapped to ASCII via `unicodedata.decimal`);
    - text inside `"..."` or `«...»`;
    - negations, recorded under a base form, over words matched by `[^\W_]+(?:['’][^\W_]+)?`. EN `not no never without except excluding cannot`, and any word ending in `n't` / `n’t` (isn't, don't, weren't), all recorded as `not`. AR base words `لا ليس غير بدون لم لن`, also with one attached prefix `و`, `ف` or `ب` (wa-la `ولا`, fa-la `فلا`, bi-la `بلا`), recorded as the base word.
  - `missing_constraints(original, texts)` returns the original's constraints absent from all `texts` under the same normalisation (a candidate's `don't` satisfies `not`).
- Create `rag_foundry_indexing/rewrite.py`: `REWRITE_SYSTEM_V1` (untrusted-data sentence; same language; keep every number, identifier, quoted phrase and negation; reply `{"query": "..."}`), `REWRITE_PROMPT_SHA256`; `RewriteConfig` (`max_output_tokens 32..512=128`, `temperature 0..2|None=0.0`, `on_invalid: fail|original = "fail"`, `on_constraint_loss: fail|original = "original"`); `QuestionRewriter` (R13, `QUERY_TRANSFORM`, `ADAPTATION`, `1.0.0`) with `async rewrite(question, *, chat) -> QueryTransformTrace` and `async retrieve_with_rewrite(question, *, rewriter, chat, retriever) -> TransformedRetrieval`. Exactly one key `query`, non-empty string <= 2000, else `invalid_model_output`. Loss gives status `constraint_loss`, `retrieval_queries == (original,)`, or raises `constraint_loss` in `fail` mode. `rejected` also retrieves with the original only. Register and export.
- Create `tests/indexing/_recording_retriever.py`: `RecordingRetriever(hits_by_query: dict[str, tuple[str, ...]], technique_id="R02", index_version_id="v1")`; records `queries`; returns ranked `RetrievedChunk`s (text = chunk id, span 0..len); an unknown query returns an empty `hits` tuple (no `KeyError`).
- Create `tests/indexing/test_rewrite.py` (non-ASCII only as `\u` escapes):
  - Applied path: the retriever saw the rewrite once; the trace keeps the exact original; `generated[1].synthetic`; 1 usage; the sha matches. The system prompt says untrusted. The Arabic question appears unescaped in the user message.
  - Constraint loss, one test each, for a dropped `2025`, `AB-1234`, `not`, `isn't`, Arabic `ليس`, and Arabic `ولا`. The retriever saw the original; `fail` mode raises. A rewrite using `does not` for `doesn't` keeps the constraint.
  - Arabic-Indic `٢٠٢٥` equals `2025`.
  - Bad JSON, `length`, an extra key and an empty query each give `invalid_model_output`; `original` mode gives `rejected`.
  - `BudgetedChatModel` with `max_calls=0` raises `BudgetExceededError`, with no request and no retrieval. Pre-call errors leave `requests == []`. `validate_config("R13", {}) == RewriteConfig()`.
