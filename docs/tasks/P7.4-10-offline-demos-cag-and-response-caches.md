- `docs/techniques/lessons/demos/p74_cag_demo.py`. Header: command, date, "offline; scripted answers; shows snapshot bounds, prefix stability and citations, not speed or answer quality; prefix reuse needs a real runtime (see live runs)". Sections:
  1. Snapshot: item count, estimated prompt tokens vs window, margin, reserve, `max_evidence_chars`; an overflow refusal with its numbers.
  2. Arms on 3 questions (EN, AR, out-of-corpus), run as blocks in this order: all `cag`, then all `full_context_uncached`, then R02 k=3. Per call: status, cited markers, answer-ledger calls, input tokens (scripted estimate, labelled); per arm "prefix identical across questions".
  3. Losing cases: overflow where R02 answers; out-of-corpus abstains in all arms; a corpus update gives a new snapshot (update cost = rebuild + cold prefill; not measured offline).
- `docs/techniques/lessons/demos/p74_response_cache_demo.py`. Header: "offline; scripted answers; test-only lexical embedder; small illustrative pair sets; not a benchmark". Sections:
  1. R50 table (request, outcome, reason, calls avoided): first run, repeat (hit), changed model, history turn, authz revision, index version, other tenant, forced collision (`scope_mismatch`), denied source, expired, pins mismatch, bypass `current` and `enriched`.

  3. Calibration from `semantic_pairs_v1.json`: per threshold dev and held-out rates with numerators/denominators, with and without the guard; chosen threshold or `None` with reason; entity-swap, month and unit losing cases.
  4. Usage per stage: answer ledger vs cache-embed ledger for cold and warm runs.
