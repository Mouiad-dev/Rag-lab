A new llama.cpp server adapter (`POST /completion`, `n_probs`) implements it; the Ollama adapter keeps its limit of 20 and rejects larger requests before I/O. ## Change
- `messages.py`: `TokenLogprob` gains `token_id: int | None = None` and `top_ids: tuple[int, ...] | None = None` (same length as `top` when set; validate). `RawCompletionRequest.top_logprobs` bound becomes `ge=1, le=65536`. Existing callers unchanged.
- `adapters/ollama.py`: `complete_raw` raises `ProviderCallError(reason="invalid_request")` before any HTTP call when `top_logprobs > 20` (server max, `r31_gguf_check.md` section 5).
- Create `adapters/llamacpp.py`: `llamacpp_raw_completion_profile(model, base_url="http://127.0.0.1:8091", ...)` declaring only `RAW_LOGPROBS` True (zero cost, local); `LlamaCppRawCompletionModel(profile, *, vocab_size: int | None = None, max_response_bytes: int = 64 * 1024 * 1024, timeout, transport=None)`. httpx only (lazy import, same `ollama` extra; add a `llamacpp` extra alias with the same pinned httpx if the extras pattern allows, else reuse `ollama`), no vendor SDK, never launches a binary.
  - Before I/O: missing capability -> `MissingCapabilityError`; `top_logprobs > vocab_size` (when known) -> `ProviderCallError(invalid_request)`.
  - Body: `prompt`, `n_predict`, `n_probs`, `temperature`, `top_k`, `top_p`, `min_p: 0`, `stream: false`, `cache_prompt: false`, `post_sampling_probs: false`, `stop` (list, when given), plus neutral penalty/extra samplers only if documented at that commit (e.g. `repeat_penalty: 1.0`, `presence_penalty: 0`, `frequency_penalty: 0`, `dry_multiplier: 0`, `xtc_probability: 0`, `typical_p: 1.0`). No chat template, no `messages`, no system prompt.
  - Response: read the body with a byte cap (stream it); over `max_response_bytes` -> `ProviderCallError(bad_response)` before JSON parsing. Parse strictly as untrusted: `content` str; `completion_probabilities` list, one entry per generated token with `id` int, `token` str, `logprob` finite and <= 1e-6, `top_logprobs` list of `{id, token, logprob}` with the same checks; ids in `[0, vocab_size)` when known; any mismatch -> `bad_response`. Map to `TokenLogprob(token, logprob, top, token_id, top_ids)`.
  - `finish_reason` from the documented stop fields (eos/word -> `stop`, limit -> `length`); usage from `tokens_evaluated` (input) and `tokens_predicted` (output), estimated as Ollama does when absent. Every failure after send is `ProviderCallError` (HTTP status mapping as in `_ollama_http.py`); no response text in messages.
- `contract_checks.py`: `check_raw_completion` also checks `len(top_ids) == len(top)` when `top_ids` is set.
- Tests `tests/providers/test_raw_completion_llamacpp.py` (httpx `MockTransport`): exact request body (all sampler fields, `cache_prompt` false, `post_sampling_probs` false, no `messages`/`system`); parsing with ids; usage and finish mapping; each bad-response case (non-finite, logprob > 1e-6, wrong types, id out of vocab, misaligned lists, missing fields); response over cap rejected (small cap in test); HTTP 500 -> `server_error`/status; connection error; non-opted profile and `top_logprobs > vocab_size` rejected with zero requests sent; `check_raw_completion` passes on the mock. In `test_raw_completion.py`: Ollama `top_logprobs=21` rejected with zero requests; `TokenLogprob` defaults keep old construction valid; misaligned `top_ids` rejected.
