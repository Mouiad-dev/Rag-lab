## Change
- Create `packages/storage/src/rag_foundry_storage/sql/migrations/versions/0004_prompt_templates.py` (revises `0003_minimal_index`; raw SQL; not mirrored in `models.py`):
  - `prompt_templates`: `id varchar(64) PRIMARY KEY` CHECK `~ '^[a-z0-9-]+-v[0-9]+$'`, `family varchar(64) NOT NULL`, `version integer NOT NULL` CHECK >= 1, `UNIQUE (family, version)`, `purpose varchar(16)` CHECK in ('grounded','ungrounded'), `system_text text NOT NULL` CHECK length 1..20000, `content_sha256 char(64) NOT NULL` CHECK `= encode(sha256(convert_to(system_text, 'UTF8')), 'hex')` (PostgreSQL `sha256(bytea)`; verify in the PG 18 docs), `created_by varchar(128) NOT NULL`, `created_at timestamptz NOT NULL DEFAULT clock_timestamp()`.
  - `prompt_activations`: `seq bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY`, `purpose`, `template_id` FK -> `prompt_templates(id)`, `activated_by varchar(128)`, `activated_at timestamptz DEFAULT clock_timestamp()`, `decision_ref varchar(200) NOT NULL`; BEFORE INSERT trigger rejecting a purpose different from the template's.
  - BEFORE UPDATE OR DELETE triggers on both tables that raise.
  - Seeds: module constants `_GROUNDED_V1`, `_GROUNDED_V2`, `_UNGROUNDED_V1` copied byte-identically from `GROUNDED_SYSTEM_V1`, `GROUNDED_SYSTEM`, `UNGROUNDED_SYSTEM` (ASCII). Insert with bound parameters (`op.execute(sa.text(...).bindparams(...))`; verify against the Alembic 1.20 `op.execute` docs); `content_sha256` from `hashlib`; `created_by='migration:0004'`. Activations in order: grounded-answer-v1 (`ADR-0013 D6`), grounded-answer-v2 (`ADR-0013 amendment 2026-11-06`), ungrounded-v1 (`ADR-0013 D6`).
  - Downgrade drops both tables and the trigger functions.
- Create `packages/storage/src/rag_foundry_storage/sql/prompt_store.py` (`SqlPromptTemplateStore(sessionmaker)`): bound parameters only; active = latest `seq` per purpose; unique violation on create -> `template_exists`; trigger purpose rejection -> `purpose_mismatch`; `sqlalchemy.exc.OperationalError` / `InterfaceError` -> `PromptError("store_unavailable")` raised without cause (no DB text); a row failing `PromptTemplate` validation -> `hash_mismatch`.
- DB tests (`-m db`, skip without `RAGF_TEST_DATABASE_URL`) `tests/storage/test_sql_prompt_store.py`: `PROMPT_STORE_CHECKS`; seeds (3 templates; active grounded `grounded-answer-v2`, ungrounded `ungrounded-v1`; v1 present, not active; three activation rows in order); UPDATE and DELETE rejected; insert with a wrong hash rejected by the CHECK; engine pointed at a closed local port -> `store_unavailable`; a sync test (outside `run`) that runs `run_migrations(url, "downgrade", "0003_minimal_index")` then `upgrade head` and finds the seeds again.
- Offline test `tests/storage/test_prompt_seed_0004.py`: load the migration file with `importlib.util.spec_from_file_location`; assert the three constants equal the `prompt.py` constants, are ASCII, and hash to three hex literals. Compute them once: `uv run python -c "import hashlib; from rag_foundry_answering.prompt import GROUNDED_SYSTEM_V1 as a, GROUNDED_SYSTEM as b, UNGROUNDED_SYSTEM as c; [print(hashlib.sha256(t.encode()).hexdigest()) for t in (a, b, c)]"`; record them in Result.
