## Goal
`Usage` can carry the cache read and cache write tokens a provider reports, and cost includes them at their own rates. Unknown rates give `None`, never a guess. A dependency-free, append-only `UsageLedger` records one `Usage` per call and answers queries by profile and operation, with totals.

## Change
- Edit `usage.py`:
  - Add `cache_read_input_tokens: int = Field(0, ge=0)` and `cache_write_input_tokens: int = Field(0, ge=0)` to `Usage`. `input_tokens` keeps its meaning: uncached input as reported.
  - `estimate_cost(profile, input_tokens, output_tokens, *, cache_read_tokens=0, cache_write_tokens=0)`. Each side with more than 0 tokens needs its rate, otherwise the result is `None`. Decimal only, no floats.
- Edit `capabilities.py`: `ModelProfile` gains `cost_per_mtok_cache_read` and `cost_per_mtok_cache_write` (`Decimal | None`, default `None`, `ge=0`).
- Create `ledger.py`:
  - `UsageSink` Protocol: `append(usage: Usage) -> None`. A later step can persist through it.
  - `UsageLedger(UsageSink)`: append-only (no remove or clear), guarded by a `threading.Lock`. `records(*, profile_id=None, operation=None) -> tuple[Usage, ...]` in insertion order. `totals(*, profile_id=None, operation=None) -> UsageTotals`.
  - `UsageTotals` (frozen pydantic) holds `calls`, the four token sums, `cost_usd`, `unknown_cost_calls` and `estimated_token_calls`. `cost_usd` is `None` if any matching record has `None` cost, else the Decimal sum (`Decimal(0)` for no calls).
  - `RecordingChatModel(model, sink)` wraps a `ChatModel`. It exposes the same `profile`, appends `complete().usage`, and appends the final stream chunk's usage. It forwards errors unchanged and records nothing for a failed call.
- Export the new names from `__init__.py`.
- Create `tests/providers/test_usage_ledger.py`:
  - Cost with cache tokens: exact Decimal values for a sample profile. A cache rate of `None` with cache tokens > 0 gives `None`; with cache tokens = 0 it is ignored.
  - Old call sites (no cache kwargs) give unchanged results.
  - Ledger filters, totals, `None` propagation, insertion order, no mutation API.
  - `RecordingChatModel` over the fake chat model: `complete` and `stream` each add one record; an early stream `break` adds none.

## Constraints

- No persistence, budgets or caps here; P2.5 owns budgets.
