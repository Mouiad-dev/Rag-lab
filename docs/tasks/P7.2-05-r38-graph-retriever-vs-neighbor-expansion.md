## Goal
R38 is registered as a `retriever` plugin (adaptation). For a question naming two entities, it returns the source chunks along the shortest undirected relation path. On a shared fixture, R38 finds all 3 gold evidence spans of a 3-hop question. R21 sentence-window expansion (adjacent text, not GraphRAG) from the same seeds finds 2 of 3. Losing cases are shown too.

## Change
- Create `packages/indexing/src/rag_foundry_indexing/graph_retrieve.py`:
  - `EntityGraphConfig(extra="forbid")`: `max_hops` (3, 1-4), `neighborhood_hops` (1, 1-2), `max_matched_entities` (5, 1-10), `max_hits` (10, 1-50).
  - `EntityGraphRetriever`:
    - manifest: `R38`, `PluginKind.RETRIEVER`, `1.0.0`, `Fidelity.ADAPTATION`;
    - constructor `(config, *, scope, graph, index, index_version)` calls `graph.check_scope`.
  - `retrieve(q)`:
    - Match entities whose normalized name occurs in the normalized query: longest name first, ordered by query position.
    - At least 2 matches: `shortest_path` between the first two. Exactly 1: the neighborhood within `neighborhood_hops`.
    - Hits are the version's `ChunkRecord`s holding the evidence spans. Load them once by paging `list_chunks`; the version must be `ready`. In path order, deduplicated, with the original chunk text.
    - A span whose chunk is missing raises `graph_evidence_missing`.
    - Score: path hits `1.0`; neighborhood hits `1/(1+hop)`. `score_components`: `graph_hop`, `path_edges`. `scoring="entity-graph"`.
  - `self.last_trace = GraphRetrievalTrace(status, matched_entity_ids, path: tuple[(relation_id, direction)], evidence)`.
    - `status` is one of `ok`, `no_entity_match`, `no_path_within_hops`.
    - The last two give empty hits; there is no fallback.
- `retrievers.py`: register it. `__init__.py`: export the new names.
- Create `tests/indexing/_graph_fixture.py` (shared with 06-09; imports use the `tests.indexing.` / `tests.chunking.` prefixes):
  - `TEXT`: single-sentence paragraphs joined by `"\n\n"`. `SPANS`: one chunk per paragraph for `ready_index`.
  - Paragraphs:
    - P0 "Lina Haddad founded Cedar Labs in 2019."
    - P1-P6 filler with no fixture entity
    - P7 "Cedar Labs supplies tide sensors to the Harbor Authority."
    - P8-P13 filler
    - P14 "Omar Nasser leads the Harbor Authority."
    - P15 one Arabic relation sentence (`\uXXXX`) whose two entities are disjoint from the path entities
  - Paragraph lengths: every filler paragraph is at least as long as the longest fact paragraph. Then P7.2-06 can choose a `RecursiveChunker` size (overlap 0) that is at least the longest paragraph but smaller than any adjacent pair plus `"\n\n"`, which gives one chunk per paragraph. Put this rule in a module comment.
  - `REPLIES`: scripted R38 replies keyed by chunk text.
  - `QUESTION = "How is Lina Haddad connected to Omar Nasser?"`, `GOLD_SPANS` (the three relation quotes as view offsets).
  - `entity_seed(question, version)`: R02-labelled `RetrievalResult` of the chunks whose text contains a matched name.
  - `evidence_span_recall(result, gold)`: fraction of gold spans fully inside a hit of the same view.
  - `build_fixture_graph()`: runs the P7.2-04 builder and the in-memory store.
- Create `tests/indexing/test_graph_retrieve.py`:
  - **R38 on `QUESTION`:** recall 1.0; path of 3 with the P14 edge `reverse`; hits P0, P7, P14; status `ok`.
  - **R21** (`window=5`, `stay_in_paragraph=False`, `max_window_chars=20000`) on `entity_seed`: `evidence_span_recall(expanded.result, ...)` is exactly 2/3 and P7 is not covered. A fixture comment explains the 7-paragraph gap.
  - **Losing case, alias:** "How is Dr. Haddad connected to Omar Nasser?" matches only Omar Nasser. Neighborhood mode gives recall 1/3; P0 and P7 are missing.
  - **Losing case, no entity:** "Who repaired the lighthouse?" gives `no_entity_match` and empty hits.
  - **Losing case, hop limit:** `max_hops=2` gives `no_path_within_hops`.
  - **Guards:**
    - stranger scope, a graph of another version and a not-ready version each raise;
    - a missing evidence chunk raises `graph_evidence_missing`;
    - the plugin passes `check_plugin_contract`.
