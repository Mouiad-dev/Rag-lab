## Change
- `packages/domain/src/rag_foundry_domain/errors.py`: `PromptError(IntakeError)`, `CODES = ("template_not_found", "no_active_template", "template_exists", "purpose_mismatch", "hash_mismatch", "invalid_template", "store_unavailable")`, same shape as `RunError`.
- Create `packages/domain/src/rag_foundry_domain/prompts.py`:
  - `PromptPurpose = Literal["grounded", "ungrounded"]`; `prompt_sha256(text) -> str` (SHA-256 hex of UTF-8).
  - `PromptTemplate` (frozen, extra forbid): `id` (`^[a-z0-9-]+-v[0-9]+$`, <= 64 chars), `family`, `version >= 1`, `purpose`, `system_text` (1..20000 chars), `content_sha256`; validators: `id == f"{family}-v{version}"`, hash equals `prompt_sha256(system_text)` (stores map a failure to `PromptError("hash_mismatch")`).
  - `PromptActivation`: `seq`, `purpose`, `template_id`, `activated_by`, `activated_at`, `decision_ref` (1..200 chars).
  - `PromptTemplateStore` Protocol: `async get(template_id)` (`template_not_found`), `async active_id(purpose) -> str` (`no_active_template`), `async create(template)` (existing id -> `template_exists`; never updates), `async activate(purpose, template_id, *, activated_by, decision_ref) -> PromptActivation` (purpose differs -> `purpose_mismatch`), `async activations(purpose)` (seq order).
  - `InMemoryPromptTemplateStore(templates=(), activations=())`.
  - `CachedPromptTemplateStore(inner)`: `get` cached by id after recomputing the hash (mismatch -> `hash_mismatch`, not cached); `active_id` always delegates; writes delegate. Helper `async active_template(store, purpose) -> PromptTemplate` (one `active_id` + one `get`).
- Create `packages/domain/src/rag_foundry_domain/prompt_testing.py`: `PROMPT_STORE_CHECKS`: create/get round trip, duplicate id, purpose mismatch, latest activation wins, activation order, unknown id, `no_active_template` for a store with none. Checks use ids with a random suffix and, in `try/finally`, re-activate the ids that were active before the check (SQL stores share the seeded rows).
- Tests `tests/domain/test_prompts.py`: the suite on the in-memory store, including that the `finally` restore runs when a check fails midway (inject a failure); cache: second `get` makes no inner call, `active_id` always does, `active_template` makes one of each on a cold cache and only `active_id` on a warm one; a template built with `model_construct` and a wrong hash -> `hash_mismatch` and is not cached; messages carry no prompt text.
