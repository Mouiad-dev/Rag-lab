## Goal
A C18 plugin builds two linked granularities over one canonical text: parents (section-bounded paragraph packs) and children (sentence packs strictly inside one parent). Each child carries a stable `parent_id`; `chunk()` returns the children as plain `ChunkSpan`s, `chunk_hierarchy()` returns both levels. Catalogue acceptance: find a specific fact in a child and inspect its enclosing parent context.

## Change
- Create `packages/chunking/src/rag_foundry_chunking/hierarchy.py`:
  - `ParentChildConfig` (frozen, forbid): `parent_size: int = 2000` (200..20000), `child_size: int = 400` (50..4000), `respect_sections: bool = True`, `oversized: Literal["split", "keep"] = "split"`. Validator: `child_size < parent_size`.
  - `ParentSpan` (frozen, forbid): `parent_id: str`, `start`, `end`, `path: tuple[str, ...] = ()`, `flags` (same Literal/sorted rule as `StructuredChunk`). `ChildSpan`: `start`, `end`, `split_level`, `parent_id`, `flags`; `to_span() -> ChunkSpan`. `Hierarchy`: `parents`, `children` (both sorted by start), `parent_of(child) -> ParentSpan`.
  - `parent_id_for(text, start, end) = "par_" + sha256(json.dumps(["c18-parent-v1", start, end, sha256(text[start:end]).hexdigest()], separators=(",", ":")))[:24]`. Depends only on offsets and content, never on list position. It is a chunk-level reference, not a source anchor (anchors stay owned by the extraction view).
  - `ParentChildChunker`: manifest `C18`, `PluginKind.CHUNKER`, `"1.0.0"`, `Fidelity.ADAPTATION`, `config_model=ParentChildConfig`.
    - Parents: units = `paragraph_ranges(doc, use_blocks=True)` trimmed. When `respect_sections` and `doc.blocks` carry `section_path`, group consecutive units by the `section_path` of the block they lie in (units outside blocks join the preceding group) and pack each group separately with `pack_units(text, units, parent_size, oversized)`; a parent never spans two section paths. `path` = that section path.
    - Children: inside each parent, units = `sentence_ranges(text, p.start, p.end)` trimmed; a sentence larger than `child_size` falls back to `word_ranges`, then `safe_cut_ranges` (split_level 1, 2); pack with `pack(..., child_size, overlap_units=0)`. A child never crosses its parent's end. A kept oversized parent still gets children <= `child_size`.
    - `chunk(doc)` -> `tuple(c.to_span() for c in hierarchy.children)`; `chunk_hierarchy(doc) -> Hierarchy`.
- Edit `__init__.py`: register `ParentChildChunker`; export it, `ParentChildConfig`, `ParentSpan`, `ChildSpan`, `Hierarchy`, `parent_id_for`. Add lines only.
- Create `tests/chunking/test_hierarchy.py` (non-ASCII only as `\u` escapes, NFC). Fixture: English and Arabic sections (Arabic sentences ending with `؟` and `.`, `،` inside sentences), `TextBlock`s with `kind`, `section_path`, `heading_level` built by hand. Assert:
  1. every child lies inside exactly one parent and `child.parent_id` equals that parent's id; children of one parent are ascending and disjoint;
  2. every non-whitespace code point of the text is in exactly one parent and exactly one child;
  3. with `respect_sections=True` no parent overlaps blocks with two different `section_path`s; with `False` a small two-section text becomes one parent;
  4. same input twice gives equal hierarchies; editing a paragraph in the last section leaves the first parent's id unchanged and changes the edited parent's id;
  5. fact lookup: the child containing a fixed quote (English and Arabic) has a parent whose text contains the quote's neighbouring sentence;
  6. oversized paragraph (> `parent_size`): `split` gives parents flagged `("oversized", "split_part")`; `keep` gives one parent flagged `("oversized",)` whose children are all <= `child_size`;
  7. `child_size >= parent_size` rejected; registry `validate_config("C18", {}) == ParentChildConfig()`; unknown key rejected; `chunk()` returns `ChunkSpan`s equal to the children.
