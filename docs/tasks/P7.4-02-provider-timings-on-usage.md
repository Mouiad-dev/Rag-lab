## Goal
A chat `Usage` can carry provider-reported phase timings, and the Ollama adapter records Ollama's documented cached-prompt count as cache-read tokens. Nothing is inferred from timings.

Verified Ollama fields (orchestrator, 2026-11-22, https://docs.ollama.com/api/chat OpenAPI schema): non-streaming `/api/chat` returns `total_duration`, `load_duration`, `prompt_eval_count`, `prompt_eval_duration` (time for uncached prompt tokens), `eval_count`, `eval_duration` (durations in nanoseconds, counts in tokens) and `prompt_eval_cached_count` ("Number of prompt tokens read from the cache"). The documented streaming schema lists only `model`, `created_at`, `message`, `done`: timing and count fields on the final stream chunk are undocumented. Older Ollama versions may omit `prompt_eval_cached_count`.

## Change
- `usage.py`: frozen `ProviderTimings(total_ms, load_ms, prefill_ms, decode_ms)`, each `float | None` (`ge=0`), extra forbidden; `Usage.timings: ProviderTimings | None = None`. Docstring: "provider-reported durations; prefill_ms covers uncached prompt tokens only (Ollama); not a cache-hit signal".
- `ollama.py` `_usage` (non-streaming `complete`): map `total_duration`, `load_duration`, `prompt_eval_duration`, `eval_duration` (ns, validated like `_count`) to ms; an absent or invalid field gives `None` for that field only; all absent gives `timings=None`. Map `prompt_eval_cached_count` (valid int) to `cache_read_input_tokens`; absent -> 0. Keep `input_tokens = prompt_eval_count` and add a comment: "whether prompt_eval_count includes cached tokens is undocumented; Ollama cost is 0, so nothing is charged twice; the P7.4-11 live run records both raw values". Set `cost_per_mtok_cache_read=0` on the Ollama chat profile so the cost stays `0`, not `None`.
- Stream: parse the same fields from the final chunk only if present (undocumented; optional); never fail because they are missing.
- Tests in `test_ollama_chat.py`: complete maps all four durations and the cached count; missing `eval_duration` -> `decode_ms=None`, others set; negative or boolean values -> `None` / 0; no fields -> `timings is None` and `cache_read_input_tokens == 0`; cached count present -> cost still `Decimal(0)`; a stream final chunk without timings still succeeds; ledger totals unchanged apart from summing cache-read tokens.

## Constraints
