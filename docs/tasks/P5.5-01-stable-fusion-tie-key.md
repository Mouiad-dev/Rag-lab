## Goal
Equal fused scores no longer fall back to random chunk ids. R07/R08 (`fusion.py` line 166) and R18 (`rag_fusion.py` line 47) break ties by stable source position. So two index builds of the same corpus, which have different chunk ids, give the same fused order.

## Change
- `fusion.py`: add a public `fusion_sort_key(score: float, best_rank: int, hit: RetrievedChunk, chunk_id: str) -> tuple`. It returns `(-round(score, 12), best_rank, hit.extraction_view_id, hit.start, hit.end, chunk_id)`. Use it in `_result`, where `hit` is the record's first-seen hit. The view id and code-point offsets come from the immutable extraction view, so they do not change on rebuild. `chunk_id` stays only as a last resort, for two chunks with the same span.
- `rag_fusion.py`: replace the line 47 key with `fusion_sort_key(rec["score"], rec["rank"], rec["hit"], cid)`.
- Do not change `multi_query.py` line 141. Its key `(best rank, query index, chunk id)` cannot tie, because one query result never has two hits at the same rank. Say so in Result.
- Lessons:
  - `R07-rrf.md` line 9 states the old rule ("then lexicographically by `chunk_id`"). Change it to: best input rank, then extraction view and start/end offsets, then `chunk_id`.
  - `R08-weighted-fusion.md`: add one Mechanism sentence with the same rule.
  - `R18-rag-fusion.md` line 9: same rule.
  - `R18-rag-fusion.md` line 68: replace the "not reproducible" limitation with this: ties now follow source position, which is stable across index builds; chunk id is used only for identical spans.
  - In Result, list every changed lesson line.

## Tests (must fail on the old key)
- `test_fusion.py`: let `hit()` take `start=0, end=1` keyword arguments. Add `test_rrf_tie_order_stable_across_builds`:
  - Build 1: `R03 [("zz", span 10-15) rank 1, ("aa", span 0-5) rank 2]` and `R02 [aa rank 1, zz rank 2]`.
  - Build 2: the same spans with the ids swapped.
  - Expected: `[h.start for h in fused.hits] == [0, 10]` for both builds.
  - The old key gives `[0, 10]` and then `[10, 0]`, so this test fails on the old code.
- Add the same test for `WeightedFusion`, using equal raw scores so the weighted sums tie. Expected `[0, 10]` for both builds.
- `test_rag_fusion.py`: add the same check with a small inline retriever that returns spans:
  - query `q` returns `(A, B)`; variant `v1` returns `(B, A)`.
  - A is span 0-5 and B is span 10-15. Run once with ids `A="zz", B="aa"` and once with them swapped.
  - Expected starts: `[0, 10]` for both runs.
- Keep `test_rrf_tie_uses_chunk_id` green unchanged. Its hits share a view and span, so the chunk-id fallback still applies.
- If any other existing test changes order, do not edit its expected values silently. The likely cause is that `RecordingRetriever` sets `end=len(chunk_id)`. List each such test with its old and new order in Result.
