## Goal
`rag-foundry-providers[ollama]` installs one pinned httpx release. `OllamaEmbeddingModel` implements `EmbeddingModel` on Ollama's `POST /api/embed` and passes every `EMBEDDING_CHECKS` through `httpx.MockTransport`. The test network guard also blocks asyncio connects to non-loopback literal IPs. ADR-0001 records why P2.2 does not use LiteLLM.

## Change
- `packages/providers/pyproject.toml`: `[project.optional-dependencies] ollama = ["httpx==<X.Y.Z>"]`. Pick the newest release uploaded at least 2 weeks before today. Record its version, upload date and transitive packages in Result. Core `dependencies` stay pydantic-only. Root dev group: use `rag-foundry-providers[ollama]`. Run `uv lock`.
- `errors.py`:
  - Add `AdapterDependencyError(ProviderError)`, with the message "install rag-foundry-providers[ollama]".
  - Add `ProviderCallError(ProviderError)` with `profile_id` and `reason` in {`connection`, `timeout`, `model_not_found`, `input_too_long`, `bad_response`}.
  - Messages carry the reason and HTTP status only. They never include request text, response bodies, headers or env values.
- Create `adapters/__init__.py` (docstring only) and `adapters/_ollama_http.py`:
  - `load_httpx()`: lazy import; on `ImportError` raise `AdapterDependencyError`.
  - `post_json(api_base, path, payload, *, timeout_s, transport, profile_id) -> dict`:
    - one `httpx.AsyncClient(base_url=api_base, transport=transport, trust_env=False, follow_redirects=False)` per call (no env proxies or .netrc);
    - `timeout=httpx.Timeout(timeout_s)` per call, and no retries;
    - error mapping: `ConnectError` → `connection`, `TimeoutException` → `timeout`, 404 → `model_not_found`, other non-2xx or non-JSON → `bad_response`; chain with `from exc`.
  - `estimate_tokens(text)`: 0 for empty text, otherwise `max(1, ceil(len(text) / 4))`. Documented as an approximation, never 0 for non-empty text.
- Create `adapters/ollama.py` (the embedding half; 04 adds chat):
  - `ollama_embedding_profile(id="local-embed", model="bge-m3")`:
    - `provider="ollama"`, `kind=embedding`, `embedding_dim=1024`, `context_window=8192`, `local=True`;
    - `token_embeddings=False`, `multivector=False` (this adapter returns dense vectors only);
    - zero cost rates, explicitly `Decimal("0")`, with the comment "no per-token fee; hardware cost not modelled".
  - `OllamaEmbeddingModel(profile, *, api_base, timeout_s=60.0, transport=None, clock=time.perf_counter)`.
  - Request uses only fields documented in api.md: `model`, `input` (list) and `truncate: false`. Ollama must refuse over-long input rather than silently cut it; map that refusal to `input_too_long` if api.md documents it, otherwise to `bad_response`.
  - Empty input returns `vectors=()` with no request.
  - Validate the response: `embeddings` count equals the input count, each vector has length `embedding_dim`, and every value is finite. Anything else is `bad_response`.
  - Usage: `PROVIDER` with `input_tokens = prompt_eval_count` when that field is a non-negative int. Otherwise use the summed `estimate_tokens` and `ESTIMATED`. `output_tokens=0`. Cost via `estimate_cost`.
  - `input_type` is accepted and ignored (bge-m3 has no query/document prefix; say so in the docstring).
- `tests/providers/conftest.py`: wrap `asyncio.BaseEventLoop.create_connection` to raise the guard error for a non-loopback `host`. This covers selector and proactor loops for literal IPs. Update the docstring; the guard is still not an isolation boundary.
- Create `tests/providers/test_ollama_embedding.py` (`MockTransport` with canned api.md-shaped JSON):
  - Parametrize `EMBEDDING_CHECKS`.
  - Request path and body.
  - Timeout reaches the request (`request.extensions["timeout"]`).
  - Usage from provider, and estimated when `prompt_eval_count` is absent.
  - Wrong count, wrong dim or NaN → `bad_response`; 404 → `model_not_found`; `ConnectError` / `ReadTimeout` raised by the handler → their reasons.
  - Missing httpx (`monkeypatch.setitem(sys.modules, "httpx", None)`) → `AdapterDependencyError`.
  - Guard self-test: `loop.create_connection(..., "93.184.215.14", 80)` is blocked.
- `ADR-0001`: append "Update 2026-11-02 (P2.2)". P2.2 uses a direct Ollama HTTP adapter on httpx. Reasons:
  - malware in litellm 1.82.7/1.82.8 (GHSA-5mg7-485q-xm76), and every clean version is under 2 weeks old;
  - a ~36 MB wheel with heavy dependencies;
  - LiteLLM cannot tell whether token counts came from Ollama;
  - LiteLLM does not forward a per-call timeout on the Ollama embedding path.

  LiteLLM is re-decided at P2.3/P2.4 planning. The ports are unchanged.
