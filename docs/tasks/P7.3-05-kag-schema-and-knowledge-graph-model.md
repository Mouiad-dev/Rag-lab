## Goal
A declared domain schema (entity types, typed properties, relation types with domain/range and cardinality) and a scoped `KnowledgeGraph` whose every fact links to source spans and every chunk links back to its facts (mutual index). Schema violations fail validation. Conflicting values for single-valued predicates are kept and reported, never silently resolved.

## Change
- Create `packages/domain/src/rag_foundry_domain/knowledge.py` (stdlib + pydantic, frozen, `extra="forbid"`):
  - `PropertyDef(name ~ ^[a-z][a-z0-9_]{0,39}$, value_kind: Literal["text","int","year"], cardinality: one|many)`.
  - `EntityTypeDef(name ~ ^[A-Z][A-Za-z0-9]{0,39}$, properties: tuple[PropertyDef, ...])`.
  - `RelationTypeDef(name ~ ^[a-z][a-z0-9_]{0,39}$, domain, range, cardinality: one|many)`; `one` means one object per subject.
  - `KnowledgeSchema(schema_id 1-64, version 1-16, entity_types, relation_types)`: names unique across a type's properties and relations; domain/range must be declared types; otherwise `kag_schema_invalid`. `schema_sha256()` over canonical JSON. `predicate(subject_type, name)` returns the property or relation definition or `None`.
  - `KEntity(entity_id ~ ^ken_[0-9a-f]{16}$, type, name 1-500, mentions 1-50 GraphSpan)`; `kentity_id_for(name, type)` uses `normalize_name`.
  - `Fact(fact_id ~ ^fct_[0-9a-f]{16}$, subject_id, predicate, object_id: str | None, literal: str | int | None, evidence 1-50 GraphSpan)`: exactly one of `object_id` / `literal`; `fact_id_for(subject_id, predicate, object_or_literal)`.
  - `Conflict(subject_id, predicate, fact_ids)`: two or more distinct objects/literals for a `one` predicate.
  - `KnowledgeGraph(schema: Literal["rag_foundry.knowledge_graph/1"], kg_key, tenant_id, project_id, index_version_id, technique_id: Literal["R48"], knowledge_schema, generator_json <= 8000, entities <= 5000, facts <= 20000)`. Validators (`kag_invalid`):
    - unique, sorted IDs; fact subject exists and its type declares the predicate;
    - a property predicate requires `literal` (and `object_id` None); a relation predicate requires `object_id` (and `literal` None);
    - relation objects exist and match `range`; literals match `value_kind` (`year`: int 1000-2999; `int`: int; `text`: str 1-500).
  - Methods: `check_scope` (`kag_scope_mismatch`); `to_json` / `from_json` (`kag_invalid`); `entity_by_name(name, type=None)`; `facts_about(entity_id, predicate=None, as_object=False)`; `facts_for_chunk(chunk_id)` and `chunks_for_fact(fact_id)` (mutual index, sorted); `conflicts()` (computed, deterministic).
- Create `tests/domain/test_knowledge.py` with reusable helpers `make_schema()` and `make_kg(...)`:
  - schema: `Person`, `Organization` (`founded_year: year, one`); relations `founded` (Person->Organization), `supplies` (Organization->Organization, many), `leads` (Person->Organization, one);
  - invalid schemas (unknown range, duplicate name); domain and range violations; bad literal kind; both/neither object and literal; a property fact with `object_id` and a relation fact with `literal` each raise `kag_invalid`;
  - JSON round trip; mutual index both ways;
  - conflict on an entity used by no other test (e.g. "Blue Reef" founded 2012 and 2014) gives one `Conflict`; the same year twice from two spans is one fact with two evidence spans;
  - stranger scope and another version fail `check_scope`; an Arabic entity name (`\uXXXX`) resolves via `entity_by_name`.

- Spec-review round 2 (2026-11-22): `int` literals must satisfy abs(v) < 2**63 (SQL `bigint`), else `kag_invalid`; the canonical schema JSON is capped at 64000 characters (SQL limit), else `kag_schema_invalid`. Test both.
