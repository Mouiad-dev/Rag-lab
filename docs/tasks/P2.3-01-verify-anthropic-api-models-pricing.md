## Change
- Edit `ADR-0001` Evidence: add "Verified 2026-11-xx (P2.3-01), Anthropic" answering, with links:
  1. Endpoint and base URL; required headers (`x-api-key`, `anthropic-version` and its current value, `content-type`).
  2. Request: `model`; whether `max_tokens` is required; roles allowed in `messages` and the alternation rule; top-level `system`; `temperature` range and whether the chosen models accept it; whether extended thinking is off unless requested.
  3. Response: content block types; the full `stop_reason` list (for example `end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `pause_turn`, `refusal`, others); every `usage` field, including `cache_creation_input_tokens`, `cache_read_input_tokens`, the per-TTL `cache_creation` breakdown and whether `input_tokens` excludes cached tokens.
  4. Streaming: the SSE event types (`message_start`, `content_block_*`, `message_delta`, `message_stop`, `ping`, `error`), which events carry usage, and whether `message_delta` usage is cumulative.
  5. Errors: the HTTP status to `error.type` table (400, 401, 403, 404, 413, 429, 500, 529 and any others), the error body shape, and the `request-id` header.
  6. Rate-limit and `retry-after` header names (record only; P2.5 uses them).
  7. Models: the current cheapest capable model and the current Sonnet-tier model. Give the exact IDs, saying which is a pinned snapshot and which is an alias, plus context window, max output, vision/tools support and any deprecation date. Confirm or refute `claude-haiku-5-5` and `claude-sonnet-5-5`; never guess an ID.
  8. Prices in USD per MTok for those two models: input, output, 5-minute cache write, 1-hour cache write, cache read. Also any long-context, regional or data-residency multiplier that could apply to a default call.
  9. Approach comparison: the latest `anthropic` SDK version and date, its required dependencies, default retries and timeout, and its logging switch. LiteLLM: any advisory since the P2.2 block, and the date when a version outside every affected range reaches 2 weeks old.
- Add a "Decision for P2.3" line recommending one approach with reasons. The default is a direct httpx adapter (httpx 0.28.1 is already locked, there is no new dependency, `token_source` stays honest, and there are no hidden retries or logging). Recommend the SDK only if the docs show a P2.3-scope feature that is impractical without it.
- Result: estimate one live run (05: about 8 calls, at most 64 output tokens each, about 30 input tokens each) from the verified Haiku-tier prices, as a formula and a USD figure.
