## Goal
`MmrSelector` (R09) reorders one ranked result by Maximal Marginal Relevance (Carbonell & Goldstein 1998). Relevance is the input score min-max normalised (adaptation: no extra query embedding call). Similarity between candidates is cosine of their **stored index embeddings** (default) or cosine of lexical term-frequency vectors. A new read port returns stored vectors, scope-checked.

## Change
- `errors.py` `IndexingError.CODES`: add `selection_missing_vector`, `selection_vectors_unavailable`, `too_many_ids`.
- `ports.py`: add `@runtime_checkable class ChunkVectorReader(Protocol)` with `async def chunk_embeddings(self, scope, index_version_id, chunk_ids: tuple[str, ...]) -> dict[str, tuple[float, ...]]`. Contract: the version must exist in scope, otherwise the same `NotFoundError` as `get_index_version`. More than 100 ids gives `IndexingError("too_many_ids")`. Malformed ids, unknown ids, ids from another version and ids from another scope are all simply absent (no distinction). Read-only.
- `uow_adapters.py` line 39: also allow names on `ChunkVectorReader` for the `indexes` family (read-only).
- `InMemoryIndexRepository.chunk_embeddings`: from `_vectors`, limited to that version's chunk ids.
- `SqlIndexRepository.chunk_embeddings`: check the version in scope as `list_chunks` does. Keep only ids that parse as canonical UUID4. Run `SELECT id, embedding::text AS e FROM chunks WHERE tenant_id=:t AND project_id=:p AND index_version_id=:i AND id = ANY(CAST(:ids AS uuid[]))` with `ids=[uuid.UUID(x) ...]`. Parse `e` with `json.loads` into floats. Empty input gives `{}` with no chunk query.
- `index_testing.py`: add `check_chunk_embeddings(factory)` to `INDEX_REPOSITORY_CHECKS`. It checks that vectors round-trip within 1e-6, a foreign-tenant chunk id and `"not-a-uuid"` are absent, another scope gets `NotFoundError`, and 101 ids give `too_many_ids`. The in-memory run is `tests/domain/test_indexing.py`; the SQL run is `tests/storage/test_sql_index_repository.py -m db`.
- Create `rag_foundry_indexing/mmr.py`:
  - `MmrConfig` (frozen, forbid): `k: 1..50 = 5`, `lambda_mult: float 0.0..1.0 = 0.5`, `similarity: Literal["embedding","lexical"] = "embedding"`.
  - `MmrSelector`: manifest `R09`, `PluginKind.FUSION`, `Fidelity.ADAPTATION`, `1.0.0`. Constructor `(config, *, scope, index_version, index, vectors: ChunkVectorReader | None = None)`. In embedding mode, `vectors is None` raises `selection_vectors_unavailable` here.
  - `async select(result) -> RetrievalResult`: `check_single_input`; `result.index_version_id != index_version.id` gives `selection_version_mismatch`. Embedding mode: first `index.get_index_version(scope, id)` (NotFoundError passes through), then `chunk_embeddings` for all hit ids. Any missing id gives `selection_missing_vector`, never a partial result.
  - rel_i = min-max of input scores (one hit or all equal: 1.0). sim = cosine (embedding) or cosine of `Counter(lexical_tokens(text))` (0.0 if either is empty). Greedy: `mmr = lambda*rel - (1-lambda)*max(sim to selected)` (max term 0 when none is selected). Pick the highest `round(mmr, 12)`; ties go to the lower input rank. Stop at `k` or when candidates run out.
  - Output hit: rank = pick order, score = mmr at pick. Components: original + `input_rank` (source=input tid, source_rank) + `mmr_relevance` + `mmr_max_similarity` + `mmr_score`. `technique_id="R09"`, `scoring=f"mmr[{tid}]:{similarity}:lambda={l:.2f}"`.
- Register in `register_builtin_plugins`; export `MmrConfig`, `MmrSelector`, and `ChunkVectorReader` from `rag_foundry_domain.ports`.
- Create `tests/indexing/test_mmr.py`:
  - Lexical hand case: A `"tidal observatory sea levels"` 1.0, B the same text with another id 0.9, C `"chess club tuesday"` 0.5, D `"sea levels tuesday"` 0.0. With `k=2, lambda=0.5` the pick is A then C; B is lost (catalogue "loss of a relevant near-duplicate"). Assert `mmr_score` of C = 0.25 and of A = 0.5. With lambda=1.0 the order equals the input order. With lambda=0.0 the first pick is input rank 1 (tie rule).
  - Embedding mode on `ready_index` with `LexicalTestEmbedder`: build input with `DenseRetriever(k=4)`. Vectors come from the repo (assert `chunk_embeddings` values equal the stored ones). Components are present, and the output ids are a subset of the input ids.
  - Negative: stranger scope gives NotFoundError. An input holding a chunk id from a second, separate `ready_index` (the other tenant's data) gives `selection_missing_vector`. Another version id gives `selection_version_mismatch`. Embedding mode without `vectors` gives `selection_vectors_unavailable`.
  - Registry: `validate_config("R09", {}) == MmrConfig()`; `{"lambda_mult": 1.5}` is rejected.
