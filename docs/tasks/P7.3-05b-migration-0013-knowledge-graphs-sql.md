## Change
- Create `.../versions/0013_knowledge_graphs.py` (revision `0013_knowledge_graphs`, down `0012_summary_trees`), raw SQL as in 0011; every table carries `tenant_id, project_id, index_version_id, kg_key`, every child FK carries all four.
  - `knowledge_graphs(technique_id, schema_json text, schema_sha256 char(64), generator_json, created_at)`: PK `(index_version_id, kg_key)`; `UNIQUE (kg_key)`; scope unique; FK to `index_versions`; checks: key and SHA patterns, technique `^R[0-9]{2}$`, schema_json <= 64000, generator <= 8000; ready-only insert trigger.
  - `kg_entities(entity_id varchar(20), type varchar(40), name text)`: PK incl. `entity_id`; scope FK to `knowledge_graphs`; checks `^ken_[0-9a-f]{16}$`, name 1-500.
  - `kg_facts(fact_id varchar(20), subject_id, predicate varchar(40), object_id null, literal_text text null, literal_int bigint null)`: PK incl. `fact_id`; FKs for `subject_id` and `object_id` to `kg_entities` with scope; check exactly one of `object_id`, `literal_text`, `literal_int` is not null; `^fct_[0-9a-f]{16}$`.
  - `kg_spans(owner_kind varchar(8), owner_id varchar(20), ordinal smallint, chunk_id, extraction_view_id, start_cp, end_cp, quote)`: as `graph_spans` in 0011 (FKs to `chunks` and `index_version_views`, `owner_kind IN ('entity','fact')`, quote length check, ordinal 0-49) with a `kg_spans_validate_insert` trigger for view, offsets, quote = chunk substring, and owner existence.
  - Scope indexes; no-update triggers reuse `reject_index_update()`; downgrade drops 0013 objects only.
- `index_repository.py`: `add_knowledge_graph` / `get_knowledge_graph` with the in-memory order and codes (early key lookup -> `kag_exists`; spans checked first; graph, entities, facts, spans in one transaction; unique violation -> `kag_exists`); `get` rebuilds the `KnowledgeSchema` from `schema_json`, checks `schema_sha256`, and returns a sorted graph.
- Tests: add `KG_STORE_CHECKS` to the parametrized SQL checks; new `test_kg_database_guards` (one case each: cross-tenant span FK, fact object from another graph, both object and literal set, bad fact ID, quote mismatch, offsets outside chunk, wrong view, unknown owner per kind, UPDATE on each table, not-ready version, downgrade to 0012 and upgrade with `reject_index_update()` intact). `test_sql_uow_db.py`: exercised `add_knowledge_graph` call.
