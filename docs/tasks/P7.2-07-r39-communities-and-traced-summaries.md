## Goal
Entities of an `EntityGraph` are grouped into communities by deterministic stdlib label propagation (one level, not Leiden). One chat call per community writes a synthetic summary made of claims. Every kept claim cites fact IDs of its own community and resolves to source spans; untraced claims are rejected and counted.

## Change
- Create `packages/indexing/src/rag_foundry_indexing/graph_community.py`. The module docstring states: label propagation, single level, not hierarchical Leiden.
  - `detect_communities(graph, *, max_iterations=20) -> tuple[Community, ...]`:
    - weighted label propagation; the weight is the evidence span count per entity pair, undirected;
    - nodes in sorted ID order, ties go to the smallest label;
    - stop when nothing changes or at the cap.
  - `Community`:
    - `community_id`: `"com_"` + the first 16 hex of the SHA-256 of the sorted member IDs;
    - `entity_ids`;
    - `relation_ids`: only relations with **both** endpoints inside;
    - `iterations`, `converged`.
  - `R39_SUMMARY_SYSTEM_V1` and its SHA (untrusted-JSON wording).
    - The user JSON lists facts as `{fact_id, text, quote}`; entity and relation IDs are the fact IDs.
    - Reply: `{"title": str, "claims": [{"text": str, "fact_ids": [str]}]}`.
  - `CommunitySummaryConfig(extra="forbid")`:
    - `min_members` (2, 2-50);
    - `max_communities` (50, at most 500). Above the cap the build raises `community_cap_exceeded` before any chat call; no silent truncation;
    - `max_claims` (8, at most 20), `max_claim_chars` (300), `max_output_tokens`, `temperature=0.0`, `on_invalid`.
  - `CommunitySummaryBuilder(config, *, graph, chat).build()` returns `CommunityBuildReport(graph_key, communities, summaries, skipped_small, rejected_claims: tuple[(community_id, claim_index, reason)], rejected_summaries, chat_calls, usage)`.
  - Claims:
    - a claim with empty `fact_ids` or an ID outside the community is rejected as `untraced_claim`;
    - a summary with no kept claim is rejected;
    - too many claims or text that is too long are item rejections.
  - `CommunitySummary`:
    - fields: `graph_key`, `community_id`, `title`, `claims: tuple[TracedClaim(claim_id = f"{community_id}:{i}", text, fact_ids, sources: tuple[GraphSpan, ...])]`, `synthetic: Literal[True]`, `prompt_sha256`, `chat_provider`, `chat_model`;
    - `sources` are the mentions and evidence of the cited facts, deduplicated.
  - `trace_claims(summary, graph) -> tuple[GraphSpan, ...]`:
    - raises `graph_key_mismatch` if `summary.graph_key != graph.graph_key`;
    - raises `untraced_claim` if any claim resolves to no span.
    - Docstring: traced means linked to source spans, not proven entailed.
  - Summaries are in-memory values in P7.2 (not persisted; ADR-0019 open item).
- Export the names from `__init__.py`. Extend `_graph_fixture.py`:
  - append P16, an entity with no relation; P0-P15 offsets do not change, and P16 follows the 05 paragraph-length rule;
  - P15 forms the second, disconnected cluster;
  - add scripted R39 summary replies keyed by `community_id`.
- Create `tests/indexing/test_graph_community.py`:
  - **Determinism:**
    - `detect_communities` gives the same result twice on the same graph.
    - Build a second graph with the P7.2-04 builder from replies with entities and relations in reversed order. It must equal the first `EntityGraph` and give the same communities.
    - Build a third graph from an index whose chunk ordinals are reversed (built with `ready_index`). Its communities must have the same `community_id`s and `entity_ids`. Chunk IDs differ, so compare memberships, not whole graphs.
    - Do not hand-build an unsorted `EntityGraph`; its validator rejects one.
  - Two clusters give two communities, and P16 is in `skipped_small`.
  - Every kept claim has spans, and each span quote equals the view slice (`StaticSourceReader`).
  - An unknown fact ID, an empty `fact_ids` and an all-bad summary are each rejected and counted.
  - `trace_claims` with another graph's key raises `graph_key_mismatch`.
  - `max_communities=1` raises `community_cap_exceeded` with 0 chat calls.
  - `chat_calls == len(summaries) + rejected_summaries == len(usage)`.
