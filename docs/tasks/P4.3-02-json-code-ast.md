## Goal
Three structure chunkers on the P4.3-01 core: C10 splits a JSON document into member groups that keep their JSON paths, C13 splits source code before language-specific declaration lines, and C14 uses Python's own parser (stdlib `ast`) for declaration boundaries and fails explicitly on unsupported languages or syntax errors. Offsets are code points into `doc.text`; oversized units are flagged, never dropped.

## Library APIs (checked against the Python 3.12/3.13 docs)
- `json.JSONDecoder(parse_constant=...).raw_decode(s, idx)` returns `(value, end_index)`; it does not skip leading whitespace. Use it for scalars and for object keys (a key is a JSON string). Use `parse_constant` to reject `NaN`/`Infinity`. Do not use undocumented helpers such as `json.decoder.scanstring`.
- `ast.parse(source)`; nodes have `lineno`, `end_lineno` (1-based) and `col_offset`, `end_col_offset`, which are **UTF-8 byte offsets** within the line. Convert to code-point offsets by decoding the line's UTF-8 prefix. Line starts must follow Python's line endings (`\n`, `\r\n`, `\r`). `ast.get_docstring(node, clean=False)` and `node.body[0]` give the docstring expression.

## Change
- Create `packages/chunking/src/rag_foundry_chunking/json_structure.py`: `JsonStructureConfig` (`chunk_size`, `oversized`, plus `max_depth: int = 64` (1..256)), `JsonStructureChunker` (manifest `C10`, `PluginKind.CHUNKER`, `1.0.0`, `Fidelity.ADAPTATION`), and `StructureParseError(ValueError)` (in `structure.py`, exported) with a short `code` (`"invalid_json"`, `"too_deep"`, `"unsupported_language"`, `"syntax_error"`).
  - An offset-tracking walker over `doc.text` (iterative or depth-capped; deeper than `max_depth` raises `StructureParseError("too_deep")`) records, for every object member and array element, its range (member: key start to value end; element: value range) and its normalized JSONPath (RFC 9535 style: `$`, `['key']` with `'` and `\` escaped, `[0]`). Invalid JSON, trailing non-whitespace or `NaN`/`Infinity` raise `StructureParseError("invalid_json")`; the result must agree with `json.loads` (test).
  - Chunking: start at the root. A container that fits `chunk_size` is one chunk. A larger container is split: its members/elements are units packed with `pack(..., overlap_units=0)` (punctuation `{ } [ ] ,` between units stays outside chunk bodies, which is fine); a unit that is itself an oversized container recurses; an oversized scalar (a long string) follows `oversized`.
  - Every chunk: `kind="json"`, `path` = the JSONPath strings of its first and last unit (one entry when they are the same), `attrs` include `container_path` (JSONPath of the parent container), `first_key`/`last_key` or `first_index`/`last_index`; `context` = `ContextSpan(role="container")` for the key token (`"key":`) of each ancestor member whose value was split (so `render` shows the field names leading to the value).
  - Helper `json_path_at(text, result, offset) -> str` returns the deepest JSONPath whose range contains `offset` (used to reassociate a retrieved value with its field).
- Create `packages/chunking/src/rag_foundry_chunking/code.py`:
  - `CodeSeparatorConfig` (`chunk_size`, `oversized`, `language: Literal["python", "javascript", "typescript", "java", "go", "rust"] = "python"`) and `CodeSeparatorChunker` (manifest `C13`, `1.0.0`, `Fidelity.ADAPTATION`). Each language has an ordered tuple of line-start regexes by level (for Python: level 0 `^(class|def|async def) `, level 1 `^\s+(def|async def) `, then blank lines, then lines). The text is cut **before** a matching line, never after a separator; decorator/annotation lines (`^\s*@`) and comment lines directly above a declaration move with it. Units at the highest level that fit are packed with `pack`; a unit over `chunk_size` is split at the next level; after the last level, `oversized` applies. `kind="code"`; `attrs` include `language`; `path` = the declaration line texts (trimmed, at most one per level) that enclose the chunk start, found by the same regexes.
  - `AstCodeConfig` (`chunk_size`, `oversized`, `language: str = "python"`, `on_syntax_error: Literal["raise", "fallback"] = "raise"`) and `AstCodeChunker` (manifest `C14`, `1.0.0`, `Fidelity.FAITHFUL` for Python). Any language other than `"python"` raises `StructureParseError("unsupported_language")` at chunk time (config validation allows any string so the error is explicit and testable). `ast.parse` failure: `"raise"` raises `StructureParseError("syntax_error")` with the line number; `"fallback"` returns `CodeSeparatorChunker` chunks for Python, each flagged `unparsed`.
  - AST chunking: top-level statements are units, a unit's range is from its first decorator (or leading comment lines directly above, same rule as C13) to `end_lineno`/`end_col_offset`. Consecutive small units (imports, assignments) are packed with `pack`. A `ClassDef`/`FunctionDef`/`AsyncFunctionDef` larger than `chunk_size` recurses into its `body` statements; its header (decorators through the line ending with the `:` before the body, plus its docstring when present) becomes the first chunk or, if that chunk would be over budget, its own chunk; chunks of the body carry `ContextSpan(role="declaration")` for each enclosing header line range (decorators excluded) so `render` shows `class A:` / `def m(self):` above a method body. `path` = qualified name parts (e.g. `("Store", "add_item")`); `attrs` include `node_type` (e.g. `FunctionDef`) and `qualname`. A leaf statement over budget follows `oversized`. Chunk boundaries are always syntax-node boundaries except `split_part` pieces.

## Constraints
- Split lines only with `structure.line_ranges` (`\n`, `\r\n`, `\r`), never `str.splitlines`. Context spans are trimmed line content. Chunk bodies are trimmed. Flags come from the unit a chunk was made from (pieces of an oversized unit: `("oversized", "split_part")`; a kept oversized unit: `("oversized",)`), never from comparing the final piece length.
- Stdlib + pydantic only; no new dependency. Pure; no I/O. Never execute the parsed code (`ast.parse` only; no `eval`, `exec`, `compile` to code objects, `import`).
- Do not edit `packages/techniques`, other chunkers' behavior, catalogue files or `docs/PROGRESS.md`. Fixes to `structure.py` only with a test.
- Non-ASCII characters in Python source only as `\u` escapes.
