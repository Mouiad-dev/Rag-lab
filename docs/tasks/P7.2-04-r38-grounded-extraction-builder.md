## Goal
A builder makes one chat call per chunk of a ready index version through the providers port, keeps only grounded entities and relations, and writes one `EntityGraph` through `EntityGraphStore.add_entity_graph`. Rejections are counted per item, never kept.

## Change
- Create `packages/indexing/src/rag_foundry_indexing/graph_extract.py`:
  - `R38_SYSTEM_V1` and its SHA-256. Use the untrusted-JSON wording of R23/R24.
  - Reply schema: `{"entities":[{"name","type","quote"}],"relations":[{"source","target","label","quote"}]}`.
  - `EntityRelationExtractConfig(extra="forbid")`:
    - `max_chunks` (200, at most 2000);
    - `max_entities_per_chunk` (10, at most 30);
    - `max_relations_per_chunk` (10, at most 30);
    - `max_output_tokens`, `temperature=0.0`, `on_invalid: fail|skip`.
  - `EntityRelationGraphBuilder(config, *, scope, index_version, index, source, chat)`.
    - `graph_key()` uses `graph_key_for` over `{index_version_id, technique_id: "R38", builder_version: "1", prompt_sha256, chat_provider, chat_model, config: model_dump()}`.
    - `build() -> GraphBuildReport(graph_key, chunks_processed, chat_calls, entities, relations, rejected: tuple[RejectedItem(chunk_id, item_index, item_kind, reason)], usage)`.
  - Order of work: check the version is ready, the chunk cap and `check_chat`. Then raise `graph_exists` if `get_entity_graph` finds the key, before any chat call. Then make all chat calls, and finally make one `add_entity_graph` write.
  - Hard errors (raise `IndexingError`): the chunk text differs from the view slice (`graph_source_mismatch`); more than 5000 entities or 10000 relations in total (`graph_too_large`).
  - Item rejections (reasons), with the other items kept:
    - `quote_not_found`: the quote is not verbatim in the chunk;
    - `ambiguous_quote`: the quote occurs more than once in the chunk. Rejected, because a first-occurrence guess could point to the wrong span;
    - `name_not_in_quote`: the normalized entity name is not inside the normalized quote;
    - `unknown_endpoint`: a relation endpoint is not an entity kept from the same chunk;
    - `endpoint_not_in_quote`: an endpoint name is not inside the relation quote;
    - `too_many_items`;
    - `too_many_spans`: more than 50 spans for one ID across chunks.
  - Span offsets are `chunk.start + quote_index`. Whole-reply invalid JSON or shape follows `on_invalid`, as in R23.
  - Entities with the same `entity_id` merge their mentions in chunk order. Output entities and relations are sorted by ID.
- `__init__.py`: export the builder, config, report and `R38_SYSTEM_V1`.
- Create `tests/indexing/test_graph_extract.py`:
  - a happy path with an English chunk and one Arabic chunk (`\uXXXX` escapes), where the graph is readable back from the in-memory store;
  - each rejection reason, including `ambiguous_quote`;
  - a merge across two chunks;
  - `graph_source_mismatch` raises;
  - an existing key raises before any chat call;
  - injected instruction text stays inside the user JSON;
  - `len(usage) == chat_calls == chunks`;
  - the key is stable and changes with the model and the config.
