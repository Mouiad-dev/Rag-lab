## Change
- Determinism rule for both demos: never print chunk, view, node, entity, fact, tree or KG IDs or keys (they come from random UUIDs). Print paragraph labels (`LABELS`), offsets, quotes, levels, schema and prompt SHAs (stable), statuses and counts. Map IDs to labels before printing; order by label.
- Create `docs/techniques/lessons/demos/p73_raptor_demo.py`. ASCII source, `\u` escapes, public APIs, scripted chat, lexical test embedder, in-memory store, no timing values. Header: command, date, "offline; scripted summaries; shows lineage and plumbing, not summary or retrieval quality". Sections:
  1. Fixture paragraphs (labels, offsets, topics); gold spans.
  2. Tree: per level the nodes as member label sets, `synthetic` flag and summary text (labelled synthetic); clustering iterations/converged; a promoted cluster under `skip` from a second build; store round trip equal.
  3. Lineage: for the root and each level-1 node, the leaf labels and quotes, each equal to the view slice.
  4. Comparison table per question (`Q_BUDGET`, `Q_OVERVIEW`, `Q_DETAIL`, `Q_ARABIC`) at a 3-hit budget: R37 collapsed, R37 traversal, flat (`max_levels=1`), R02; hit labels, `recall (hits=n)`; selected nodes per R37 run as level + member labels.
  5. Losing case explained: traversal beam 1 on `Q_DETAIL`.
  6. Cost: chat and embed calls and tokens for build and per query. "Update cost = full rebuild; not measured separately."
- Create `docs/techniques/lessons/demos/p73_kag_demo.py` (same rules). Header: "offline; scripted extraction and plans; shows schema checks, logical forms and grounding, not extraction or planning quality". Sections:
  1. Schema (types, properties, relations, cardinality) and its SHA.
  2. Graph: entities and facts by name with label, span and quote; rejected items by reason; the Blue Reef conflict; mutual index for two paragraphs; store round trip equal.
  3. Per question: plan JSON, each step's status, bindings by name, supporting facts and quotes, final status and derived answer.
  4. Re-planning: one success and one failure (both attempts' reasons, 2 calls each).
  5. Baselines: R48 vs R38 vs R02 `recall (hits=n)` per question; note that R38/R02 cannot count.
  6. Losing cases: extraction miss, partial (Gulf Marine), conflict, `unsupported_operator`, `schema_violation`, invalid plan. One line points to `tests/answering/test_kag_answer.py` for the cited answer.
  7. Cost: extraction calls/tokens; plan calls/tokens per question incl. re-plans. "Update cost = full rebuild; not measured separately."
- Both end with `## Live run (orchestrator)` and `<orchestrator>` placeholders. Generate both evidence files.
