## Goal
- R27 fits ranked evidence into a stated token budget and orders it for the prompt. The budget is: context window - reserved output - prompt overhead - fixed text.
- Every hit that is not placed is recorded with a reason. Nothing is cut silently.
- Hits are never edited, so provenance is unchanged. Token counts are an **estimate** from `lab-regex-v1`, not the model's tokenizer.

## Change
- Create `packing.py`, R27, `CONTEXT_BUILDER`, 1.0.0, ADAPTATION.
  - `ContextPackConfig` (frozen, `extra="forbid"`):
    - `order`: `"rank"` (default), `"lost_in_middle"` or `"source_order"`;
    - `context_window_tokens`: `int | None` (None, 256..2_000_000);
    - `prompt_overhead_tokens`: 256 (0..100000);
    - `per_item_overhead_tokens`: 16 (0..1000);
    - `drop_contained`: True.
  - Models:
    - `PlacedEvidence(chunk_id, rank, position, cost_tokens)`. `position` is **1-based**: the first evidence block in the prompt has position 1;
    - `DroppedEvidence(chunk_id, rank, reason: budget|contained, cost_tokens, kept_chunk_id: str | None)`;
    - `PackTrace(technique_id, input_technique_id, order, tokenizer="lab-regex-v1", context_window, reserve_output_tokens, fixed_tokens, budget_tokens, used_tokens, placed, dropped)`. `placed` is in position order;
    - `PackedContext(trace, items: tuple[RetrievedChunk, ...])`. Items are the original hits, unchanged, in prompt order.
  - `ContextPacker(config).pack(result, *, model_context_window: int | None, reserve_output_tokens: int, fixed_text: str = "")`:
    - Input errors raise `packing_invalid_input`: grounding is not `corpus`, `index_version_id` is None, duplicate ranks or chunk ids, or more than 50 hits. Gaps in ranks are allowed.
    - Window: use `config.context_window_tokens` if it is set, else `model_context_window`. If both are None, raise `packing_no_context_window`. If the config value is greater than a known model window, raise `packing_window_exceeds_model`.
    - `budget = window - reserve_output_tokens - prompt_overhead_tokens - tokens(fixed_text)`. If it is <= 0, raise `packing_no_budget`.
    - `tokens(t) = len(LabRegexTokenizer().token_spans(t))`, and `cost = tokens(hit.text) + per_item_overhead_tokens`.
    - Selection walks the hits by ascending rank:
      - a hit whose span lies inside an already placed hit of the same view becomes `contained`, with `kept_chunk_id` set;
      - otherwise, the first hit whose cost would push the used tokens above the budget stops selection. It and every later non-contained hit become `budget`.
    - Order of the selected hits (put the rule in the docstring):
      - `rank`: ascending rank;
      - `lost_in_middle`: in rank order, index i (0-based) goes to the front list if i is even and to the back list if odd; the result is front + reversed(back). For 5 hits the ranks in output order are 1,3,5,4,2;
      - `source_order`: sorted by `(extraction_view_id, start, end, rank)`.
  - Add `packing_invalid_input`, `packing_no_context_window`, `packing_window_exceeds_model` and `packing_no_budget` to CODES. Register R27 and export the new names.
- Create `tests/indexing/test_packing.py`. All hits are in one view, R02 input:

  | Rank | Text | Span | Tokens |
  |---|---|---|---|
  | h1 r1 | `"Alpha one."` | [40,50) | 3 |
  | h2 r2 | `"Beta two three."` | [0,15) | 4 |
  | h3 r3 | `"Gamma 12345."` | [20,32) | 4 (`123`, `45`) |
  | h4 r4 | `"Delta."` | [60,66) | 2 |
  | h5 r5 | `"Eps five six seven."` | [80,99) | 5 |

  Unless a case says otherwise, use `prompt_overhead_tokens=30`, `per_item_overhead_tokens=2`, `model_context_window=100` and `reserve_output_tokens=50`, so the budget is 20. Expected:
  1. `order="rank"`: ranks in output order [1,2,3] with costs [5,6,6] and positions [1,2,3]; `used_tokens` 17. Dropped: (r4, budget, 4) and (r5, budget, 7).
  2. `fixed_text="Question: x?"`: `fixed_tokens` 4, budget 16. Ranks in output order [1,2], `used_tokens` 11; r3 is dropped with reason budget.
  3. Window 1000, reserve 10, overhead 0. Expected ranks in output order (`[item.rank for item in items]`, equal to `[p.rank for p in trace.placed]`, with positions 1..n):
     - `lost_in_middle` on h1-h5: [1,3,5,4,2];
     - `lost_in_middle` on h1-h4: [1,3,4,2]; on h1-h3: [1,3,2]; on h1-h2: [1,2]; on h1 alone: [1];
     - `source_order` on h1-h5: [2,3,1,4,5].
  4. Contained: the input is h1 r1, d r2 (`"one."` at [46,50)) and h2 r3. d is dropped as `contained` with `kept_chunk_id == h1.chunk_id`; ranks in output order [1,3].
  5. Losing case: h5 alone as r1, window 10, reserve 5, overhead 0. No items; dropped (r1, budget, 7); `used_tokens` 0.
  6. Window errors:
     - window 100, reserve 70, overhead 30 raises `packing_no_budget`;
     - model window None and config None raises `packing_no_context_window`;
     - config 300 with model 256 raises `packing_window_exceeds_model`;
     - config 300 with model None is used as the window (`trace.context_window == 300`).
  7. Input errors and determinism:
     - duplicate ranks raise `packing_invalid_input`;
     - `grounding="none"` raises `packing_invalid_input`;
     - ranks [1,3] (a gap) are accepted;
     - `items[i] ==` the input hit with that rank;
     - two calls give equal `model_dump_json()`.
