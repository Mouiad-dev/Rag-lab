## Goal
R15 splits a composite question into subquestions with checked dependencies, checks that every hard constraint of the original survives in some subquestion, and retrieves per subquestion. R16 asks for one more general question and always retrieves with both the original and the step-back question; constraints the step-back question drops are reported, never hidden.

## Change
- Create `rag_foundry_indexing/decompose.py`:
  - `DECOMPOSE_SYSTEM_V1` (untrusted-data sentence; split into the fewest standalone subquestions in the question's language; keep every number, identifier, quoted phrase and negation; reply `{"subquestions": [{"id": "s1", "text": "...", "depends_on": []}]}`), sha256.
  - `DecomposeConfig`: `max_subquestions 2..6=4`, `k 1..50=5`, `max_output_tokens 64..1024=384`, `temperature 0..2|None=0.0`, `on_invalid: fail|original = "fail"`, `on_constraint_loss: fail|original = "original"`.
  - Validation: 1..max items (more gives `too_many_queries`); `id` matches `^s[1-9][0-9]?$` and is unique; `text` non-empty <= 2000; extra keys give `invalid_model_output`; `depends_on` may name only ids that appear earlier, else `invalid_dependency` (this rules out self-loops, cycles and unknown ids).
  - Constraint check: `missing_constraints(original, all subquestion texts)`; loss gives status `constraint_loss` and retrieval with the original only, or raises in `fail` mode.
  - `QuestionDecomposition` (R15, `QUERY_TRANSFORM`, `ADAPTATION`) `async run(question, *, chat, retriever) -> TransformedRetrieval`: retrieves the original, then each subquestion in order with its literal text; `generated` keeps `id` and `depends_on`; merged via `merge_best_rank(technique_id="R15", scoring="decomposition-union-best-rank")`.
- Create `rag_foundry_indexing/step_back.py`:
  - `STEP_BACK_SYSTEM_V1` (untrusted-data sentence; one more general question about the underlying concept or principle, same language; zero-shot; reply `{"step_back_question": "..."}`), sha256.
  - `StepBackConfig`: `k 1..50=5`, `max_output_tokens 32..512=128`, `temperature 0..2|None=0.0`, `on_invalid: fail|original = "fail"`.
  - `StepBackRetrieval` (R16, `QUERY_TRANSFORM`, `ADAPTATION`) retrieves with the original first, then the step-back question. It never retrieves with the step-back question alone.
  - `trace.lost_constraints` lists the constraints missing from the step-back question. Status stays `applied`, because the loss is expected and reported.
  - A step-back equal to the original (NFC casefold) is dropped: `duplicates_dropped == 1`, one retrieval. Merge via `merge_best_rank(technique_id="R16", scoring="step-back-union-best-rank")`; the original wins ties.
- Register both; export.
- Create `tests/indexing/test_decompose.py` and `tests/indexing/test_step_back.py` (non-ASCII only as `\u` escapes):
  - R15 dependencies: two subquestions with `s2` depending on `s1` give 3 retrieval calls (original, s1, s2) and keep `depends_on`. `s1` depending on `s2`, on itself or on `s9` each give `invalid_dependency`.
  - R15 validation: a duplicate id, or 5 items with max 4, fail with their codes. Subquestions that drop `2025` give `constraint_loss` (original-only retrieval; `fail` raises). An Arabic composite question with both parts kept gives `applied`.
  - R16: 2 retrieval calls, original first. A hit found only by the step-back query is in the result with its `q1` component. `lost_constraints == ("ab-1234",)` when the step-back drops it, with status `applied`. A duplicate step-back gives 1 call.
  - Both: one chat request per run; `BudgetedChatModel` with `max_calls=0` raises before any retrieval; bad JSON gives `invalid_model_output`; `validate_config` defaults.

## Constraints
- No answer generation and no substitution of earlier answers into dependent subquestions (P6/P8). Do not call the step-back output "evidence". ASCII sources.
- Fidelity note for the lesson (P5.4-05): arXiv 2310.06117 uses few-shot step-back prompting followed by reasoning. Ours is a zero-shot prompt used only for retrieval: an adaptation.
