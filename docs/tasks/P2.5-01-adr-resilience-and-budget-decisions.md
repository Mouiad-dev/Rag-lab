## Change
- Edit ADR-0001: append `## Update 2026-11-xx (P2.5)` (date = day written), max ~35 lines:
  - **Ownership.** Retries and per-call deadlines live only in provider-side wrappers in `packages/providers` (`resilience.py`), wrapping the bound adapter; adapters keep doing one HTTP attempt each; domain/technique code never retries model calls. Budgets are hard caps checked before every attempt (`budget.py`). Wrapper order: `Resilient( Budgeted( Recording( adapter ) ) )`, so every attempt is budget-checked and recorded, and a budget error is never retried.
  - **Decisions D1-D10**, each with the owner's answer if the caller supplies one, else the proposed value plus "proposed, pending owner":
    - D1 attempts: `max_attempts = 3` (1 call + 2 retries).
    - D2 backoff: full jitter, base 0.5 s, cap 8 s; `Retry-After` (delta-seconds) honoured up to 60 s; larger → no retry, raise at once.
    - D3 retryable reasons: `connection`, `rate_limited`, `overloaded`, `server_error`. `timeout` is retried only for `local` profiles (a paid timeout may be billed; Moonshot 504 arrives after 900 s). Never retried: `auth`, `billing`, `invalid_request`, `input_too_long`, `model_not_found`, `refused`, `bad_response`. A stream is retried only if it failed before its first chunk.
    - D4 per-attempt deadline: 300 s for `complete`, `stream` (whole stream) and `embed`; the adapters' httpx timeouts (60/120 s per operation) stay as they are. Note: Sonnet at 16384 output tokens may approach 300 s.
    - D5 per-run budget: no implicit amount. `build_registry` refuses a run that binds any non-local profile without an explicit `RunBudget(max_usd=...)`. Suggested example value USD 0.50.
    - D6 local profiles (`capabilities.local is True`) never block the USD cap; they count toward `max_calls` only.
    - D7 a non-local profile with an unknown input or output rate is refused before the call (`UnboundedCostError`). A finished call whose cost is None keeps its full reservation as spent.
    - D8 a stream stopped early, cancelled, or failed without usage: the budget keeps the full worst-case reservation as spent ("unsettled"); the ledger records nothing (no invented tokens). Alternative the owner may pick: record an `ESTIMATED` usage.
    - D9 worst-case cost per attempt: input bound = UTF-8 bytes of all message contents, tool specs and response schema (JSON, `ensure_ascii=False`) + 64; output bound = `request.max_output_tokens` or the adapter's default cap; input priced at max(input rate, cache-write rate when set). Embeddings: input only. Caveat: whether Moonshot K3 reasoning tokens fall inside `max_completion_tokens` is not confirmed.
    - D10 live evidence for P2.5 done: Ollama (free) and Anthropic Haiku with a USD 0.05 cap. Moonshot, LM Studio and vLLM not run.
  - **429 classification.** OpenAI `insufficient_quota` (code or type) and Moonshot `exceeded_current_quota_error` map to `billing`; Moonshot `engine_overloaded_error` maps to `overloaded`. Anthropic spend-cap 429s have no `retry-after`; they fail after D1 attempts at zero token cost.
