## Change
- Edit `ADR-0001` "Evidence": add a dated "Verified 2026-11-xx (P2.2-01)" block answering, with links:
  1. Latest stable LiteLLM version and release date; Python 3.12 support; license.
  2. Security: any advisories or yanked/compromised PyPI releases (check the reported March 2026 PyPI compromise of some 1.82.x releases); the chosen version must be outside every affected range.
  3. Model prefix for Ollama chat (`ollama_chat/` vs `ollama/`) and for embeddings; how `api_base` is passed; that `acompletion`, `acompletion(stream=True)` and `aembedding` exist and are async.
  4. Usage: does LiteLLM pass through Ollama `prompt_eval_count`/`eval_count` (chat) and `prompt_eval_count` (`/api/embed`), or does it compute counts itself (tokenizer fallback) when Ollama omits them? Can the adapter tell the two apart? This decides `token_source`.
  5. Default retries and timeouts in LiteLLM, and how to disable retries (`num_retries=0` or equivalent). Retries are owned by P2.5.
  6. Does importing litellm make network calls at import (for example fetching the remote model cost map) and how to disable that (env var name). Does it send telemetry by default?
  7. Exception classes raised on connection refused / 404 model not found / timeout.
  8. Install footprint: wheel size and the direct dependency list from PyPI metadata (do not install).
- Edit `docs/plan/FREE_MODELS.md`: add a "Verified for P2.2" table for `gemma4:e4b` and `bge-m3` only: download size, context length, embedding dim, tool-calling / vision / structured-output support per the model page, license, Ollama minimum version. Write "unknown" for anything the official pages do not state. Confirm `ollama/ollama:0.40.13` is new enough for both models.
- Finish the Result section with one verdict line: `FITS` or `DOES NOT FIT: <reason>`.
