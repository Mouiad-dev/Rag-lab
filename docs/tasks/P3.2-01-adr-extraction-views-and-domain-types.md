## Change
- Create `docs/decisions/ADR-0010-extraction-views-and-normalization.md` (max ~85 lines, README row). Decision: `DocumentVersion -> ExtractionView -> SourceBlock`; views immutable, owned by one version, never by chunks; identity key `(document_version_id, extractor, extractor_version, profile_id, unicode_version)`; same key returns the existing view; any change makes a new view; old views stay valid. Text layers: decoded source (or PDF raw page text) -> canonical text (stored, `canonical-v1`) -> search text (derived on demand, never stored or anchored). `block_text = canonical[block.start:block.end]`; `SourceAnchor` v1 `text_range` is relative to `block_text`; anchors target canonical (NFC) text, so `exact` can differ from the original in mark order; `source_map` reaches the decoded source or PDF raw text. "Reversible" = positions map back; text comes from the stored original, a lossy step is never inverted. Decisions, all "decided by owner 2026-11-05":
  D1 PDF library `pypdfium2` (Apache-2.0/BSD-3, PDFium BSD-3 plus bundled third-party notices), verified and pinned in 04; rejected PyMuPDF (AGPL), poppler tools (GPL) · D2 third-party HTML parser, chosen in 03 after verification (candidates selectolax, html5lib, lxml); offsets come from an alignment layer over the source; unalignable text raises `alignment_failed`, never a guess; no network, scripts or external entities · D3 Markdown: stdlib line scanner, markup kept verbatim · D4 no API trigger; service + dev/test CLI in the worker; queued job at P8.4; never in the API process. Known gap: no subprocess isolation in P3.2, so a native crash or hang in a parser can take down the worker; subprocess isolation with timeout and memory limit planned for P8.4 · D5 metadata row in Postgres; payload (canonical text, blocks, source map, IDs) as canonical JSON in the object store; no blocks table yet · D6 `canonical-v1` = LF newlines + NFC only · D7 `search-ar-en-v1`: NFKC, casefold, NFKC, strip Cf + U+034F, tatweel, harakat U+064B-U+065F and U+0670, alef/yeh/kaf folds, Arabic-Indic digits, whitespace collapse; not folded: teh marbuta, hamza seats U+0624/U+0626, Quranic marks U+06D6-U+06ED. Alef maksura to yeh trades precision for recall (U+0639 U+0644 U+0649 and U+0639 U+0644 U+064A then match); search text only, never stored or anchored · D8 PDF: one `page` block per page, joined by `\n\n`, no geometry until P3.3 · D9 Arabic PDF test skipped until the owner supplies a license-clean fixture (gap) · D10 dedup by identity key · D11 limits 2,000 pages and 5,000,000 code points (worst-case offset map about 5M segments x 40 B = 200 MB; typical far less since identity runs merge); encrypted (needs a user password) and no text layer are typed errors; empty pages are warnings · D12 views record `unicodedata.unidata_version`; a Python upgrade creates new views; tests never hard-code it.
- Create `rag_foundry_domain/extraction.py`:
  - `BlockKind` StrEnum: `heading`, `paragraph`, `code`, `page`.
  - `SourceBlock`: `block_id` (`^b[0-9]{5,8}$`, `f"b{ordinal:05d}"`), `ordinal >= 0`, `kind`, `start`, `end` (half-open code points in canonical text, `end >= start`), `section_path: tuple[str, ...]`, `heading_level: int | None` (1-6, headings only), `page_index: int | None` (>= 0).
  - `NewExtraction`: `document_id`, `document_version_id` (Uuid4), `extractor` (`^[a-z0-9._-]{1,64}$`), `extractor_version` (1..128), `profile_id`, `unicode_version` (`^\d+\.\d+\.\d+$`), `canonical_sha256`, `char_count >= 1`, `block_count >= 1`, `page_count: int | None` (>= 1), `payload_sha256`, `payload_key`, `payload_schema_version: Literal[1]`, `warnings: tuple[str, ...]` (codes `^[a-z0-9_:]{1,64}$`, never content).
  - `ExtractionView` = those + `id`, `tenant_id`, `project_id`, UTC `created_at`; `ExtractionKey` (the five identity fields); `ExtractionOutcome(view, created)`. Frozen, `extra="forbid"`.
- `errors.py`: `ExtractionError(IntakeError)` codes `no_text_layer`, `pdf_encrypted`, `pdf_malformed`, `too_many_pages`, `text_too_long`, `integrity_mismatch`, `unsupported_extractor`; subclass `ExtractionAlignmentError` code `alignment_failed`. No content or paths in messages.
- `ports.py` `ExtractionRepository` (async): `find_view(scope, key) -> ExtractionView | None`; `create_view_or_get(scope, new) -> ExtractionOutcome` (version must exist in scope, else `NotFoundError`; atomic dedup); `get_view(scope, view_id)`; `list_views(scope, document_version_id)` by `created_at`, then `id`.
- `testing.py`: `InMemoryExtractionRepository(documents)`; `ExtractionRepoFactory`; public `make_new_extraction(...)`; `EXTRACTION_REPOSITORY_CHECKS`: same key -> `created=False`, same ID, `find_view` finds it; other `extractor_version`/`profile_id` -> second view; other tenant/project, unknown or malformed IDs -> `NotFoundError` (create/get/list) and `None` (find); 10 concurrent creates -> one view; list order; frozen.
- Tests `tests/domain/test_extraction.py`, `tests/domain/test_extraction_repository_checks.py` (pass in-memory; each check fails on a broken repo).
