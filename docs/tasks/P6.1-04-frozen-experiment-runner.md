## Goal
A runner that freezes the run config and hashes it into a run id. The config holds: dataset id, version and sha; the corpus; an index fingerprint; the code version; splits and the held-out flag; ks; thresholds; and technique ids with plugin versions and validated configs. The runner writes per-case results JSON. Rerunning the same config, even on a freshly rebuilt index, gives byte-identical results (roadmap done criterion). Usage is counted per technique and per stage.

## Change
Create `src/rag_foundry_evaluation/runner.py`.

**Corpus binding and index fingerprint**
- `BoundDocument(extraction_view_id, text)` is a frozen dataclass.
- `check_binding(dataset, binding)` raises these codes:
  - `binding_missing_document`
  - `binding_text_mismatch` (sha256 of the UTF-8 text, or length, differs)
  - `binding_quote_mismatch` (`text[start:end] != quote`)
  - `binding_duplicate_view`
- `async index_fingerprint(scope, index, version, binding) -> str`:
  - The result is the sha256 of `canonical_json({"index_config": version.model_dump(mode="json", include=set(IndexConfig.model_fields)), "chunks": sorted([doc_key, start, end, text_sha256])})`.
  - Never include `extraction_view_ids` or `corpus_sha256`; both are random per build. Also exclude ids, tenant fields and timestamps.
  - Page through `list_chunks` with limit 100.
  - A chunk on an unbound view raises `binding_unbound_view`.

**Run config and run id**
- `TechniqueSpec(label, technique_id, config: dict)`. The label must match `^[A-Za-z0-9+._-]{1,40}$`.
- `ResolvedTechnique(label, technique_id, plugin_version, config: dict)`, where `config` is the validated `model_dump(mode="json")`.
- `RunConfig` (frozen, `extra="forbid"`):
  - `format="rag-foundry.eval-run-config"`, `format_version="1"`
  - `dataset_id`, `dataset_version`, `dataset_sha256`
  - `corpus` (sorted `(doc_key, text_sha256)` pairs)
  - `index_fingerprint`, `code_version`
  - `splits`, `allow_held_out: bool` (part of the run id)
  - `ks`, `coverage_threshold`, `leakage_jaccard_threshold`
  - `techniques`
- `build_run_config(dataset, *, registry, techniques, index_fingerprint, code_version, splits=("dev","validation"), ks=(1,3,5), coverage_threshold=0.8, leakage_jaccard_threshold=0.8, allow_held_out=False)`:
  - Validate each technique through `registry.validate_config`. Let its errors propagate.
  - Duplicate labels raise `duplicate_label`.
  - `held_out` in `splits` without `allow_held_out` raises `held_out_locked`.
- `run_id(config) = "run-" + sha256(canonical_json(config.model_dump(mode="json")))[:16]`.

**Usage per stage**
- `StageSinks.sink(stage) -> UsageLedger` creates one ledger per stage. Stage names match `^[a-z_]{1,32}$`.
- `totals()` returns a dict of stage to `UsageTotals`.

**`async run_experiment(dataset, config, *, binding, registry, factory, scope, index, version, index_build_usage: UsageTotals | None = None, clock=time.perf_counter) -> RunOutput`**
1. Do all of these checks before any `factory` call:
   - Recompute `dataset_sha256`. A mismatch raises `config_dataset_mismatch`.
   - Run `check_binding`.
   - Recompute `await index_fingerprint(scope, index, version, binding)`. If it differs from `config.index_fingerprint`, raise `config_index_mismatch`.
   - Re-check `held_out`: if it is in `config.splits` and `config.allow_held_out` is False, raise `held_out_locked`. This matters for a `RunConfig` built directly.
   - Run `check_leakage`, then `raise_on_errors`.
2. For each technique in config order:
   - Create a new `StageSinks` and call `factory(resolved, registry.validate_config(id, config), sinks)`.
   - For each case in dataset order whose split is in `splits`, call `retrieve(question)`.
   - On an exception, set `status = "error"` and `error = f"{type(exc).__name__}:{getattr(exc, 'code', '')}"`, and use an empty hit list.
   - Map each hit's view to a `doc_key` through the binding (unbound gives None). Its `text_sha256` is the sha256 of the hit text.
3. `RunOutput` has these fields:
   - `run_id`, `config`
   - `results_json`: `json.dumps(results, ensure_ascii=True, sort_keys=True, indent=2) + "\n"`. Results contain:
     - `format="rag-foundry.eval-run-results"`, `format_version="1"`, `run_id`, `config`
     - `leakage` (the report dump)
     - `usage` (`{label: {stage: UsageTotals.model_dump(mode="json")}}`, so Decimal cost becomes a string)
     - `index_build_usage` (`model_dump(mode="json")` or null)
     - `cases`: per case and label, the hits (doc_key, start, end, rank, score rounded to 6 places, text_sha256), the metrics rounded to 6 places, status and error
     - `summaries` (`{label: aggregate}`)
     - No chunk, view or index ids, and no timings.
   - `timings`: `{label: {case_id: total_ms}}` from `clock`, kept outside `results_json`. Retrieval has no stream, so TTFT is not applicable; record `"ttft": "not_applicable"`.
- `git_code_version(repo_root) -> str`:
  - Return `git rev-parse HEAD`, plus `-dirty` when `git status --porcelain` prints anything.
  - Use `subprocess.run([...], check=True, capture_output=True, text=True)` with no shell.

## Tests
`tests/evaluation/_corpus.py`:
- `DOC_KEY = "paired-fixture"`.
- `build_dataset(rows)` takes rows of `(case_id, language, tags, split)`. It looks up the question and paragraph in `CASES`, uses grade 1 and `quote = paragraph`, and makes one `EvalDocument` for `DOC`.
- `async bound_index(embedder, spans=SPANS)` returns `ready_index(spans, embedder)` plus the binding.
- `make_factory(owner, index, version, embedder)` builds R02, R03 and R06. It wraps the embedder as `RecordingEmbeddingModel(embedder, sinks.sink("query_embedding"))`.

`tests/evaluation/test_runner.py` uses the cases en-fact (dev), id-exact (dev), ar-fact (validation) and unanswerable (validation), with labels R02, R03 and R06:
- **Rerun on two builds.** Build the index twice and run each with a fake clock that gives different values per run.
  - The fingerprints are equal. `results_json` and `run_id` are byte-identical, while `timings` differ.
  - Neither index id nor view id appears in `results_json`.
  - Parse `results_json`: there are 4 cases x 3 labels, and every answerable case has non-empty hits for every label.
- **Changes that must show up:**
  - R03 `k=3` instead of 5 changes `run_id` and also changes `results_json`.
  - A different `code_version` changes `run_id`, and so does one changed grade.
- `run_id` matches `^run-[0-9a-f]{16}$`.
- R03 on id-exact gives `rr == 1.0` (as in the P5.2 test).
- **Usage.** R02 `query_embedding` calls equal the number of cases run (4). R03 usage is `{}`. Index-build usage, recorded by wrapping the embedder for `ready_index`, has 19 calls (`len(SPANS) == 19`). The `cost_usd` field is a JSON string.
- **Raises before any factory call** (track calls in a list):
  - R03 config `{"k": 0}`
  - an unknown config field
  - `build_run_config` with `held_out` and no flag
  - a directly built `RunConfig` with `held_out` in splits and `allow_held_out=False` passed to `run_experiment`: `held_out_locked`
  - a config fingerprinted on the full index, run against `bound_index(embedder, SPANS[:-1])` (one chunk different): `config_index_mismatch`
  - a leaking dataset
  - binding text changed by one char
- `allow_held_out=True` and False give different run ids for the same splits `("dev",)`.
- A retriever raising `IndexingError("empty_query")` on one case: status error, counted in `n_errors`, and the run continues.
- `git_code_version` matches `^[0-9a-f]{40}(-dirty)?$`. Skip if `git` is missing.
