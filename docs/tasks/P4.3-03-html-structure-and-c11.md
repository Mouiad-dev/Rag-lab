## Goal
Chunkers can see the block structure the extractors already store (kind, section path, heading level, page index), and C09 chunks an HTML extraction view into DOM sections with locators (section path + block ids), removing repeated boilerplate blocks (for example a navigation menu repeated in header and footer) without losing content or source identity. C11 stays `planned` with a written reason.

## Why the contract changes
The HTML view's canonical text has no tags; its structure lives only in `SourceBlock.kind/section_path/heading_level`. `ChunkInput.blocks` (`TextBlock`) currently carries only `block_id/start/end`, so C09 cannot be faithful without these fields. The change is additive (all new fields optional with defaults), so every existing chunker and caller keeps working.

## Change
- Edit `kinds.py` `TextBlock`: add `kind: Literal["heading", "paragraph", "code", "page"] | None = None`, `section_path: tuple[str, ...] = ()`, `heading_level: int | None = Field(default=None, ge=1, le=6)`, `page_index: int | None = Field(default=None, ge=0)`. Validator: `heading_level` is set only when `kind == "heading"` and is required for it (same rule as `SourceBlock`), but `kind=None` with no level stays valid. No other change to `kinds.py`.
- Edit `service.py`: build `TextBlock(block_id=..., start=..., end=..., kind=b.kind.value, section_path=b.section_path, heading_level=b.heading_level, page_index=b.page_index)`. Nothing else.
- Create `packages/chunking/src/rag_foundry_chunking/html_structure.py`: `HtmlStructureConfig` (`chunk_size`, `oversized`, `drop_repeated_boilerplate: bool = True`, `boilerplate_max_chars: int = 120` (1..2000), `boilerplate_min_repeats: int = 2` (2..100)) and `HtmlStructureChunker` (manifest `C09`, `PluginKind.CHUNKER`, `1.0.0`, `Fidelity.ADAPTATION`).
  - Needs blocks with `kind`; when `doc.blocks` is empty or any block has `kind=None`, raise `StructureParseError("missing_structure")` (add the code; message says C09 needs extraction blocks with kinds).
  - Boilerplate: a non-heading block whose trimmed text is `<= boilerplate_max_chars` and whose exact text (whitespace-collapsed) occurs in `>= boilerplate_min_repeats` blocks is boilerplate. The **first** occurrence is kept as content; later occurrences are left out of chunk bodies and reported in `StructureResult.skipped` as `SkippedRange(start, end, reason="repeated_boilerplate", block_id=...)`. With `drop_repeated_boilerplate=False` nothing is skipped. A skipped block that sits between kept blocks of one chunk is not allowed: chunk bodies never contain a skipped range (end the chunk before it).
  - Sections: consecutive kept blocks with the same `section_path` form a section; a heading block starts a new section. Blocks are units (`(block.start, block.end)`, trimmed), packed with `pack(..., overlap_units=0)` within a section only. Each chunk: `kind="section"` (`"code"` when every block is code), `path = section_path`, `block_ids` = ids of its blocks (the locators), `context` = `ContextSpan(role="heading")` for each ancestor heading block found in the document before the chunk (the heading block whose title matches each path prefix, the nearest preceding one), plus the section's own heading for chunks after the first. A block larger than `chunk_size` follows `oversized`. Text outside all blocks is not chunked (the HTML view has none except separators).
- Edit `__init__.py`: register `HtmlStructureChunker`; export it and its config. Add lines only.
- Create `tests/chunking/test_html_structure.py`: build the `ChunkInput` from a real HTML extraction in the test (`rag_foundry_ingestion.extract` HTML extractor on a small fixture string, then `TextBlock`s from its blocks the same way `service.py` does; skip with `pytest.importorskip("selectolax")` if missing). Fixture: `<header>` with a 4-link menu as `<p>`/`<li>` items, `<h1>`, `<h2>` sections with paragraphs and a `<pre>` block, an Arabic `<h2>` section (`\u` escapes, NFC), and a `<footer>` repeating the same menu. Assert: paths per chunk; footer menu blocks reported in `skipped` with their block ids and exact offsets, and their text still appears in the first (kept) occurrence; every non-whitespace code point of the canonical text is in exactly one chunk body or one skipped range; chunk `block_ids` equal the blocks overlapping the chunk; context heading text for an `<h2>` section chunk equals the `<h1>` text; `drop_repeated_boilerplate=False` skips nothing; oversized `<p>` in `keep` and `split`; missing kinds raise `StructureParseError("missing_structure")`; registry default config; unknown key rejected.
- Add one test to `tests/indexing/test_index_service.py` (or a new `tests/indexing/test_index_blocks.py` using the same fixtures): a recording chunker wrapper sees `TextBlock.kind`/`section_path`/`heading_level` equal to the stored view's blocks during `build`.
- Create `tests/techniques/test_text_block_fields.py` (or extend an existing kinds test): defaults keep old construction valid; `heading_level` without `kind="heading"` rejected; heading without level rejected; level 7 rejected.
- Create lesson draft `docs/techniques/lessons/C09-html-structure.md` (C08 format, real demo output only). Limitations: boilerplate detection is a repeated-block heuristic, not landmark (`<nav>`, `role=navigation`) detection; that needs the HTML extractor to record landmarks in the view (an extractor version change, later step). HTML tables are flattened to cell blocks by the current extractor, so C12 does not see HTML table rows.
