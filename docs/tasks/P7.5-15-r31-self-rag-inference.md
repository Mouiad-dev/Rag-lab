## Goal
R31 follows the official short-form Self-RAG procedure: the model decides retrieval from `[Retrieval]` vs `[No Retrieval]` probabilities, generates one candidate per retrieved passage, scores each with the probabilities of its relevance, support and utility tokens plus sequence logprob, and returns the best candidate citing that passage's original chunk. Decisions come only from reflection-token probabilities, never from a self-check prompt.

## Amendments from P7.5-13 and P7.5-14 (orchestrator, 2026-11-24; these override the Change section where they differ)
- Model calls only through `RawCompletionModel.complete_raw` with `temperature=0.0`, `top_p=1.0`, `top_k=0`, `top_logprobs=20` (evidence section 6, conditions b and e). Tokens are matched by text (`TokenLogprob.token`), there are no ids; check the needed token strings exist by name only (the GGUF check in 13 proved the ids); `selfrag_tokens_missing` is raised when the provider profile does not declare `RAW_LOGPROBS` or a config token list is empty/unknown, not from a vocab lookup.
- Missing token in the top 20: logprob -100 (the official fallback, evidence section 2), so probability exp(-100); count every such fallback per group (retrieval, relevance, support, utility) in the trace.
- Retrieval decision (deviation, documented in the module docstring and evidence): use probabilities, p_ret = exp(lp[Retrieval]) / (exp(lp[Retrieval]) + exp(lp[No Retrieval])) > threshold (paper semantics), not the official code's ratio of raw logprobs (a quirk listed in 13). Read at position 0 of the no-retrieval generation, as the official code does. If both retrieval tokens are missing from position 0's top 20, the decision is `undetermined_topk` and falls back to the official no-threshold rule: retrieve iff `[Retrieval]` appears as a generated token; record which rule was used.
- Defaults (official README runs): threshold 0.2, w_rel 1.0, w_sup 1.0, w_use 1.0 (CLI default), use_seqscore True (adds exp(mean token logprob)), k (ndocs) 5, max_new_tokens 100 for the evidence passes; cite README lines from the evidence file. Evidence prompt: base prompt + `[Retrieval]<paragraph>{title}\n{text}</paragraph>` (title = document title or empty), one passage per call.
- Relevance read at position 0 of each evidence generation; support and utility at the first generated position whose token is in that group, as in the official code; ground and utility scores are 0.0 when that group never appears (official behaviour), recorded as `absent` in the trace.
- Languages: `SelfRagConfig.supported_languages=("en",)`; a question with any Arabic-script code point (U+0600-U+06FF) runs anyway and the trace gets `language_outside_model: true`.
- Live test also, per question: compare position-0 top-20 between `top_k=1` and `top_k=0` and print `pre_sampler_check=equal|different` (condition e). It must print, per question, the number of scored positions and how many had none of their group's tokens in the top 20 (condition d). Asserts stay structural.
- Evidence file: the blocked rules from 13 section 6 (d) and (e) are applied by the orchestrator to the printed numbers: R31 is `blocked` if reflection tokens are not literal text, if more than 20% of scored positions lack all of their group's tokens in the top 20, or if `pre_sampler_check` is `different`.
- `RunError` codes: add any of `selfrag_tokens_missing`, `selfrag_logprobs_unavailable`, `selfrag_output_invalid` that are not already in `errors.py` (check lines 230-252), with tests in `tests/domain/test_p75_errors.py` if that file lists P7.5 codes.
