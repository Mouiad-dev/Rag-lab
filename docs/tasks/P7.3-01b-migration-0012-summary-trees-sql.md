## Goal
PostgreSQL stores summary trees. Keys and triggers enforce tenant/project/index-version scope on every row, leaf provenance against chunk text, a single parent per node and immutability. `SqlIndexRepository` implements `SummaryTreeStore` and passes `TREE_STORE_CHECKS`.

## Change
- Create `.../versions/0012_summary_trees.py` (revision `0012_summary_trees`, down `0011_entity_graphs`), raw SQL as in 0011; every table carries `tenant_id, project_id, index_version_id, tree_key`, and every child FK carries all four.
  - `summary_trees(technique_id, embedding_key, embedding_dim smallint, generator_json, created_at)`: PK `(index_version_id, tree_key)`; `UNIQUE (tree_key)`; scope unique; FK to `index_versions`; checks key `^[0-9a-f]{64}$`, technique `^R[0-9]{2}$`, dim 1-8192, generator length <= 8000; ready-only insert trigger.
  - `tree_nodes(node_id varchar(20), level smallint, kind varchar(8), text, synthetic bool, embedding double precision[], chunk_id uuid null, extraction_view_id uuid null, start_cp int null, end_cp int null)`: PK `(index_version_id, tree_key, node_id)`; scope FK to `summary_trees`; FKs `(tenant, project, version, chunk_id)` to `chunks` and `(..., extraction_view_id)` to `index_version_views`; checks: id pattern, level 0-8, kind in (leaf, summary); leaf iff chunk/view/offsets not null and `level = 0` and not synthetic; summary iff they are null, `level >= 1`, synthetic, `char_length(text)` 1-4000; `UNIQUE (tenant, project, version, tree_key, chunk_id)` (a chunk is at most one leaf).
  - Trigger `tree_nodes_validate_insert`: embedding length equals the tree's `embedding_dim`; for leaves, view equals the chunk's view, offsets inside the chunk, `text = substr(chunk.text, start_cp - chunk.start + 1, end_cp - start_cp)` (real 0003 column names, as 0011 does).
  - `tree_edges(parent_id, child_id)`: PK `(index_version_id, tree_key, child_id)` (one parent); both FK to `tree_nodes` with scope; trigger: parent is a summary and its level is greater than the child's.
  - Scope indexes; no-update triggers on all three tables reuse `reject_index_update()`. Downgrade drops 0012 objects only, never `reject_index_update()`.
- `index_repository.py`: `add_summary_tree` / `get_summary_tree` matching the in-memory order and codes (early key lookup -> `tree_exists`; spans checked before insert; tree, nodes, edges in one transaction; unique violation -> `tree_exists`); `get` filters by scope and version and rebuilds a sorted `SummaryTree`.
- Tests: add `TREE_STORE_CHECKS` to the parametrized SQL checks; new `test_tree_database_guards` (direct SQL, one case each: cross-tenant chunk FK, leaf quote mismatch, leaf offsets outside chunk, wrong view, wrong embedding length, leaf with null chunk, summary with chunk, second parent, child level >= parent, UPDATE on each table, not-ready version, downgrade to 0011 and upgrade again with `reject_index_update()` intact). `test_sql_uow_db.py`: exercised `add_summary_tree` call.
- TRUNCATE lists: add `tree_edges, tree_nodes, summary_trees` before `graph_spans` in each TRUNCATE string of: `tests/storage/test_sql_index_repository.py`, `test_sql_repository.py`, `test_sql_extraction_repository.py`, `tests/indexing/test_fts_db.py`, `test_index_db.py`, `test_sparse_db.py`, `tests/live/test_answer_live.py`, `test_index_live.py`, `tests/api/test_anchors_db.py` (only files whose TRUNCATE lists `graph_spans`).
