## Goal
PostgreSQL stores R50/R51 cache entries. Scope is on every row, rows are never updated, removal happens only by explicit invalidation, delete or expiry purge, and a reverse index links entries to source document versions. `SqlResponseCacheStore` implements the domain `ResponseCacheStore` port and passes `RESPONSE_CACHE_STORE_CHECKS` unchanged. No question text is stored.

## Change
- Create `.../versions/0014_response_cache.py` (revision `0014_response_cache`, down `0013_knowledge_graphs`), raw SQL:
  - `response_cache_entries(tenant_id, project_id, key char(64), partition char(64), response_json text, source_run_id varchar(64), created_at timestamptz, expires_at timestamptz, features_json text null, question_vector vector null, vector_key varchar(200) null)`: PK `(tenant_id, project_id, key)`; FK `(tenant_id, project_id)` to `projects`; checks: key and partition `^[0-9a-f]{64}$`, `expires_at > created_at`, response_json 1..200000 chars, features_json <= 4000, vector and vector_key both null or both set. Index `(tenant_id, project_id, partition, vector_key)` and `(tenant_id, project_id, expires_at)`. `question_vector` uses pgvector `vector` without a fixed dimension (no ANN index; exact scan inside one partition).
  - `response_cache_sources(tenant_id, project_id, key, document_version_id)`: PK all four; FK `(tenant_id, project_id, key)` to entries `ON DELETE CASCADE`; index `(tenant_id, project_id, document_version_id)`; insert trigger rejects a `document_version_id` that has no `document_versions` row with the same tenant and project.
  - No-update triggers on both tables (reuse `reject_index_update()` or an equivalent); downgrade drops 0014 objects only.
- Create `packages/storage/src/rag_foundry_storage/sql/response_cache_store.py`: `SqlResponseCacheStore(database)` implementing the port with the in-memory semantics and codes: `put` inserts entry and sources in one transaction (unique violation -> `cache_exists`; scope mismatch -> `cache_scope_mismatch`); `get` filters by caller scope; `similar` uses `<=>` cosine distance filtered by scope, partition, vector_key, ordered, `LIMIT k`, similarity = 1 - distance; `invalidate_sources`, `invalidate_partition`, `delete`, `purge_expired` are scoped DELETEs returning counts. Loads rebuild `CacheEntry` through its validating constructor; failure -> `CacheError("cache_entry_invalid")`. No logging of row content.
- Tests: `tests/storage/test_sql_response_cache_store.py` (`-m db`): run `RESPONSE_CACHE_STORE_CHECKS` on the SQL store; guard cases: UPDATE on each table rejected; source row for another tenant's document version rejected; cross-scope FK to entries rejected; bad key pattern; vector without vector_key; delete cascades sources; downgrade to 0013 and upgrade again. Add both tables to the TRUNCATE lists in the db test files that truncate `projects` or `document_versions` (list the files changed in the Result).
