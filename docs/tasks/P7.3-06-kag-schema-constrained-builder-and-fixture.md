## Goal
A builder makes one chat call per chunk, giving the model the declared schema, keeps only facts that are grounded (verbatim unique quote, names and literal inside it) and schema-valid, and writes one `KnowledgeGraph` through `KnowledgeGraphStore.add_knowledge_graph`. Every rejection is reported with a reason; conflicts are reported, not resolved.

## Change
- Create `packages/indexing/src/rag_foundry_indexing/kag_extract.py`:
  - `R48_EXTRACT_SYSTEM_V1` + SHA (untrusted-JSON wording). User JSON: `{"schema": <types and predicates>, "chunk": text}`. Reply: `{"entities":[{"name","type","quote"}],"facts":[{"subject","predicate","object"|"value","quote"}]}`.
  - `KagExtractConfig(extra="forbid")`: `max_chunks` (200, at most 2000), `max_entities_per_chunk` (10, at most 30), `max_facts_per_chunk` (15, at most 40), `max_output_tokens`, `temperature=0.0`, `on_invalid: fail|skip`.
  - `KagGraphBuilder(config, *, scope, index_version, index, source, chat, knowledge_schema)`; `kg_key()` over `{index_version_id, technique_id "R48", builder_version "1", prompt_sha256, schema_sha256, chat_provider, chat_model, config}`; `build() -> KagBuildReport(kg_key, chunks_processed, chat_calls, entities, facts, rejected: tuple[(chunk_id, item_index, item_kind, reason)], conflicts, usage)`.
  - Order: version ready, chunk cap, `check_chat`, existing key -> `kag_exists`; then all chat calls; then build, validate and write once. Chunk text differing from the view slice raises `kag_source_mismatch`; totals above the model caps raise `kag_too_large`.
  - Item rejection reasons: `quote_not_found`, `ambiguous_quote`, `name_not_in_quote`, `value_not_in_quote`, `unknown_type`, `unknown_predicate`, `range_violation`, `bad_literal`, `unknown_subject` / `unknown_object` (not kept from the same chunk), `too_many_items`, `too_many_spans`.
  - Literals: `year`/`int` values must appear in the quote as ASCII digits; no digit normalization (Arabic-Indic digits give `value_not_in_quote`; a recorded limit).
  - Same-ID entities and identical facts merge evidence in chunk order. Whole-reply invalid JSON or shape follows `on_invalid` (`kag_invalid` on `fail`); usage always kept.
- Export the names from `__init__.py`. Grounding logic is duplicated from `graph_extract.py` on purpose; sharing it is a later refactor.
- Create `tests/indexing/_kag_fixture.py` (used by 07-10). `SCHEMA` = the P7.3-05 schema. Single-sentence paragraphs joined by `"\n\n"`, one chunk each, with `LABELS` (`K0..Kn`). Follow the P7.2-05 paragraph-length rule (every filler at least as long as the longest fact paragraph, and no adjacent pair short enough to merge) so 08b can chunk one per paragraph with `RecursiveChunker`:
  - "Lina Haddad founded Cedar Labs in 2019."; "Cedar Labs supplies tide sensors to the Harbor Authority."; "Omar Nasser leads the Harbor Authority."; "Delta Works, founded in 2010, also supplies the Harbor Authority.";
  - conflict entity used by no count/multi-hop question: "Blue Reef was founded in 2012." and "Blue Reef was founded in 2014.";
  - extraction misses (scripted replies rejected): "Nour Saleh leads Delta Works." (`quote_not_found`) and "Gulf Marine also supplies the Harbor Authority." (fact rejected as `name_not_in_quote`);
  - one Arabic paragraph (`\uXXXX`) with an organization and a founding year in ASCII digits; filler paragraphs with no entity.
  - `KAG_REPLIES` keyed by chunk text (covering every reason except `too_many_spans`), `R38_REPLIES` for the same text (used by 08), `QUESTIONS` and gold spans, async `build_fixture_kg()`.
- Create `tests/indexing/test_kag_extract.py`: happy path incl. Arabic; each rejection reason; a separate synthetic test for `too_many_spans` (51 mentions over many small chunks, or caps monkeypatched as P7.2-04 did); the Blue Reef conflict is in `report.conflicts` with both facts kept; mutual index from a chunk to its facts; stored graph equals loaded graph; an existing key raises before any chat call; the key changes with schema, model and config; `fail` and `skip` on an invalid reply; an injected instruction stays inside the user JSON; `len(usage) == chat_calls == chunks`.
