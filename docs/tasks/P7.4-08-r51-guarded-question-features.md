## Goal
A deterministic extractor turns a question into the meaning-bearing features a semantic hit must preserve exactly: numbers, years, negation, comparatives, identifiers, quoted strings and script. Two questions are eligible for reuse only if their features are equal. Features (not the question) are what a cache entry stores, so they serialize to canonical JSON. Known limits are written down.

## Change
Arabic words are given as Unicode code points (U+XXXX). In Python write each as a backslash-u escape (U+0644 U+0627 -> backslash `u0644` backslash `u0627`); files stay ASCII.
- Create `packages/cache/src/rag_foundry_cache/features.py`:
  - `QuestionFeatures` (frozen, extra forbidden): `numbers: tuple[str, ...]` (canonical decimal strings; ASCII, Arabic-Indic U+0660-U+0669 and Extended U+06F0-U+06F9 digits map to the same value; `2,000` equals `2000`; sorted multiset), `negation: int`, `comparatives: tuple[str, ...]` (tags `before`, `after`, `more`, `less`, `at_least`, `at_most`, `except`), `identifiers: tuple[str, ...]` (tokens mixing letters and digits, e.g. `INV-2041`, `R2D2`; case kept), `quoted: tuple[str, ...]`, `script: Literal["latin","arabic","mixed","other"]`. `to_json()` (canonical) and `from_json()` (invalid -> `CacheError("cache_entry_invalid")`). Stored form (orchestrator edit 2026-11-23, P7.4-06 review; owner rule "no question text at rest"): `to_json()` writes `numbers`, `identifiers` and `quoted` as sorted SHA-256 hex digests of their canonical (NFC) values, never the raw strings; `negation`, `comparatives` and `script` stay plain. `eligible` compares the hashed forms (equality is all it needs), so it gives the same result for raw and stored features. Test: no identifier, quoted string or number from the question appears in `to_json()`; `eligible` agrees before and after a JSON round trip.
  - EN negation: `not`, `no`, `never`, `without`, `none`, `nobody`, `neither`, `nor`, words ending in `n't`. AR negation: U+0644 U+0627; U+0644 U+064A U+0633 and U+0644 U+064A U+0633 U+062A; U+0644 U+0645; U+0644 U+0646; U+063A U+064A U+0631; U+0628 U+062F U+0648 U+0646; each also with a leading U+0648 or U+0641.
  - EN comparatives: `before`, `after`, `more`, `less`, `fewer`, `at least`, `at most`, `except`, `over`, `under`. AR: U+0642 U+0628 U+0644 before; U+0628 U+0639 U+062F after; U+0623 U+0643 U+062B U+0631 more; U+0623 U+0642 U+0644 less; U+0628 U+0627 U+0633 U+062A U+062B U+0646 U+0627 U+0621 except.
  - `features(question)`; `eligible(a, b) -> tuple[bool, tuple[str, ...]]` (differing feature names).
  - Module docstring, known limits: U+0645 U+0627 is not negation (it also means "what"); entity names without digits are not features; spelled-out numbers ("two", U+0627 U+062B U+0646 U+0627 U+0646) are not parsed; month names (EN "March" vs "May", AR month names) and units ("km" vs "miles", "USD" vs "EUR") are not features; no stemming. Each limit means a possible false hit that only the threshold, margin and revalidation can stop.
- Create `tests/cache/test_features.py`:
  - eligible: EN word-order paraphrase; the same number in ASCII and Arabic-Indic digits;
  - not eligible, with the named feature: 2025 vs 2026; "with" vs "without"; "is" vs "isn't"; an AR question with and without U+0644 U+0627 before the verb; before vs after (EN and AR); `INV-2041` vs `INV-2014`; `"blue"` vs `"red"`; Latin vs Arabic script;
  - documented limits stay eligible (asserted, commented as known false-hit risks): "in March" vs "in May"; "10 km" vs "10 miles";
  - `2,000`, `2000` and Arabic-Indic 2000 equal; JSON round trip; deterministic; whitespace-only input gives empty features.
