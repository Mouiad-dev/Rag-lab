## Goal
A chunk built by a parent-linked chunker (C18) stores its parent's code-point span `(parent_start_cp, parent_end_cp)`. Inspection shows the parent anchors and R02/R03 hits carry the pair. Chunks from other chunkers (C05 and the rest) keep both values null. The parent id is never stored: it is `parent_id_for(canonical_text, parent_start, parent_end)` from `hierarchy.py`.

## Change
- Create `docs/decisions/ADR-0016-chunk-parent-spans.md` (short: context, decision, consequences) and add its row to `docs/decisions/README.md`. Decision: store nullable offsets only. The id is derived with the existing `parent_id_for`; no third id format. Parents are chunk-level references, not source anchors. Query-time parent return stays R22/R25 (P6.2).
- `kinds.py`: frozen `ParentedSpan(ChunkSpan)` with `parent_start: int | None = None`, `parent_end: int | None = None` and a validator: both None, or `0 <= parent_start <= start < end <= parent_end`. `@runtime_checkable class ParentLinkedChunker(Protocol)` with `def chunk_with_parents(self, doc: ChunkInput) -> tuple[ParentedSpan, ...]`. `RetrievedChunk`: add `parent_start: int | None = None`, `parent_end: int | None = None`. Export both new names in `rag_foundry_techniques/__init__.py`.
- `hierarchy.py`: `ParentChildChunker.chunk_with_parents(doc)` returns one `ParentedSpan` per child, in the same order as `chunk()`, with its parent's span.
- `domain/indexing.py`: `NewChunk` and `ChunkRecord` gain `parent_start_cp: int | None = None`, `parent_end_cp: int | None = None` with the same pair rule (reuse one helper). `index_testing.py`: the in-memory repo keeps the pair. Add `async def check_parent_spans(factory)` (null pair and set pair round-trip through `add_chunks` -> `list_chunks` and `search`) and call it from `check_index_repository`.
- Create `.../migrations/versions/0007_chunk_parent_spans.py` (down_revision = 0006's id): add two nullable integer columns to `chunks`, plus raw-SQL `CHECK` named `ck_chunks_parent_span`: `(parent_start_cp IS NULL AND parent_end_cp IS NULL) OR (0 <= parent_start_cp AND parent_start_cp <= start_cp AND start_cp < end_cp AND end_cp <= parent_end_cp)` (use the real column names from 0003). The downgrade drops the constraint, then the columns. If the 0003 validate trigger lists columns, check it still accepts the new ones.
- `sql/index_repository.py`: write and read the pair in `add_chunks`, `_chunk`, `list_chunks`, `search`.
- `indexing/service.py`: compute `linked = isinstance(chunker, ParentLinkedChunker)` once per build. If linked, use `chunk_with_parents`, else `chunk`. Before saving, check `parent_end <= len(payload.canonical_text)` and raise `IndexingError` if not (use an existing code or add one to the domain error registry). `ChunkInspection` gains `parent_anchors: tuple[SourceAnchor, ...] = ()`, from `anchors_for_span(scope, view, parent_start_cp, parent_end_cp)` when the pair is set.
- `retrievers.py` (R02) and `bm25.py` (R03): copy `parent_start_cp/parent_end_cp` into `RetrievedChunk.parent_start/parent_end`. Nothing else changes.
