## Change
- Edit ADR-0001 Evidence: add "Verified 2026-11-xx (P2.4-01), OpenAI-compatible endpoints" answering, with links:
  1. Chat Completions: request fields we send (`model`, `messages` roles, `max_tokens` vs `max_completion_tokens`, `temperature`, `stream`, `stream_options.include_usage`); response `choices[].message.content`, `finish_reason` values; `usage` fields (`prompt_tokens`, `completion_tokens`, cached-token details). SSE format: `data:` lines, `[DONE]` sentinel, where usage arrives when streaming, error shape mid-stream.
  2. Embeddings: request (`input` list, `model`, `encoding_format`), response (`data[].embedding`, `data[].index` order), `usage.prompt_tokens`.
  3. Errors: status codes, body shape `{"error": {...}}`, request-id header name. Auth header (`Authorization: Bearer`).
  4. LM Studio and vLLM, each: default base URL and port, which of 1–3 they support (chat, stream, stream usage, embeddings), whether an API key is required or optional, tool-calling support and how it is enabled (for example vLLM `--enable-auto-tool-choice`). Note that vLLM's default port 8000 collides with our API port.
  5. Moonshot: base URL (international and China endpoints, which one we use), auth, current Kimi K-series model IDs copied verbatim (the ADR "km3" assumption: confirm or refute), context window, tool-calling and JSON-mode support, whether an embeddings endpoint exists, prices in USD (or CNY, stated as such) per MTok for input, cache hit and output, and any minimum top-up.
  6. LiteLLM: latest stable version and date, any advisory since the P2.3 block, whether `1.106.6` is still outside every affected range and is now (or when it becomes) 2 weeks old.
