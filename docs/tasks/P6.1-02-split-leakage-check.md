## Goal
A deterministic check that reports leakage between the dev, validation and held_out splits, using an exact rule. Error findings block a run (P6.1-04). Warnings are reported only.

## Change
Create `src/rag_foundry_evaluation/leakage.py`.

**Normalization and tokens**
- `normalize_question(text) -> str`, in this order:
  1. NFC
  2. casefold
  3. NFD
  4. drop every char whose `unicodedata.category` is `Mn` (Arabic harakat, Latin accents)
  5. drop U+0640 (tatweel)
  6. NFC
  7. `" ".join(s.split())`
- `question_tokens(text) -> frozenset[str]`: `re.findall(r"[^\W_]+", normalize_question(text))`.
- `jaccard(a, b)`: `len(a & b) / len(a | b)`. If either set is empty, return `0.0`.

**Models**
- `LeakageFinding` (frozen, `extra="forbid"`):
  - `rule: Literal["exact_question","near_duplicate_question","shared_relevant_span"]`
  - `severity: Literal["error","warning"]`
  - `case_a`, `case_b` (with `case_a < case_b` by string order), `split_a`, `split_b`
  - `value: float | None` (Jaccard rounded to 6 places, or None)
- `LeakageReport`: `jaccard_threshold`, `pairs_checked: int`, `findings: tuple[LeakageFinding, ...]` sorted by `(rule, case_a, case_b)`, and an `errors` property.

**`check_leakage(dataset, *, jaccard_threshold=0.8) -> LeakageReport`**
- Only consider pairs in different splits. `pairs_checked` is the number of such unordered pairs.
- Rule 1, `exact_question` (error): the normalized questions are equal. Then emit no near-duplicate finding for that pair.
- Rule 2, `near_duplicate_question` (error): `jaccard >= jaccard_threshold`.
- Rule 3, `shared_relevant_span` (warning, value None): some span pair is on the same `doc_key` and `max(starts) < min(ends)`. Touching spans do not count.
- The threshold must satisfy `0 < t <= 1`. Otherwise raise `EvaluationError("invalid_threshold")`.

**`raise_on_errors(report)`**
- Raise `EvaluationError("leakage", "<rule> <case_a> <case_b>")` for the first error.
- If there are only warnings, do not raise.

Export the new names.

## Tests (`tests/evaluation/test_leakage.py`)
Expected values below are hand-computed:
- Dev `"one two three four five six seven eight nine"` and validation `"one two three four five six seven eight ten"`: intersection 8, union 10, so one `near_duplicate_question` error with value `0.8`.
- Same pair, both in dev: no findings, `pairs_checked == 0`.
- Dev Q1 and validation `"one two three four five six seven ten eleven"`: intersection 7, union 11, so no finding (0.636364).
- Arabic, dev `"المخزن"` and held_out `"المَخْزَن"`: one `exact_question` error and no near-duplicate finding for that pair.
- `"What Is X?"` and `"what is x"` in different splits: not exact (`?` stays), so `near_duplicate_question` with value `1.0`.
- Spans on doc `d`: dev `[0,10)` and validation `[5,20)` give a `shared_relevant_span` warning. `[0,10)` and `[10,20)` give nothing.
- 2 dev, 1 validation and 1 held_out case: `pairs_checked == 5`.
- `raise_on_errors`: code `leakage` on an error report. Returns None on a warning-only report.
- Threshold `0` or `1.5` raises `invalid_threshold`.
- Write the Arabic test strings exactly as the `\u` escapes above, never as literal Arabic characters. The diacritic test only works if the combining marks (U+064E, U+0652) survive; check the diff.
