## Goal
R37 is a `retriever` plugin (adaptation) with the paper's two modes: collapsed tree and tree traversal. Summary nodes route the search; hits are always original leaf chunks reached through lineage, never summary text (owner decision 2026-11-22: summaries are not answer context). On the fixture it is compared at an equal 3-hit budget with a flat summary index (`max_levels=1`, catalogue acceptance) and R02 dense, including a losing case. This closes "leaf lineage preserved".

## Change
- Create `packages/indexing/src/rag_foundry_indexing/raptor_retrieve.py`:
  - `RaptorConfig(extra="forbid")`: `mode: collapsed|traversal` (collapsed), `top_nodes` (5, 1-20), `leaves_per_node` (1, 1-10), `beam` (2, 1-10), `max_hits` (10, 1-50).
  - `RaptorRetriever`: manifest `R37`, `RETRIEVER`, `1.0.0`, `Fidelity.ADAPTATION`; constructor `(config, *, scope, tree, index, index_version, embedder)` calls `tree.check_scope` and the embedder key check; the version must be `ready`.
  - `retrieve(q)` embeds the query once; cosine against node embeddings; ties broken by the node's first lineage span `(start, end)`, then `node_id` (same rule as 02, so results never depend on random IDs):
    - collapsed: rank all nodes (all levels); take `top_nodes`; a leaf adds itself; a summary adds its `leaves_per_node` best leaves (query cosine) from its lineage;
    - traversal: start at `roots()`, keep the `beam` best children per level down to leaves.
  - Hits: original `ChunkRecord`s (loaded once, as in R38), deduplicated, in selection order, cut to `max_hits`; a lineage chunk missing from the version raises `tree_source_mismatch`. `scoring="raptor-tree"`; components `node_level`, `node_similarity`, `leaf_similarity`.
  - `last_trace = RaptorTrace(mode, selected_nodes: tuple[(node_id, level, similarity, synthetic)], hit_lineage: tuple[(chunk_id, via_node_id)])`.
- Register in `retrievers.py`; export names. If a test counts built-ins (`tests/techniques/test_builtin_kinds.py`), update only that count.
- Create `tests/indexing/test_raptor_retrieve.py`. All arms use a 3-hit budget: R37 collapsed and flat with `max_hits=3`, R37 traversal with `max_hits=3`, R02 with `k=3`. Each comparison prints `recall (hits=n)` per arm.
  - **Lineage:** every hit's span is inside the lineage of its `via_node_id`; hit text equals the view slice; no hit text equals any summary text.
  - **Q_BUDGET (diversity):** R37 collapsed and flat cover one budget paragraph per topic (recall 1.0); R02 picks both harbor paragraphs and misses one topic.
  - **Q_OVERVIEW (full vs flat):** report recall for full tree, flat, traversal and R02; assert the values produced; a comment explains whether the root helps. No direction required.
  - **Losing case Q_DETAIL:** traversal `beam=1` descends into the wrong branch because the clinic summary omits the detail (recall 0); R02 finds it.
  - **Guards:** stranger scope, another version's tree, wrong embedder, not-ready version raise; `check_plugin_contract` passes; `Q_ARABIC` reaches the Arabic leaf in collapsed mode.
