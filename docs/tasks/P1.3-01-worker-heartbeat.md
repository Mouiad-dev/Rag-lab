## Goal
The worker can prove it is alive inside a container. `rag-foundry-worker --heartbeat-file PATH` touches PATH at start and on every loop iteration. `rag-foundry-worker --check-heartbeat PATH` exits 0 if PATH is fresh and 1 otherwise. Compose (P1.3-03) uses this as the worker healthcheck. The image has no curl or procps.

## Read only these files
- `apps/worker/src/rag_foundry_worker/main.py` (current argparse and loop)
- `packages/core/src/rag_foundry_core/settings.py` (`worker_poll_seconds`, `load_settings`)
- `tests/worker/test_main.py` (existing test style)

## Change
- Edit `apps/worker/src/rag_foundry_worker/main.py`:
  - Add `--heartbeat-file PATH` (optional). If given, write the file (`Path.touch()` or a short write that updates mtime) after settings load. In the loop, write it again after each `time.sleep`. With `--once`, write it once, then return 0.
  - Add `--check-heartbeat PATH`. It loads settings and returns 0 if PATH exists and `time.time() - mtime <= 3 * worker_poll_seconds + 5`. Otherwise it returns 1. It must not start the loop or log `worker started`. Make it mutually exclusive with `--once` and `--heartbeat-file` (argparse group).
  - Keep the helpers small and pure where possible, for example `is_fresh(path, max_age, now)`.
- Edit `tests/worker/test_main.py`: add tests for
  - `--once --heartbeat-file` creates the file.
  - `--check-heartbeat` returns 0 for a fresh file, 1 for a missing file, and 1 for a stale file (set with `os.utime` to an old time).
  - The loop writes the heartbeat. Monkeypatch `time.sleep` so the first call returns and the second raises `KeyboardInterrupt`. Assert the exit code is 0 and the mtime was updated.

## Constraints
- Add no new settings field. The path is a CLI argument, so `Settings` and `extra="forbid"` stay unchanged.
- Use the standard library only, with no new dependencies. The worker does not import FastAPI.
- Never log file contents, environment variables or settings values beyond what already exists.
- Existing behavior (`--once` with no heartbeat, exit codes, the `worker started env=` log) stays unchanged.
