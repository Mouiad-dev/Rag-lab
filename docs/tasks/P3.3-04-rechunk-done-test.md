## Goal
An offline test proves the P3.3 done criterion: anchors created over one view resolve to the exact quote from either of two different chunkings, and stale anchors fail explicitly. No chunker exists yet (C05 is P3.4), so the chunkings are two synthetic span sets in the test.

## Change
- `tests/ingestion/test_anchor_rechunk.py` only. Document: Markdown with a heading, an English paragraph, an Arabic paragraph with harakat and tatweel, a mixed paragraph with a non-BMP emoji, and the same paragraph twice (all as escapes).
  - Chunking A: windows of 40 code points, overlap 10, over canonical text. Chunking B: per block, split at the block midpoint. Both are plain `(start, end)` lists. Assert the boundary sets of A and B differ.
  - Three fact quotes (Arabic, emoji, second copy of the repeated paragraph) with hand-computed block-relative ranges; anchors via `AnchorService.anchor`.
  - For A and B: `anchors_for_span` per chunk; serialize every anchor to JSON. Resolve with a fresh `AnchorService` instance (new object, same store and repos) after reloading the JSON. Assert: every result is `exact`; joined texts per chunk equal the chunk text minus inter-block gaps; for each fact anchor, the union of A's chunk-anchor ranges in the same block covers the fact range, and the same holds for B; the fact anchor resolves to the same quote and block_id whichever set was built first.
  - Anchor JSON keys equal the `SourceAnchor` field set (no chunk or index ID). Fact anchors are byte-identical when created before and after building A and B.
  - Repeated paragraph: the fact anchor resolves to the second block's `block_id`, not the first.
  - Stale cases:
    - `exact` changed by one code point -> `mismatch/quote_mismatch`.
    - v2 upload where one code point inside the fact's range is replaced by another (same length, same block ordinal), then extracted: the v1 anchor still resolves `exact` against the v1 view; the same anchor with `source` switched to the v2 IDs -> `mismatch/quote_mismatch` (never relocated).
    - v3 upload changing one code point only in the prefix context before the fact (quote unchanged), same block ordinal: anchor switched to v3 IDs -> `mismatch/prefix_mismatch`.
    - Range past block end -> `range_out_of_bounds`; another tenant -> `unavailable/not_found`.
  - PDF (skip if the `pdf` extra is missing): anchor on page 2 text has `page_index` 1, `regions == ()`, `precision == exact_text`.
