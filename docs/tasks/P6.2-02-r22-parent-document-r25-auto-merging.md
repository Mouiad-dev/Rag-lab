## Goal
- **R22** returns the stored C18 parent span of each child hit.
- **R25** replaces retrieved children with their parent only by a stated ratio rule.

Both reuse the P6.2-01 core, so scope, the index version and exact spans are rechecked. Both have explicit size budgets.

## Change
- Edit `tests/indexing/_inmemory_index.py`: `ready_index` also accepts 5-tuples `(start, end, text, parent_start, parent_end)`. They map to `parent_start_cp/parent_end_cp`. Existing 3-tuple callers are unchanged.
- Create `parent_document.py`, R22, `CONTEXT_BUILDER`, 1.0.0, ADAPTATION. `ParentDocumentConfig`:
  - `max_parent_chars` 4000 (20..20000), `max_total_chars` 8000 (20..100000), `max_seeds` 20 (1..50);
  - `on_missing_parent`: `"error"` (default) or `"keep_child"`.
- `ParentDocumentExpander(config, *, scope, index_version, index, source)`, with `async expand(result)`. Result: `technique_id="R22"`, `scoring="parent-document"`.
- R22 rule:
  - Each hit is replaced by `[parent_start, parent_end)`. Children of the same parent become one output at the best child's rank.
  - A parent longer than `max_parent_chars` keeps the child (flag `parent_too_large`).
  - A hit without a parent raises `parent_unavailable`, or with `keep_child` stays as is (flag `no_parent`).
  - `parent_end > len(text)` -> `expansion_source_mismatch`.
  - After this, outputs go through the core `merge_overlapping` and then the budget.
- Create `auto_merge.py`, R25, `CONTEXT_BUILDER`, 1.0.0, ADAPTATION (two levels only, from C18). `AutoMergeConfig`:
  - `merge_ratio` 0.5 (>0, <=1), `min_children` 2 (1..10);
  - `max_parent_chars`, `max_total_chars` and `max_seeds` as in R22;
  - `max_index_chunks` 5000 (1..20000).
- `AutoMergingExpander(config, *, scope, index_version, index, source)`. Result: `technique_id="R25"`, `scoring="auto-merge"`.
  - **Child counts.** Use the version **returned by `load_sources`**, not the constructor argument. If its `chunk_count > max_index_chunks`, raise `auto_merge_index_too_large` before listing. Otherwise list all chunks in pages of 500 and count children per `(view, parent_start_cp, parent_end_cp)`. Cache the counts on the instance, keyed by the version id.
  - **Merge rule** (stated in the docstring). For a parent with m retrieved children out of n total, merge if and only if `m / n >= merge_ratio` and `m >= min_children` and the parent length is <= `max_parent_chars`.
  - **Merged output.** It goes at the best child's rank, has seeds = those children, and is flagged `merged:m/n`.
  - **Unmerged children.** They keep their own span and chunk_id and are flagged `not_merged:m/n`. Hits without a parent pass through unchanged.
- Register R22 and R25 in `retrievers.py`; export them in `__init__.py`.
- Create `tests/indexing/test_parent_document.py` and `test_auto_merge.py`. Fixture:
  - `T2 = "Alpha one. Beta two.\n\nGamma three. Delta four."` (len 46);
  - children c1 [0,10) and c2 [11,20) with parent [0,20); c3 [22,34) and c4 [35,46) with parent [22,46);
  - input order c2 r1 (score 0.9), c3 r2 (0.8), c1 r3 (0.7).
- R22 expected:
  1. [0,20) `"Alpha one. Beta two."` r1 with seeds (c2, c1), score 0.9; [22,46) `"Gamma three. Delta four."` r2. `input_chars` 31, `output_chars` 44.
  2. With `max_parent_chars=20`: second hit is c3 [22,34), same chunk_id, flag `parent_too_large`; `output_chars` 32.
  3. With `max_total_chars=30`: one hit; `dropped_for_budget == (c3,)`.
  4. A hit without a parent raises `parent_unavailable`; with `keep_child` it is kept with flag `no_parent`.
  5. Arabic: TA from P6.2-01 (escapes) as parent [0,25), with children [0,7) [8,16) [17,25). Seed [8,16) -> hit text == TA, start 0, end 25.
  6. A stranger scope raises NotFoundError. A parent end of 47 on T2 raises `expansion_source_mismatch`.

  2. With `min_children=1`: r2 [22,46) flag `merged:1/2`; `output_chars` 44.
  3. With `merge_ratio=0.75, min_children=1`: r2 stays c3.
  4. With `max_index_chunks=3`: `auto_merge_index_too_large`, and `list_chunks` is never called (use a spy wrapper).
