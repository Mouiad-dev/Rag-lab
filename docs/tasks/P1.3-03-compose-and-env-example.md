## Goal
`compose.yaml` defines `db` (Postgres + pgvector), `api` and `worker`, plus `ollama` under profile `ollama` only. Each service has a healthcheck. Published ports bind `127.0.0.1` only. `.env.example` contains placeholders only. Tests check both files without pulling images.

## Read only these files
- `packages/core/src/rag_foundry_core/settings.py` (valid `RAG_FOUNDRY_*` keys; unknown ones crash `load_settings()`)
- `Dockerfile` (from P1.3-02)
- `apps/worker/src/rag_foundry_worker/main.py` (`--heartbeat-file`, `--check-heartbeat` from P1.3-01)
- `.gitignore` (`.env` is ignored, `.env.example` is tracked)
- Compose spec (docs.docker.com/reference/compose-file/services): `healthcheck`, `depends_on.condition`, `profiles`, `init`, `read_only`, `tmpfs`, `cap_drop`, `security_opt`
- Docker Hub `pgvector/pgvector` and `ollama/ollama` tag lists (check that the exact tags exist; do not pull them)

## Change
- Create `compose.yaml` (no top-level `version:`):
  - `db`: `pgvector/pgvector:<pgvector x.y.z>-pg<major>[-<debian>]`. Prefer the newest pgvector release with a PostgreSQL 18 tag; otherwise use pg17. Set `POSTGRES_USER`, `POSTGRES_DB` and `POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?copy .env.example to .env and set it}`. Use named volume `pgdata`. For pg18 images the mount point is `/var/lib/postgresql`, not `/var/lib/postgresql/data`; check this in the image docs. Healthcheck: `pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}`. Do not publish a port. Set `security_opt: [no-new-privileges:true]`.
  - `api`: `build: .`, `image: rag-foundry-app:local`, `command: ["rag-foundry-api"]`. Set environment keys explicitly: `RAG_FOUNDRY_API_HOST: 0.0.0.0` (container-internal only), `RAG_FOUNDRY_API_PORT: "8000"`, `RAG_FOUNDRY_ENVIRONMENT: ${RAG_FOUNDRY_ENVIRONMENT:-dev}`, `RAG_FOUNDRY_LOG_LEVEL: ${RAG_FOUNDRY_LOG_LEVEL:-INFO}`. Ports: `"127.0.0.1:${API_HOST_PORT:-8000}:8000"`. Healthcheck: `python -c` with `urllib.request.urlopen("http://127.0.0.1:8000/health", timeout=3)`. Depends on `db: service_healthy`.
  - `worker`: same image, `command: ["rag-foundry-worker", "--heartbeat-file", "/tmp/worker.heartbeat"]`, with the same env keys except the API keys. Healthcheck: `["CMD", "rag-foundry-worker", "--check-heartbeat", "/tmp/worker.heartbeat"]`. Depends on `db: service_healthy`.
  - `api` and `worker` both get: `init: true`, `read_only: true`, `tmpfs: [/tmp]`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, no `env_file:` (only the explicit keys above reach containers) and no volumes.
  - `ollama`: `ollama/ollama:<exact x.y.z>`, `profiles: [ollama]`, named volume `ollama-models:/root/.ollama`, ports `"127.0.0.1:11434:11434"`, healthcheck `["CMD", "ollama", "list"]`. Do not add a model pull, `command:` override or init job. `api` and `worker` must not depend on it.
  - Give every healthcheck `interval`, `timeout`, `retries` and `start_period`.
- Create `.env.example` with comments stating that values are placeholders and the real `.env` is never committed. Keys: `POSTGRES_USER=rag_foundry`, `POSTGRES_DB=rag_foundry`, `POSTGRES_PASSWORD=change-me-local-only`, `API_HOST_PORT=8000`, `RAG_FOUNDRY_ENVIRONMENT=dev`, `RAG_FOUNDRY_LOG_LEVEL=INFO`. Add no provider keys.
- Create `tests/stack/test_env_example.py`:
  - Every `RAG_FOUNDRY_*` key is a field name in `Settings.model_fields`, and `Settings(**{k: v})` accepts it.
  - Every other key is in an allowlist (`POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD`, `API_HOST_PORT`).
  - Any key matching `PASSWORD|SECRET|TOKEN|KEY` has an empty value or one starting with `change-me`.
  - No value matches common secret shapes such as `sk-`, `ghp_`, `AKIA` or long base64 runs.
- Create `tests/stack/test_compose_config.py`. Skip if `shutil.which("docker")` is None or `docker compose version` fails. Run `docker compose --env-file .env.example [--profile ollama] config --format json` and assert:
  - Every published port has `host_ip == "127.0.0.1"`.
  - No volume has `type: bind`, and no source contains `docker.sock`.
  - Every service has a `healthcheck`.
  - Images have explicit, non-`latest` tags.
  - `ollama` is absent without the profile and present with it.
  - The environment keys of `api` and `worker` are a subset of known settings fields.

## Constraints
- Database URL settings are out of scope: nothing connects to Postgres until P3 (SQLAlchemy/Alembic). When a URL is added later it must be `SecretStr`.
- Do not use `CREATE EXTENSION`, init scripts or bind mounts. Do not hard-code a password in `compose.yaml`.
