## Goal
`ProviderCallError` carries a bounded `retry_after_s` parsed from `retry-after`, and quota 429s are classified as `billing` (not retryable), so the 03 retry wrapper can decide from typed fields only. Messages, str and repr stay unchanged.

## Change
- Edit `errors.py`:
  - `ProviderCallError.__init__(..., retry_after_s: float | None = None)`; stored as attribute; never in the message.
  - `RETRYABLE_REASONS: frozenset[ProviderCallReason]` = D3 set (`connection`, `rate_limited`, `overloaded`, `server_error`); `timeout` is decided by the wrapper (local only), so it is not in this set.
  - `parse_retry_after(value: object) -> float | None`: accepts only a str of ASCII digits (delta-seconds, at most 6 digits); returns float seconds; anything else (HTTP-date, negative, decimals, whitespace-padded junk, non-str) → None. HTTP-date support is out of scope.
- Edit `_anthropic_http.anthropic_status_error`: set `retry_after_s=parse_retry_after(headers.get("retry-after"))` when headers is given.
- Edit `_openai_http.openai_status_error`: same `retry_after_s`; for status 429, decode the body (catch `ValueError`, `RecursionError`) and compare `error.code` / `error.type` against fixed strings only: `insufficient_quota` or `exceeded_current_quota_error` → reason `billing`; `engine_overloaded_error` → `overloaded`; else stays `rate_limited`. Never copy any body string into the error.
- Create `tests/providers/test_retry_metadata.py`: parse_retry_after table (`"0"`, `"7"`, `"120"`, `"1234567"`→None, `"-1"`, `"1.5"`, `" 7"`, HTTP-date, `None`, int); 429 with/without header for both helpers; the three OpenAI/Moonshot bodies → `billing`/`billing`/`overloaded`; a body whose `message` holds a sentinel string never appears in `str`, `repr` or `args` of the error; `RETRYABLE_REASONS` contents.

## Constraints
- Errors are still raised without `__cause__`/`__context__` where they are today. No change to status→reason tables except the 429 body rule above. No retry logic here.
