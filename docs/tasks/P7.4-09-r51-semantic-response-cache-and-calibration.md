## Goal
`SemanticResponseCache` (R51, `cache` plugin) reuses an answer only inside the exact R50 partition, above a calibrated similarity threshold, with a margin over the runner-up, with equal guarded features, and after R50 revalidation. Calibration picks a threshold on a small dev split or reports that none qualifies; nothing is chosen silently.

## Change
- Create `packages/cache/src/rag_foundry_cache/semantic.py`:
  - `SemanticCacheConfig(threshold: float 0.5..1.0 (required, no default), margin: 0.0..0.5 = 0.05, k: 2..10 = 3, ttl_s as R50)`. Manifest `R51`, kind `cache`, version 1.0.0, fidelity `adaptation`.
  - `async run(scope, question, inputs, answer_fn, *, embedder, expected_index_version_id, anchors, gate, clock, run_id_factory) -> CachedRun`:
    - Same bypass rules as R50. Embed the question once through the `EmbeddingModel` port; the caller passes an embedder recorded on a separate cache ledger. `vector_key` = embedder profile id + model.
    - `store.similar` in the caller's scope and `partition_key` only; entries without `features_json` or a vector are not candidates. Miss reasons in order: `no_candidate`, `below_threshold`, `ambiguous` (top two >= threshold, within `margin`, different answers), `features_differ:<names>` (new question's features vs the candidate's stored `features_json`), then R50 revalidation reasons (`scope_mismatch` handled as in R50).
    - A miss runs `answer_fn` and stores as R50 does (same pins check), plus `features_json` and the vector. Never the question text. `features_json` is validated on write: it must come from `QuestionFeatures.to_json()` and round-trip through `from_json()` (else not stored, reason `not_cacheable_status`).
    - Hit: as R50, with `layer="R51"` and `similarity`.
  - `calibrate(pairs, vectors, thresholds) -> CalibrationReport` (pure): per threshold and split (`dev`, `held_out`) the paraphrase hit rate and adversarial false-hit rate, each with and without the feature guard, with numerators and denominators. `chosen_threshold` = lowest threshold with zero dev false hits after the guard and at least one dev paraphrase hit; if none, `chosen_threshold=None` and `reason="no_threshold_without_dev_false_hits"`; held-out rates are reported only for a chosen threshold. A `None` result means R51 cannot be configured from this calibration; the caller must not substitute a default.
  - Register R51; builtin count 54 -> 55.
- Create `tests/cache/data/semantic_pairs_v1.json` (ASCII; Arabic as backslash-u escapes): about 12 pairs per split, `{id, split, kind: paraphrase|adversarial, lang: en|ar|mixed, a, b, note}`; adversarial kinds: year, negation, identifier, comparative, number, cross-language, entity swap without digits, month name, unit (the last three are expected to pass the guard: documented losing cases). A header field says "small illustrative sets, not a benchmark".
- Create `tests/cache/test_semantic_cache.py`:
  - paraphrase of a cached question in the same partition: hit, zero answer calls, one cache-ledger embed call;
  - same question in another tenant, or another partition (model changed): miss;
  - 2025 vs 2026 and with/without: miss `features_differ:*` even when a stub embedder forces similarity 1.0;
  - two close cached answers: `ambiguous`; denied source on a semantic hit: `source_denied`; stored entries contain no question text;
  - data checks: unique ids; no pair text, and no near-duplicate (token Jaccard >= 0.8 after lowercasing) shared between splits;
  - `calibrate` with `LexicalTestEmbedder`: threshold chosen from dev only (editing a held-out pair does not change it); a synthetic dev set where every threshold has a false hit gives `None`; report numbers pinned and printed; entity-swap, month and unit false hits, if they occur, are asserted and kept.
