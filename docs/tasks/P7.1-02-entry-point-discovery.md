## Goal
`discover_plugins(registry)` loads third-party plugin classes from the entry-point group `rag_foundry.techniques`. Discovery is explicit (never at import), deterministic (sorted) and all-or-nothing. Every failure becomes a typed error; nothing is silently skipped.

## Read only these files
- `packages/techniques/src/rag_foundry_techniques/registry.py`, `errors.py`, `__init__.py` (after P7.1-01)
- `tests/techniques/test_registry.py` (test style)
- Python 3.12 docs `https://docs.python.org/3.12/library/importlib.metadata.html#entry-points` (the repo targets py312; CI uses 3.12). Check these points:
  - `entry_points(group=...)` returns `EntryPoints`; the dict interface was removed in 3.12;
  - `EntryPoint` has `.name`, `.value`, `.group`, `.dist` (may be `None`) and `.load()`;
  - `EntryPoint(name, value, group)` can be constructed directly.

## Change
- Create `packages/techniques/src/rag_foundry_techniques/discovery.py`:
  - Import with `from importlib import metadata` and call `metadata.entry_points(group=ENTRY_POINT_GROUP)`. Do not use `from importlib.metadata import entry_points`, so that tests can monkeypatch `discovery.metadata.entry_points`.
  - `ENTRY_POINT_GROUP = "rag_foundry.techniques"`.
  - Frozen dataclass `DiscoveredPlugin`: `entry_point: str` (the name), `value`, `distribution`, `distribution_version` (the last two are `None` when `.dist` is `None`), `technique_id`, `kind`, `plugin_version`.
  - `discover_plugins(registry, *, entry_points=None) -> tuple[DiscoveredPlugin, ...]`. When `entry_points` is `None`, it uses the call above; tests inject a list.
  - Steps:
    1. Sort the candidates by `(name, value, distribution or "")`.
    2. Check each candidate, in sorted order. Collect a failure when:
       - `group != ENTRY_POINT_GROUP`;
       - `.load()` raises any `Exception` (reason `import failed: <ExcType>: <msg>`);
       - the loaded object is not a class;
       - `registry.check(cls)` raises (unknown ID, wrong kind, duplicate vs an already registered built-in, lax config, no manifest);
       - the entry-point `name` is not equal to `manifest.technique_id`.
    3. Duplicate between entry points: when two or more valid candidates claim the same ID, **every** one of them gets a failure (`error_type="DuplicatePluginError"`, reason `duplicate entry point for <ID>`). None of them is registered.
    4. If there are any failures, raise `PluginDiscoveryError` and leave the registry unchanged.
    5. Otherwise, register all candidates in sorted order and return the report.
  - Docstring and module comment: `.load()` imports third-party modules. Import side effects (module state, `sys.modules` entries) are **not rolled back** when discovery fails. "Unchanged" refers to the registry only. Plugins are trusted code.
- `errors.py`:
  - Add a frozen dataclass `PluginDiscoveryFailure`: `entry_point: str` (the entry-point name), `value: str`, `distribution: str | None`, `reason: str`, `error_type: str` (the name of the exception class, for example `UnknownTechniqueError`).
  - Add `PluginDiscoveryError(TechniqueError)` with a `.failures` tuple, sorted by `(entry_point, value, distribution or "")`. Its message lists one line per failure.
- `__init__.py`: export `ENTRY_POINT_GROUP`, `DiscoveredPlugin`, `discover_plugins`, `PluginDiscoveryError`, `PluginDiscoveryFailure`.
- Create `tests/techniques/test_discovery.py`. Use fake entry-point objects (`name`, `value`, `group`, `dist=None`, `load`) that return test classes. Cases:
  - success, with the report fields checked;
  - reversed input gives a sorted report;
  - unknown ID X99;
  - wrong kind;
  - name/ID mismatch;
  - duplicate with a built-in: pre-register a C05 test plugin, then discover C05 -> `DuplicatePluginError`;
  - duplicate between two entry points -> two failures, both `DuplicatePluginError`, sorted;
  - a real `EntryPoint(name="C11", value="ragf_missing_module_xyz:Plugin", group=ENTRY_POINT_GROUP)` -> import failure;
  - a real `EntryPoint` pointing at `rag_foundry_techniques.protocol:PluginKind` -> no manifest;
  - a mixed batch (1 good, 2 bad): both failures are reported, and `registry.registered_ids()` is still `()`;
  - the default path calls `metadata.entry_points` with `group="rag_foundry.techniques"` (monkeypatch `discovery.metadata.entry_points`);
  - import does not call `entry_points`. Use `subprocess.run([sys.executable, "-c", code])`, where `code` sets `importlib.metadata.entry_points` to a function that raises `SystemExit(3)`, then runs `import rag_foundry_techniques`, then prints `ok`. Assert exit code 0 and `ok` in stdout.
