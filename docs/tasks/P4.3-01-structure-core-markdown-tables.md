## Goal
Structure-aware chunkers can report what a plain `ChunkSpan` cannot (section path, header context, table lineage, oversized flags) without changing the shared `ChunkSpan` contract. C08 chunks Markdown by heading sections and C12 chunks pipe and tab-separated tables by row groups that keep the header as source-offset context. Oversized structures are flagged, never dropped.

## Change
- Create `packages/chunking/src/rag_foundry_chunking/structure.py` (public, stdlib + pydantic only):
  - `ContextSpan` (frozen, `extra="forbid"`): `start >= 0`, `end > start`, `role: Literal["heading", "table_header", "declaration", "container"]`.
  - `StructuredChunk` (frozen, `extra="forbid"`): `start`, `end` (`end > start`), `split_level: int` (0..63), `kind: Literal["section", "table", "text", "code", "json"]`, `path: tuple[str, ...] = ()`, `context: tuple[ContextSpan, ...] = ()`, `block_ids: tuple[str, ...] = ()`, `attrs: tuple[tuple[str, str], ...] = ()` (keys unique, sorted), `flags: tuple[Literal["oversized", "split_part", "unparsed"], ...] = ()` (unique, sorted). Validators: every context span ends at or before `start`; context spans ascending and non-overlapping. Method `to_span() -> ChunkSpan`; property-like helper `attr(key) -> str | None`.
  - `SkippedRange` (frozen): `start`, `end`, `reason: str`, `block_id: str | None = None` (used by C09 later).
  - `StructureResult` (frozen): `chunks: tuple[StructuredChunk, ...]`, `skipped: tuple[SkippedRange, ...] = ()`.
  - `render(text: str, chunk: StructuredChunk, separator: str = "\n") -> str`: the source text of each context span, then the body `text[start:end]`, joined by `separator`. Only source substrings; no invented text.
  - `split_oversized(text, start, end, size, level) -> list[tuple[int, int, int]]`: line ranges (trimmed, non-blank) packed with `pack(..., overlap_units=0)`; a line longer than `size` becomes `word_ranges`, a word longer than `size` becomes `safe_cut_ranges`. Every piece is `<= size`; levels `level`, `level+1`, `level+2`.
  - Shared config mixin or fields used by both chunkers: `chunk_size: int = 1200` (32..8000), `oversized: Literal["split", "keep"] = "split"`. `"keep"` emits the whole oversized unit as one chunk flagged `("oversized",)`; `"split"` emits `split_oversized` pieces each flagged `("oversized", "split_part")`. Nothing is dropped in either mode.
- Create `packages/chunking/src/rag_foundry_chunking/markdown.py`: `MarkdownSectionConfig` (`chunk_size`, `oversized`, `max_heading_level: int = 6` (1..6)) and `MarkdownSectionChunker` (manifest `C08`, `PluginKind.CHUNKER`, `1.0.0`, `Fidelity.ADAPTATION`).
  - Parse `doc.text` itself (CommonMark subset, same rules as the Markdown extractor: ATX headings `^ {0,3}#{1,6}(\s|$)` with optional closing `#`s; fenced code with ``` or ~~~, closed by a fence of the same char and at least the same length; an unclosed fence runs to the end). A `#` line inside a fence is not a heading. Headings deeper than `max_heading_level` are body text.
  - A section runs from its heading line to the next heading line at any level (text before the first heading is a section with `path=()`). `path` is the stack of heading titles (closing `#`s removed, trimmed). `context` holds `ContextSpan(role="heading")` for every ancestor heading line (not the section's own heading, which is in its body). `kind="section"`, `attrs` include `("heading_level", "n")` when the section has a heading.
  - A section that fits `chunk_size` is one chunk (trimmed). A heading-only section (no body before the next heading) whose next section is a child is merged into that child's first chunk when the result fits; otherwise it is its own chunk.
  - A larger section is split into units: paragraphs (blank-line runs) and whole fenced blocks (a fence is never split when it fits). Units are packed with `pack(..., overlap_units=0)`; every chunk of the section keeps the same `path` and `context`, plus the section's own heading line as an extra `heading` context for chunks after the first. A single unit larger than `chunk_size` follows `oversized`. Fenced blocks get `kind="code"` only when a chunk is exactly one fenced block; otherwise `"section"`.
  - `chunk(doc)` returns `tuple(c.to_span() for c in chunk_structured(doc).chunks)`.
- Create `packages/chunking/src/rag_foundry_chunking/tables.py`: `TableConfig` (`chunk_size`, `oversized`, `rows_per_chunk: int = 20` (1..1000)), `TableCell` (frozen: `row: int` (1-based body row), `column: int` (1-based), `start`, `end`, `row_label: str`, `column_label: str`), `TableChunker` (manifest `C12`, `1.0.0`, `Fidelity.ADAPTATION`), and `table_cells(text, chunk) -> tuple[TableCell, ...]`.
  - Detect tables in `doc.text`: (a) GFM pipe tables: a header line containing `|`, then a delimiter line matching `^\s*\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)*\|?\s*$` with the same cell count, then body lines containing `|` until a blank or non-pipe line; escaped `\|` is not a separator. (b) Tab-separated tables: at least 2 consecutive lines (header + 1 body) with the same number `>= 1` of tab characters. Cells are trimmed ranges between separators (no leading/trailing pipe cell).
  - Table chunks: body rows grouped by at most `rows_per_chunk` rows and `chunk_size` code points (counting only the rows; the header is context). The first chunk's body starts at the header line (header and delimiter are in its body); later chunks carry `ContextSpan(role="table_header")` for the header line (and the delimiter line for pipe tables). `kind="table"`; `attrs`: `table_index` (0-based in the document), `table_start` (offset), `row_first`, `row_last` (1-based body rows), `columns` (count). A single row larger than `chunk_size` follows `oversized` (`split_part` pieces keep the same row attrs).
  - Text outside tables: `paragraph_ranges` on the gaps (build a `ChunkInput` slice is not allowed; write a helper that uses blank-line splitting on `[gap_start, gap_end)` with absolute offsets), packed with `pack(..., overlap_units=0)`, `kind="text"`; units larger than `chunk_size` follow `oversized`.
  - `table_cells` returns cells of the chunk's body rows with exact offsets; `column_label` is the trimmed header cell text from the source; `row_label` is the row's first cell text. For a chunk that is not a table it returns `()`.
- Edit `__init__.py`: register `MarkdownSectionChunker`, `TableChunker`; export them, their configs, `StructuredChunk`, `ContextSpan`, `SkippedRange`, `StructureResult`, `render`, `TableCell`, `table_cells`. Add lines only; do not reorder existing ones.
- Create `tests/chunking/test_structure.py`, `tests/chunking/test_markdown_sections.py`, `tests/chunking/test_tables.py` (non-ASCII only as `\u` escapes):
  - Core: `StructuredChunk` rejects context after `start`, unsorted flags, duplicate attr keys; `render` output equals concatenated source substrings; `split_oversized` pieces `<= size`, ascending, cover every non-whitespace code point.
  - C08: nested headings `# A / ## B / ### C / ## D` give paths `("A",)`, `("A","B")`, `("A","B","C")`, `("A","D")`, and the `### C` chunk's context spans are exactly the `# A` and `## B` lines; a `# not a heading` line inside a ``` fence stays in its section and the fence is never cut when it fits; an unclosed fence runs to the end; an oversized fence with `oversized="keep"` is one chunk flagged `oversized`, with `"split"` all pieces `<= chunk_size` flagged `("oversized", "split_part")`; Arabic NFC headings (`\u` escapes, assert `unicodedata.is_normalized`) give the exact Arabic path; text before the first heading has `path=()`.
  - C12 (the P4.3 exit criterion): a pipe table with header `| Item | Weight (kg) | Price (USD) |` and 45 body rows with `rows_per_chunk=20` gives 3 table chunks; chunk 1 body contains the header, chunks 2 and 3 have `table_header` context whose source text equals the header and delimiter lines; `row_first`/`row_last` are 1-20, 21-40, 41-45 and `table_index`/`table_start` match; `table_cells` on chunk 2 finds the cell of row 25 column 2 with `column_label == "Weight (kg)"`, the right `row_label`, and `text[start:end]` equal to the cell value; `render` of chunk 3 starts with the header line. A TSV table works the same. A single 2,000-character row with `chunk_size=200`: `"keep"` gives one chunk flagged `oversized`; `"split"` gives pieces `<= 200` flagged `("oversized", "split_part")` with the same row attrs; no non-whitespace code point is lost in either mode. Text before/between/after tables becomes `kind="text"` chunks. Escaped `\|` stays inside a cell.
  - Both: all spans ascending, non-overlapping, trimmed, within the text, every non-whitespace code point in exactly one chunk body; `chunk()` equals `to_span()` of `chunk_structured`; determinism; registry `validate_config("C08", {})` and `("C12", {})` equal the default configs; unknown keys rejected.
- Create lesson drafts `docs/techniques/lessons/C08-markdown-sections.md` and `docs/techniques/lessons/C12-table-aware-segments.md` in the C02 lesson format (Intuition, Mechanism, Worked example with real demo output you ran, Runnable demo, Failure case, Limitations, Baseline comparison "Not measured yet; P4.5", Status "Draft.").
