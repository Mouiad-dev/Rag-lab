## Change
- Create `packages/domain/src/rag_foundry_domain/summary_tree.py` (stdlib + pydantic):
  - `TreeNode(node_id ~ ^rnd_[0-9a-f]{16}$, level 0-8, kind: leaf|summary, text, span: GraphSpan | None, children: tuple[node_id, ...], embedding: tuple[float, ...], synthetic: bool)`.
    - leaf: level 0, `span` set, no children, `synthetic=False`, `text == span.quote` (no extra length cap).
    - summary: level >= 1, `span=None`, 1-50 children, `synthetic=True`, text length 1-4000.
  - `node_id_for(level, payload)`: prefix + first 16 hex of SHA-256 of canonical JSON (leaf: chunk ID; summary: sorted child IDs).
  - `tree_key_for(payload) -> str` (64 hex). The builder passes `{index_version_id, technique_id, builder_version, prompt_sha256, chat_provider, chat_model, embedding_key, config}`.
  - `SummaryTree(schema: Literal["rag_foundry.summary_tree/1"], tree_key, tenant_id, project_id, index_version_id, technique_id: Literal["R37"], embedding_key, generator_json <= 8000, nodes 1-4000)`. Validators (`ValueError` -> pydantic error): unique IDs; nodes sorted by `(level, node_id)`; one embedding dimension (>= 1); each child exists with a lower level; each non-root node has exactly one parent; no cycles.
  - Methods: `check_scope(scope, index_version_id)` (`tree_scope_mismatch`); `to_json()` / `from_json()` (`tree_invalid` on unknown schema or invalid content); `roots()`; `children_of(id)`; `lineage(id) -> tuple[GraphSpan, ...]` (leaf spans under the node, sorted by `(extraction_view_id, start, end)`); `leaf_ids(id)`; `levels()`.
- `errors.py` `IndexingError.CODES` add: `tree_scope_mismatch`, `tree_invalid`, `tree_exists`, `tree_too_large`, `tree_source_mismatch`, `raptor_summary_invalid`, `kag_schema_invalid`, `kag_scope_mismatch`, `kag_invalid`, `kag_exists`, `kag_too_large`, `kag_source_mismatch`.
- Create `tests/domain/test_summary_tree.py`: every new code constructs; a 2-level tree round-trips through JSON; root `lineage` equals all leaf spans; failures for a missing child, two parents, a child at the same level, a leaf whose text differs from its quote, a summary over 4000 chars, mixed embedding dimensions; stranger scope and another version fail `check_scope`; an Arabic leaf quote (`\uXXXX` escapes) round-trips; a 3000-character leaf is accepted.
- Create `docs/decisions/ADR-0020-raptor-tree-and-kag-adaptation.md` (Accepted; owner approved persistence 2026-11-22; at most 70 lines):
  - Persistence: migration `0012_summary_trees` (`summary_trees`, `tree_nodes`, `tree_edges`) and `0013_knowledge_graphs` (`knowledge_graphs`, `kg_entities`, `kg_facts`, `kg_spans`). Scope FKs to `index_versions` / `index_version_views` / `chunks`, ready-only inserts, span triggers against chunk text, no updates, deletion follows the index version. The JSON forms stay as the export format. Ports `SummaryTreeStore` and `KnowledgeGraphStore` are separate from `IndexRepository`.
  - RAPTOR summaries are synthetic and route retrieval only; hits and citations are original leaf chunks; summaries are not sent as answer context (owner decision 2026-11-22).
  - KAG has its own model (`knowledge.py`), not `EntityGraph` (R38-only technique ID, no typed literals, no schema); it reuses `GraphSpan`. The KAG schema is validated in the domain, not in SQL.
  - KAG planning: one plan call plus at most one re-plan on a defined failure status; no fallback to chunk retrieval.
  - No OpenSPG code, dependency or service; original adaptation. Stdlib clustering (no numpy, sklearn, umap).
  - R37 and R48 register as `retriever` plugins; builders are helpers.
  - Headings "RAPTOR fidelity" and "KAG fidelity" with a placeholder; P7.3-11 fills them.
