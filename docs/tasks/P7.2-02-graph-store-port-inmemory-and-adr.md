## Goal
An `EntityGraphStore` port (separate from `IndexRepository`, like `RepresentationStore`) stores and loads one immutable entity graph per `(index_version_id, graph_key)`. The in-memory store enforces scope, readiness and provenance; shared checks later run unchanged against SQL (03). ADR-0019 records the schema decision before the migration lands.

## Change
- `ports.py`: add `@runtime_checkable class EntityGraphStore(Protocol)`:
  - `add_entity_graph(scope, index_version_id, graph: EntityGraph) -> None`: atomic, all rows or none.
  - `get_entity_graph(scope, index_version_id, graph_key) -> EntityGraph`: `NotFoundError` when missing or outside scope.
- `uow.py`: add `add_entity_graph` to `WRITE_METHODS["indexes"]`.
- `index_testing.py` `InMemoryIndexRepository`: implement both. On add, in this order: version in scope (else `NotFoundError`); state `ready` (else `not_ready`); `graph.check_scope(scope, index_version_id)`; key not present (else `graph_exists`); every span's chunk belongs to this version, `span.extraction_view_id == chunk.extraction_view_id`, `chunk.start <= span.start < span.end <= chunk.end`, and `chunk.text[span.start - chunk.start : span.end - chunk.start] == span.quote` (else `graph_source_mismatch`). Store a copy; get returns an equal object.
- `index_testing.py`: `check_entity_graphs(factory)` and `GRAPH_STORE_CHECKS = (check_entity_graphs,)`, written against the port only (works for SQL in 03). It covers: round trip; stranger scope add and get fail; not-ready version; duplicate key; span with wrong quote, outside its chunk, or a chunk of another version; Arabic quote round trip. Add a `make_entity_graph(scope, version, chunks)` helper.
- Run the checks offline in a new `tests/domain/test_graph_store.py` (same pattern as `test_representations.py`).
- Create `docs/decisions/ADR-0019-graphrag-storage-and-fidelity.md` (at most 50 lines, Accepted, owner approval 2026-11-13):
  - Tables from migration 0011 (P7.2-03): `entity_graphs`, `graph_entities`, `graph_relations`, `graph_spans` and their keys.
  - Scope FKs to `index_versions` / `index_version_views` / `chunks`; the ready-only insert trigger; no updates.
  - Provenance: `graph_spans` stores the extraction view and code-point offsets (the anchor) plus `chunk_id` (an index-local link). Rechunking means a new index version and a new graph.
  - Deletion follows the index version, as derived data.
  - The `EntityGraph` JSON is the export form, not the store.
  - Community summaries are not persisted in P7.2 (open item).
  - R38/R39 are `retriever` plugins and the builders are helpers. Stdlib only.
  - Put "Fidelity" behind a placeholder heading; P7.2-10 fills it in.
