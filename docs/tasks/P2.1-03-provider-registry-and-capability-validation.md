## Goal
`ProviderRegistry` holds model profiles and binds adapter instances to them by profile ID. `validate_requirements` checks a whole set of stage requirements before a job starts and raises one `MissingCapabilityError` that lists every gap. It has no fallback and never substitutes another profile.

## Read only these files
- `packages/providers/src/rag_foundry_providers/{errors,capabilities,ports}.py` (from P2.1-01/02)
- `packages/techniques/src/rag_foundry_techniques/registry.py` (registry style and error behavior)
- `tests/providers/test_ports.py` (house style and stub pattern)

## Change
- Create `src/rag_foundry_providers/registry.py`:
  - `StageRequirement` (frozen dataclass): `profile_id: str`, `required: frozenset[Capability]`.
  - `ProviderRegistry()` provides:
    - `add_profile(profile)`. A duplicate ID raises `DuplicateProfileError`.
    - `profile(pid)`. An unknown ID raises `UnknownProfileError`.
    - `profile_ids()` returns IDs in sorted order.
    - `bind(pid, model)`. Profile is unknown → `UnknownProfileError`; ID already bound → `DuplicateProfileError`; `model.profile != registered profile` → `ProviderError` (a declaration mismatch); `model` does not satisfy the port for the profile's kind (`isinstance` against `ChatModel`/`EmbeddingModel`/`Reranker`) → `ProfileKindError`.
    - `chat(pid)`, `embedding(pid)` and `reranker(pid)`. Unknown → `UnknownProfileError`; wrong kind → `ProfileKindError`; known but unbound → `ProviderUnavailableError`.
    - `validate_requirements(reqs: Mapping[str, StageRequirement]) -> None`, keyed by stage name. Unknown profile IDs raise `UnknownProfileError` first. Then build one `CapabilityProblem` for every `(stage, capability)` whose `profile.declared(cap)` is not `True`. Sort problems by stage, then capability. Raise `MissingCapabilityError` when there are any. It does not need adapters to be bound.
- Create `tests/providers/test_provider_registry.py`. Use small in-test stub adapters and do not import the fake provider. Cover:
  - The add/get/duplicate/unknown paths for profiles and bindings.
  - A bind mismatch on both profile and kind.
  - Unbound → `ProviderUnavailableError`, with the profile ID in the message.
  - A `tool_calling` requirement against a profile with `tool_calling=None`, and against one with `False`. Both are rejected, and `declared` is recorded correctly.
  - Two stages with two problems produce one error carrying both, in a stable order.
  - A satisfied requirement set returns `None`.
  - `local` required against a non-local profile is rejected.
  - None of the errors is a `KeyError`/`LookupError`.
