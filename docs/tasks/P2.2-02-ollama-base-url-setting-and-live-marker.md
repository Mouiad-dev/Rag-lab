## Goal
`Settings.ollama_base_url` exists with default `http://127.0.0.1:11434` and env var `RAG_FOUNDRY_OLLAMA_BASE_URL`. A strict `live` pytest marker is registered so later tasks can mark opt-in tests.

## Read only these files
- `packages/core/src/rag_foundry_core/settings.py` (field style, strict config)
- `tests/core/test_settings.py` (house style)
- `pyproject.toml` (root; `[tool.pytest.ini_options]`, `--strict-markers` is on)
- `.env.example` (placeholder-only env documentation)

## Change
- Edit `settings.py`: add `ollama_base_url: str = "http://127.0.0.1:11434"` with a field validator that:
  - accepts only `http` or `https` schemes with a host (use `urllib.parse.urlsplit`);
  - rejects user info (`user:pass@`), query and fragment, so no credential can hide in the URL;
  - strips one trailing `/`.
  The value is not a secret; do not use `SecretStr`.
- Edit `tests/core/test_settings.py`: default value; env override via `RAG_FOUNDRY_OLLAMA_BASE_URL`; trailing slash stripped; rejects `ftp://x`, `127.0.0.1:11434` (no scheme), `http://u:p@host:11434`, `http://host/?a=1`. The error message for the user-info case must not contain the password text.
- Edit root `pyproject.toml`: add `markers = ["live: opt-in test that calls a real local or remote provider; skipped unless explicitly enabled"]` under `[tool.pytest.ini_options]`.
- Edit `.env.example`: add a commented line `# RAG_FOUNDRY_OLLAMA_BASE_URL=http://127.0.0.1:11434` (inside compose the worker would use `http://ollama:11434`; mention this in the comment).

## Constraints

- Do not touch `compose.yaml` or `packages/providers`.
