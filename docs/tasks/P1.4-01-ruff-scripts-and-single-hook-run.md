## Goal
`ruff check .` and `ruff format --check .` cover `scripts/`. `tasks.py check` runs the 21 hook tests exactly once (through pytest), not twice. Behavior of the three scripts does not change.

## Read only these files
- `pyproject.toml` (`[tool.ruff] extend-exclude`, `[tool.pytest.ini_options] testpaths`)
- `scripts/tasks.py` (`GROUPS["repo"]` runs `unittest discover -s tests/hooks`; `GROUPS["test"]` runs pytest over `tests/`, which also collects `tests/hooks`)
- `scripts/verify_package.py`, `scripts/build_flow.py` (formatting/lint fixes only)
- `CONTRIBUTING.md` ("Development setup" section, lines ~15-40)

## Change
- Edit `pyproject.toml`: remove `"scripts"` from `extend-exclude`. Keep `.claude` and `tests/hooks` excluded.
- Run `uv run ruff format scripts` and `uv run ruff check --fix scripts`. Fix any remaining findings by hand (expect E501 in `verify_package.py`; split long f-strings or lines, do not add `noqa` unless a fix would change output text).
- Edit `scripts/tasks.py`: remove the `unittest discover -s tests/hooks` entry from `GROUPS["repo"]`. Update the module docstring or help text so it says hook tests run in the `test` group (pytest).
- Edit `CONTRIBUTING.md`: one line noting that `tasks.py check` runs the hook tests via pytest; the plain stdlib `python -m unittest discover -s tests/hooks -v` command stays valid for setups without uv.

## Constraints
- `scripts/*.py` stay standard-library only and runnable with plain `python` (no uv). No logic changes: same checks, same messages, same exit codes.
- The `PASS:` line printed by `verify_package.py` must be byte-identical before and after.
- Do not touch `tests/hooks` or `.claude/`.
