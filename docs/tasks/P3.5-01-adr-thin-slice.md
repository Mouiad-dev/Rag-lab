## Change
- Create `docs/decisions/ADR-0013-thin-slice-grounded-answers.md` (Context / Decision / Alternatives / Consequences / Evidence, like ADR-0012), status `accepted (decided by owner 2026-11-06)`. Decisions D1-D15, all decided by owner 2026-11-06:
  - D1 Package: new workspace member `packages/answering` (prompt, citation checks, retrieval gate, `AnswerService`, `LocalRunner`). Packing/compression go to `packages/context` at P6.3. Alternative not taken: `packages/context` now.
  - D2 Contract: `rag_foundry_contracts.runs`, `CONTRACT_VERSION` 1.0 (additive), `RunRequest` / `RunResponse` (both carry `contract_version`), schemas `run-request.v1.json`, `run-response.v1.json`. Citations are answer-level; claim-level checks are P6.3. Known gap: a resolving citation is not proof it supports the claim; a reply like "The passages do not state the population [S1]" passes the checks and counts as `answered`.
  - D3 Citations: the model writes `[S<n>]`, n = evidence retrieval rank. Marker -> chunk span -> `AnchorService.anchors_for_span` (one anchor per block). Every cited anchor must resolve `exact` before the answer is returned, else abstain `citation_unresolved`. Granularity is the chunk span (quotes at P6.3).
  - D4 Abstention, three layers, reason recorded: (a) retrieval gate before any chat call: no hits -> `no_evidence`; top score < `min_score` -> `low_score`; (b) reply contains `INSUFFICIENT_EVIDENCE` -> `model_declined`; (c) deterministic checks: `finish_reason == "length"` -> `truncated_output`, no marker -> `uncited_answer`, unknown marker -> `invalid_citation`, anchor not exact -> `citation_unresolved`. Abstained responses never carry model text.
  - D5 Threshold: default per embedding model `(provider, model, dim)`; `("ollama","bge-m3",1024)` -> 0.45. This is an unvalidated coarse floor: the P3.4 values 0.41-0.43 were top distractors for on-topic queries, and the only unanswerable observation (0.507) is above it, so it is not evidence that 0.45 separates anything. Per-case `top_score` is recorded live for calibration at P6. Unknown embedding models need an explicit `min_score`, else `abstention_threshold_unset`. Only hits >= `min_score` go to the model. Alternatives not taken: no gate; 0.6 fitted to one case (overfit); LLM judge (P6.5).
  - D6 Prompt and injection defence: templates `grounded-answer-v1`, `ungrounded-v1`; instructions only in the system message; evidence and question only in the user message inside per-run 16-hex nonce delimiters (a nonce found in the content is regenerated); the system message says evidence is untrusted quoted data; no tools, no structured output; deterministic checks (D4c) as a second layer. Injection is measured on two levels: `model_followed_injection` (raw model reply contains the canary, or the injection case is not answered correctly; a false abstention there counts as an injection success) and `canary_leaked` (canary in the response `answer` text or `warnings`; evidence and citation anchors are excluded because they quote retrieved source text by design). Only "no leak" is a pass/fail gate; the model-level result is a security result, recorded per run and never averaged with quality. Prompt defence is not a guarantee.
  - D7 Execution: `POST /api/v1/projects/{project_id}/runs` runs synchronously in the API (1 embedding + at most 1 chat call, async I/O), returns 200 with `RunResponse`; no SSE, no job. Index builds stay worker/CLI side (ADR-0012 D9). For runs this overrides the ADR-0001 P2.5 retry policy: `RetryPolicy(max_attempts=2, attempt_timeout_s=120, retry_timeouts_for_local=False)`. `max_concurrent=1` per process for local Ollama (Ollama queues requests, and the next request's attempt clock runs while it waits); else 429 `too_many_runs`. Run deadline 300 s (503 `run_timeout`). 300 s / 1 / 120 s are provisional until measured; the live run records wall time and token counts per case. A client disconnect does not cancel the run (cancel at P8.4). The live fixture uses 120-char chunks, so its prompts are smaller than API defaults (800-char chunks, up to 12000 evidence chars). Alternative not taken: 202 + worker job (P8.4).
  - D8 Persistence: none. `run_id` is a UUID4, not stored; GET/events/cancel at P8.4. Logs carry only run_id, status, reason and counts.
  - D9 Budget: one `RunBudget(Decimal("0"), max_calls=2 * attempts)` and one `UsageLedger` per run; local profiles only in P3.5 (paid chat needs P6 per-stage config and an explicit budget); `max_output_tokens` 512; temperature 0.
  - D10 Models: Ollama `gemma4:e4b` and `bge-m3` at `settings.ollama_base_url`, wrapped Resilient(Budgeted(Recording(adapter))) as in `pipeline.build_registry`; zero keys.
  - D11 Techniques: R02 = retrieval + grounded generation. R01 run = `status="ungrounded"`, no evidence, no citations, no gate. The service branches on `RetrievalResult.grounding`, never on a technique ID; the edge maps `technique_id` to a retriever; others -> `unsupported_technique`.
  - D12 Dev CLI (moved from P3.4): `rag-foundry-index build|inspect`, `rag-foundry-ask` in `apps/worker`; `LOCAL_DEV_SCOPE`; refused in prod; ASCII-safe JSON output; `--question-file` for non-ASCII input; inspect prints no chunk text unless `--show-text`.
  - D13 Evaluation: 10-question bilingual fixture (5 en, 3 ar, 2 mixed; 3 unanswerable: 2 near-topic, 1 fully off-topic so the gate is exercised; 1 injection canary). Cases 1, 2 and 7 reuse P3.4 queries on the same base corpus and are not unseen. Per-case outputs; substring answer check (weak, not a judge, markers stripped first); citation check = a cited anchor contains the fact and all cited anchors are exact; abstention measured per layer. A smoke fixture, not a benchmark; Arabic pending native-speaker review.
  - D14 Freeze: the prompt templates and the threshold are frozen before the first live run. Any later change gets a new template id (`-v2`) or a recorded threshold decision and a new run; no tuning until a case passes. Results, including a failing population case, are reported as measured.
  - D15 Done and catalogue: done when the live run (gemma4:e4b + bge-m3 + compose testdb; no keys, no download) shows the EN and AR P3.4 fact cases answered with exact citations to the fact chunk, the population case abstains, and `canary_leaked` is false for all cases.
