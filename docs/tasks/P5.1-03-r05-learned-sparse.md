## Goal
R05 retrieves with a real pretrained learned sparse encoder (SPLADE family), stores document-side sparse vectors per chunk, and fails with `TechniqueUnavailableError` when the encoder package or local model files are absent. No random, hash or hand-made vectors ever stand in for the model.

## Step 0 (orchestrator, before any code; record in Result)
Verify on the current official pages, then get the owner's OK for exactly these items (my values are from memory, not checked this session):
- Package: `sentence-transformers` (Apache-2.0), version with `SparseEncoder` (v5.x); pulls `torch` (BSD-3, CPU wheel), `transformers`, `tokenizers`, `safetensors`, `huggingface-hub` (Apache-2.0). Install as optional extra `rag-foundry-providers[sparse]`, never in the default install.
- Model (recommended): `opensearch-project/opensearch-neural-sparse-encoding-multilingual-v1`, Apache-2.0, multilingual incl. Arabic (verify), about 160M params / ~0.67 GB. Confirm whether queries are model-encoded or IDF-only, and pin the revision hash.
- Alternative: `BAAI/bge-m3` sparse head via `FlagEmbedding` (MIT, ~2.3 GB). Rejected: `naver/splade-v3`, `naver/splade-cocondenser-*` (CC BY-NC-SA 4.0, English, gated).
- Download is a separate explicit owner command into a local directory; the adapter loads with `local_files_only=True` and never downloads.

## Change
Part A (no dependency, no download):
- `docs/decisions/ADR-0017-sparse-encoder-port.md` (<= 30 lines): new port, storage table, explicit-unavailable rule, no implicit downloads.
- `messages.py`: `SparseVector(terms: tuple[str, ...], weights: tuple[float, ...])` (equal length, unique terms, finite weights > 0, <= 4096 entries); `SparseEncodingResult(vectors, usage)`. `ports.py`: `SparseEncoder` Protocol `profile`, `async encode(texts, *, input_type: Literal["document","query"])`.
- Migration `0009_chunk_sparse_vectors.py`: add `UNIQUE (tenant_id, project_id, index_version_id, id)` on chunks; table `chunk_sparse_vectors(tenant_id, project_id, index_version_id, chunk_id, encoder_key varchar(64), terms text[], weights real[])`, PK `(chunk_id, encoder_key)`, FK on the 4-tuple to chunks, CHECK equal array lengths, `reject_index_update` trigger.
- SQL repo: `add_sparse(scope, index_version_id, encoder_key, rows)` and `sparse_search(scope, index_version_id, encoder_key, query: SparseVector, k)`: dot product in SQL (`unnest` both arrays, join query terms, `sum(w_doc*w_q)`), scope + ready checks as `search`, top 8 matched terms per hit returned.
- `rag_foundry_indexing/sparse.py`: `SparseIndexService.build(scope, version, encoder)` (pages chunks, encodes `document`, stores, returns nonzero counts for the memory comparison); `LearnedSparseRetriever` (R05, `Fidelity.ADAPTATION`), components `sparse_term` per matched term, `scoring="learned-sparse-dot"`; `encoder is None` or encoder key mismatch -> `TechniqueUnavailableError` / `IndexingError("incompatible_sparse_encoder")`.
- Tests: `tests/indexing/_vocab_sparse_encoder.py` test-only double (weights from `lexical_tokens` counts, model name `test-vocab-sparse`, never registered, docstring says it is not R05, per ADR-0012 D13); offline tests for validation and unavailable path; `test_sparse_db.py` (`-m db`) for store, scope isolation and immutability.
Part B (only after owner OK in Step 0):
- `rag_foundry_providers/sentence_transformers_sparse.py` adapter; lazy import, `ImportError` or missing model dir -> provider error that R05 maps to `TechniqueUnavailableError("R05 needs the [sparse] extra and approved local model files")`; encoding via `asyncio.to_thread`; usage tokens from the tokenizer, cost 0. `[sparse]` extra in `packages/providers/pyproject.toml`; `uv lock`.
- `tests/live/test_sparse_live.py`, opt-in `RAG_LIVE_SPARSE=1` + model dir env var; EN and AR fixture facts in top-5.
