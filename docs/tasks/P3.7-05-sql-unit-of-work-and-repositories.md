## Goal
One `AsyncSession` per `SqlUnitOfWork`; the five SQL repositories are bound to it and keep every query, scope filter, lock and error mapping. Callers keep per-call behaviour through `PerCall`, so services are unchanged. A two-repository write commits or rolls back as one; writes in a read-only UoW are refused.

## Change
- Create `packages/storage/src/rag_foundry_storage/sql/uow.py`: `SqlUnitOfWork(sessionmaker, *, read_only)`. `__aenter__` creates the session (no connection, no statement), sets `session.info["read_only"]`, records `asyncio.current_task()`, builds the five repos; each repo property checks the owning task (`RuntimeError` otherwise). `commit()`: read-only -> `RuntimeError`; `OperationalError`/`InterfaceError` -> `StoreError("store_unavailable")`, other `DBAPIError` -> `StoreError("commit_failed")`, both `from None`. `__aexit__`: not committed -> `rollback()`; errors from rollback/close never replace a propagating exception; always `close()`. `Database.uow(*, read_only=False)` returns one.
- Create `sql/_tx.py`: `read(session)` (async CM yielding the session) and `write(session)` (raises `RuntimeError("read-only unit of work")` if `session.info.get("read_only")`, else `async with session.begin_nested(): yield session`). In `repository.py`, `extraction_repository.py`, `index_repository.py`, `prompt_store.py`, `settings_repository.py`: constructor takes `session: AsyncSession`; `async with self._sessionmaker() as session, session.begin():` -> `async with write(self._session) as session:`; `async with self._sessionmaker() as session:` -> `async with read(self._session) as session:` (no re-indent; queries untouched; existing `try/except` mapping stays around the block). No `commit`, `rollback`, `close` or `begin()` left in repositories. No UoW takes more than one advisory lock (ADR D7 ordering rule applies to any future one).
- `ensure_local_scope` becomes module function `ensure_local_scope(uow_factory, scope)` (one write UoW, commit); `open_container` updated.
- Composition: `container.py` and the three CLIs build repositories as `per_call_documents(db.uow)` etc. Tests that built `SqlXRepository(maker)` (`tests/storage/*`, `tests/indexing/test_index_db.py`, `tests/api/test_anchors_db.py`, `tests/live/*`, the 00 `_build`) use the `per_call_*` helpers; assertions unchanged.
- Tests `tests/storage/test_sql_uow_db.py` (`-m db`): document + extraction view written in one UoW, exception before commit -> neither exists (fresh read UoW), committed -> both exist; in one UoW `add_chunks([valid, duplicate])` -> `duplicate_ordinal`, the valid row absent, then valid `add_chunks` + `mark_ready` + commit succeed; every write method of the five repos raises `RuntimeError` in a read-only UoW and no row appears; repo access from another task raises; closed-port URL -> `PromptError("store_unavailable")` raised by the read inside the block, not by `__aenter__`; killed backend: inside a write UoW read `pg_backend_pid()` through the UoW session, `pg_terminate_backend(pid)` from a second connection, then (a) `uow.settings.append(...)` -> `SettingsError("store_unavailable")`, (b) in another UoW a `documents` write -> the driver error propagates (documented fallback, D8), (c) a terminated UoW whose block completes -> `commit()` raises `StoreError("store_unavailable")`; in all three no savepoint-rollback, rollback or close error replaces the original. `tests/storage/test_sql_uow.py` (offline): commit `OperationalError` -> `StoreError("store_unavailable")` with no cause text; a failing rollback does not mask the original exception.
