## Goal
A pure C21 plugin chunks Arabic, English and mixed-script text at the best available boundary (sentence, clause, word, script change, safe hard cut), never splits a word from its diacritics or bidi controls, and offers a reversible normalization view whose every character maps back to an original offset. C06, C07 and C21 become `implemented` in the catalogue.

## Change
- Create `packages/chunking/src/rag_foundry_chunking/multilingual.py`:
  - `script_of(char) -> Literal["arabic", "latin", "other"]`: Arabic for U+0600-06FF, U+0750-077F, U+08A0-08FF, U+FB50-FDFF, U+FE70-FEFF; Latin for ASCII letters and U+00C0-024F; else other. Digits, marks, punctuation and spaces are `other`.
  - `MultilingualConfig` (frozen, `extra="forbid"`): `chunk_size: int = 800` (32..8000), `overlap_sentences: int = 0` (0..3), `abbreviations` as in C06.
  - `MultilingualChunker`: manifest `C21`, `PluginKind.CHUNKER`, `1.0.0`, `Fidelity.ADAPTATION`, `config_model=MultilingualConfig`. Levels: sentences (`sentence_ranges`) 0; an oversized sentence splits after clause marks `، ؛ , ; :` followed by whitespace (level 1); oversized clauses into words (level 2); an oversized word into script runs, cutting where the script of the previous letter differs from the next letter, skipping `other` chars (level 3; marks, tatweel `ـ`, ZWJ/ZWNJ stay with their letter); still oversized: `safe_cut_ranges` (level 4). Bidi controls `‎ ‏ ؜ ‪-‮ ⁦-⁩` are never the first or last char of a chunk when an adjacent non-whitespace char belongs to the same word (treat them as part of the word, never as whitespace). Then `pack`.
  - `normalize_with_map(text, start=0, end=None) -> tuple[str, tuple[int, ...]]`: removes Arabic harakat and Quranic marks (U+064B-065F, U+0670, U+06D6-06ED), tatweel `ـ` and bidi controls; maps alef forms `آ أ إ ٱ` to `ا`; returns the normalized string and, per normalized char, its original offset. Never changes chunk offsets (it is a view for inspection and matching).
- Edit `__init__.py`: register `MultilingualChunker`; export it, `MultilingualConfig`, `normalize_with_map`. Do not change other lines.
- `config/techniques.json`: C06, C07, C21 `status: "implemented"` and `implementation_path` to `sentence.py`, `paragraph.py`, `multilingual.py`. `docs/techniques/TECHNIQUE_CATALOG.md`: those three rows end in `implemented`; line 3 names C05, C06, C07 and C21 as implemented (change only that clause). Regenerate `docs/flow/index.html` with `python scripts/build_flow.py`.
- Create `tests/chunking/test_multilingual.py` (`\u` escapes):
  - Mixed sentence `<Arabic words> API <Arabic words>؟ The API returns JSON.`: sentence ranges exact; the English abbreviation rules still hold inside Arabic text.
  - Oversized Arabic sentence with `،` and `؛`: chunks end right after those marks (level 1).
  - Oversized no-space mixed token (`<Arabic letters with harakat>API<Arabic letters>` repeated, no spaces): level 3 cuts only at Arabic/Latin changes; no chunk starts with a haraka, tatweel or ZWNJ.
  - Bidi: RLM/LRM and an isolate pair around an English word inside Arabic are kept inside the chunk with that word.
  - Arabic-Indic digits with `٫` decimal (`٣٫١٤`) never split.
  - NFC fixtures: `unicodedata.is_normalized("NFC", text)`; offsets are code points on the original text.
  - `normalize_with_map`: diacritics, tatweel, bidi removed, alef forms folded; `len(normalized) == len(mapping)`; for each i, `normalized[i] == fold(text[mapping[i]])`; mapping strictly increasing; applied to a chunk range it maps inside that range.
  - Coverage, bounds, determinism, strictly increasing starts/ends; seeded property test (300 texts over Arabic letters, harakat, Latin letters, `،؟. ‏`); registry `validate_config("C21", {})` defaults, unknown key rejected.
