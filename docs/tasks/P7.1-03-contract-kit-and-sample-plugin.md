## Goal
1. Any plugin package can call `rag_foundry_techniques.contract` to check its own contract.
2. A separate sample package under `examples/plugins/` registers C11 through an entry point. Core code is not changed for it. A test installs it on a test-only metadata path (a `.dist-info` under `tmp_path`), discovers it and runs it.

## Read only these files
- `packages/techniques/src/rag_foundry_techniques/registry.py`, `discovery.py`, `kinds.py` (`ChunkInput`, `TextBlock`, `ChunkSpan`, `Chunker`), `__init__.py`
- `packages/chunking/src/rag_foundry_chunking/fixed.py` lines 1-60 (style for a built-in chunker manifest and config)
- `tests/techniques/test_discovery.py`

## Change
- Create `packages/techniques/src/rag_foundry_techniques/contract.py`. It uses plain functions, does not import pytest, and has `PluginContractError(AssertionError)`.
  - `check_plugin_contract(plugin_cls, catalogue, *, sample_config=None) -> PluginManifest` checks that:
    - the manifest is valid;
    - the ID is in the catalogue;
    - the kind is in `catalogue.kinds_for`;
    - the config model is `extra="forbid"`;
    - `model_json_schema()` works;
    - a fresh `TechniqueRegistry` raises `TechniqueUnavailableError` (not a `KeyError`) for the ID before registration, registers the plugin once, and raises `DuplicatePluginError` the second time.
    - When `sample_config` (a raw mapping) is given, it validates, and the same mapping plus `"__contract_unknown__": 1` raises `ValidationError`.
  - `check_chunker_run(plugin_cls, config, doc) -> tuple[ChunkSpan, ...]`:
    - `config` is a **raw mapping**. The function validates it with `plugin_cls.manifest.config_model.model_validate(dict(config))`, then calls `plugin_cls(model).chunk(doc)`.
    - It checks that the kind is `chunker`, that every span is a `ChunkSpan` with `0 <= start < end <= len(doc.text)`, and that spans are in ascending order.
- `__init__.py`: export the two functions and `PluginContractError`.
- Create `examples/plugins/rag_foundry_sample_plugin/`:
  - `pyproject.toml`: hatchling, name `rag-foundry-sample-plugin`, version `0.1.0`, dependency `rag-foundry-techniques`, and this entry point:
    ```toml
    [project.entry-points."rag_foundry.techniques"]
    C11 = "rag_foundry_sample_plugin:PageBlockChunker"
    ```
  - `src/rag_foundry_sample_plugin/__init__.py`: `PageBlockChunker` (kind `chunker`, fidelity `simulation`, version `0.1.0`, config `PageBlockConfig(extra="forbid")` with `max_pages: int = Field(1, ge=1)`). It makes one span per group of `max_pages` consecutive `kind == "page"` blocks. Input with no page blocks raises `TechniqueUnavailableError("C11 sample needs page blocks")`.
  - `README.md` (at most 25 lines): what it is, that it is a sample and not an implementation of C11, the trusted-code warning, and how to install it with `uv pip install -e`.
- Create `tests/techniques/test_contract_kit.py`:
  - The kit passes for every built-in registered by the chunking and indexing `register_builtin_plugins`, with `sample_config=None`, parametrized by ID.
  - The kit raises `PluginContractError` for a lax config, a wrong kind, an unknown ID and a bad chunker span.
- Create `tests/techniques/test_sample_plugin.py`:
  - Write `rag_foundry_sample_plugin-0.1.0.dist-info/` under `tmp_path`. It holds `METADATA` (`Metadata-Version: 2.1`, `Name: rag-foundry-sample-plugin`, `Version: 0.1.0`) and an `entry_points.txt` that starts with the section header:
    ```text
    [rag_foundry.techniques]
    C11 = rag_foundry_sample_plugin:PageBlockChunker
    ```
  - Prepare the environment:
    - `monkeypatch.syspath_prepend` both `tmp_path` and the example `src`;
    - `monkeypatch.delitem(sys.modules, "rag_foundry_sample_plugin", raising=False)` before and as cleanup, so no test sees a cached module;
    - `importlib.invalidate_caches()`.
  - Run `discover_plugins` on a fresh registry. The report shows `C11`, `rag-foundry-sample-plugin` and `0.1.0`.
  - Call `registry.plugin("C11")`, then `check_chunker_run(cls, {"max_pages": 1}, <3-page ChunkInput>)`; the result is 3 spans.
  - The kit passes with `sample_config={"max_pages": 2}`.
  - The no-pages input raises unavailable.
  - Afterwards `load_catalogue(...).get("C11").status == "planned"`.
