## Goal
State found: `config/techniques.json` is already `schema_version: 2` and `load_catalogue` already enforces v2 fields. This task tightens v2 validation in the loader. It adds one required top-level map `allowed_plugin_kinds` (category -> plugin kinds). The registry then refuses a plugin whose `kind` does not fit its entry's category. All 72 entries stay byte-identical. The version stays 2, because the change is additive.

## Change
- `config/techniques.json`: add the top-level `"allowed_plugin_kinds"` after `allowed_categories`. Append one sentence about it to `schema_notes`. Do not touch any entry. Use this map; it matches every current built-in manifest:
  `agentic_workflow: [query_transform, workflow]` (R28 is `query_transform`), `baseline: [retriever]`, `cache: [cache]`, `chunking: [chunker]`, `context: [context_builder]`, `evaluation: [evaluator]`, `graph_knowledge: [graph_builder, knowledge_store, retriever]`, `knowledge_context: [knowledge_store, workflow]`, `multimodal: [representation, retriever]`, `other: [<all 12 kinds>]`, `query_transform: [query_transform]`, `representation: [representation]`, `reranking: [reranker]`, `retrieval: [fusion, retriever]` (R07-R10 are `fusion`), `structured_data: [retriever, workflow]`. Lists are sorted.
- `catalogue.py`:
  - `Catalogue` stores the map immutably, as `allowed_plugin_kinds: tuple[tuple[str, tuple[str, ...]], ...]` (sorted pairs) or as a private attribute. Never expose a mutable dict. The public accessor is `kinds_for(tid) -> tuple[str, ...]`; it raises `UnknownTechniqueError` for an unknown ID.
  - `load_catalogue` rejects the map with `CatalogueError` when it is missing, is not an object, lacks an allowed category or has an extra one, has an empty list, or names a kind that is not a `PluginKind` value.
  - New per-entry checks, each a `CatalogueError` naming the ID. Use `re.fullmatch` with `[0-9]`, never `\d` and never `^...$`:
    - `id`: `re.fullmatch(r"[A-Z][0-9]{2}", id)`;
    - `roadmap_step`: `re.fullmatch(r"P[0-9]+\.[0-9]+", step)`;
    - `phase` equals the step's phase number;
    - `date_added` matches `re.fullmatch(r"[0-9]{4}-[0-9]{2}-[0-9]{2}", ...)` and passes `datetime.date.fromisoformat`;
    - `primary_source` is null or starts with `https://`;
    - `status == "validated"` requires `evidence_path`.
- `errors.py`: add `PluginKindError(TechniqueError)`.
- `registry.py`:
  - Split `register` into `check(plugin_cls) -> PluginManifest` (all validation, no state change) and `register` (calls `check`, then stores).
  - Check order:
    1. the manifest;
    2. the unknown ID;
    3. the **kind check** (new): if `manifest.kind` is not in `catalogue.kinds_for(tid)`, raise `PluginKindError` naming the ID, the kind and the allowed kinds;
    4. the config `extra="forbid"` check;
    5. the duplicate check.
  - Error types do not change otherwise.
- `scripts/verify_package.py` (stdlib only): check that the map's keys equal `allowed_categories` and that every kind is in a literal 12-kind set.
- Tests:
  - Extend `test_catalogue.py`:
    - one rejection case per new rule, using the `_copy` helper;
    - a round-trip test: `[e.model_dump(exclude_unset=True) for e in cat.entries] == raw["techniques"]`, where `raw` is `json.loads` of the committed file;
    - a test that `kinds_for("C01") == ("chunker",)`.
  - Extend `test_registry.py`:
    - a wrong-kind case: a `reranker` claiming C01 -> `PluginKindError`;
    - a wrong kind together with a lax config -> `PluginKindError` (this proves the order);
    - `check` leaves the registry empty.
  - Create `tests/techniques/test_builtin_kinds.py`: register `rag_foundry_chunking.register_builtin_plugins` and `rag_foundry_indexing.register_builtin_plugins` into one registry with no error.
