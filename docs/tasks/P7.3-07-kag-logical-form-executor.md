## Goal
A small, versioned JSON logical-form grammar is parsed against the schema and executed deterministically over a `KnowledgeGraph`. Every step result lists bindings, supporting fact IDs and source spans. Missing facts, conflicts, unknown entities, schema violations and unsupported operators are explicit statuses, never silent fallbacks.

## Change
- Create `packages/indexing/src/rag_foundry_indexing/kag_logical_form.py` (no chat, no I/O). Module docstring: "operators named after the KAG paper's logical forms; our own JSON grammar, not OpenSPG's".
  - Grammar `rag_foundry.kag_lf/1`: `{"steps":[...]}`, 1-8 steps, ids `s1..s8`; a step may reference only earlier ids:
    - `retrieve`: `{"op","id","subject": ref|null,"predicate","object": ref|null}`; `ref` is `{"entity": {"name","type"}}` or `{"step": id}`; exactly one side is null (the unknown); property predicates need a non-null subject and null object;
    - `filter`: `{"op","id","input","predicate","cmp": eq|ne|gt|ge|lt|le,"value"}` on a property;
    - `count`: `{"op","id","input"}`;
    - `sort`: `{"op","id","input","predicate","order": asc|desc,"limit" 1-20}`;
    - `output`: `{"op","id","inputs":[ids]}`, exactly once, last.
  - `parse_logical_form(data, schema) -> LogicalForm | PlanRejection(reason, detail)`. Reasons: `invalid_logical_form` (shape, ids, refs, missing or extra `output`), `unsupported_operator` (any other `op`, e.g. `deduce`, `math`), `schema_violation` (unknown predicate for the type, property on the wrong side, filter/sort on a relation).
  - `execute(form, graph) -> Execution`:
    - `Binding(value: entity_id | literal, fact_ids)`; supporting facts accumulate through steps.
    - `StepResult(step_id, op, status, bindings, examined_fact_ids, missing: tuple[(entity_id, predicate)], conflicts)`. Statuses:
      - `ok`: at least one binding;
      - `empty`: the step ran validly and legitimately produced no binding (a filter or sort whose inputs all failed the condition). Not a failure;
      - `unknown_entity`: an entity ref matches no entity;
      - `missing`: a `retrieve` found no fact, or a filter/sort input lacks the property (that input is dropped and listed in `missing`);
      - `conflict`: an input has a `Conflict` on a `one` property; it is dropped and listed. No guessing.
    - `count` returns an int binding. Its facts are the union of its input bindings' facts; over an `empty` input they are the input step's `examined_fact_ids`, so a count of 0 is traceable. `count` over `empty` is `ok` with value 0.
    - `Execution(status: answered|incomplete|conflict, steps, answer, fact_ids, sources)`. `answered` if every step is `ok` or `empty`; otherwise `conflict` if any step is `conflict`, else `incomplete`. `answer` is empty unless `answered`. Sources are the deduplicated evidence spans of `fact_ids`.
  - All iteration in sorted ID order; deterministic.
- Export the names from `__init__.py`.
