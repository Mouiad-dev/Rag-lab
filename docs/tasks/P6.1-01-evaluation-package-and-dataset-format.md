## Goal
A new workspace package `rag-foundry-evaluation` (planned in PROJECT_ARCH.md §5 line 125 and SUMMARY "Where things go"). It holds a versioned, framework-neutral JSON dataset format. - Run `uv lock --offline`. If it fails without network, stop and report it; the orchestrator runs `uv lock`. Then run `uv sync --locked`.
- Create `src/rag_foundry_evaluation/errors.py` with `class EvaluationError(Exception)`. It has a `code: str` attribute and an optional `detail: str`, and `str(e)` returns `"code: detail"`.
- Create `src/rag_foundry_evaluation/dataset.py`. Use frozen pydantic models with `extra="forbid"`.
  - `KEY = r"^[a-z0-9][a-z0-9._-]{0,63}$"`
  - `EvalDocument`: `doc_key` (KEY), `text_sha256` (`^[0-9a-f]{64}$`), `length: int >= 1`.
  - `RelevantSpan`: `doc_key`, `start >= 0`, `end > start`, `grade: int` in 1..3, `quote: str`. Require `len(quote) == end - start`.
  - `EvalCase`: `case_id` (KEY), `question` (1..2000 chars, not blank), `language: Literal["en","ar","mixed"]`, `tags: tuple[Literal["identifier","paraphrase","diacritics","table","ocr"], ...] = ()` (must be sorted and unique), `split: Literal["dev","validation","held_out"]`, `answerable: bool`, `relevant: tuple[RelevantSpan, ...]`, `notes: str = ""` (max 500).
    - An answerable case needs at least one span. An unanswerable case needs none.
    - Two spans of one case on the same doc must not overlap.
  - `EvalDataset`: `format: Literal["rag-foundry.eval-dataset"]`, `format_version: Literal["1"]`, `dataset_id` (KEY), `dataset_version` (`^[0-9]+(\.[0-9]+)*$`), `description` (max 500), `documents` (at least 1, unique `doc_key`), `cases` (at least 1, unique `case_id`).
    - Every span's `doc_key` must be a known document, with `end <= length`.
  - `load_dataset(path) -> EvalDataset`:
    - Decode the file as strict UTF-8.
    - Pre-pass with `json.loads`, using `object_pairs_hook` to reject duplicate keys and `parse_constant` to reject NaN/Infinity.
    - Then call `EvalDataset.model_validate_json(text, strict=True)`.
    - Raise every failure as `EvaluationError("invalid_dataset", <short reason>)`.
  - `canonical_json(obj) -> str`: `json.dumps(obj, ensure_ascii=True, sort_keys=True, separators=(",", ":"))`.
  - `dataset_sha256(ds)`: sha256 of `canonical_json(ds.model_dump(mode="json"))`.
  - `dump_dataset(ds) -> str`: `json.dumps(..., ensure_ascii=True, sort_keys=True, indent=2) + "\n"`.
- `__init__.py`: export these names.

## Tests (`tests/evaluation/test_dataset.py`)
- Build the datasets in `tmp_path` from Python dicts.
- A valid dataset has 2 docs and 3 cases (EN dev, AR validation with the question `"كم مخطوطة؟"`, unanswerable held_out). It loads, and `load(dump(ds)) == ds`. Its sha is stable across two loads.
- Changing one `grade` changes `dataset_sha256`.
- Each of these raises `EvaluationError` with code `invalid_dataset` (one parametrized test):
  - an unknown field
  - a duplicate JSON key
  - `NaN`
  - an answerable case with no spans
  - an unanswerable case with spans
  - `end > length`
  - an unknown `doc_key`
  - a quote length mismatch
  - a duplicate `case_id`
  - split `"test"`
  - overlapping spans `[0,10)` and `[5,12)`
  - tags `["paraphrase","identifier"]`
  - `format_version "2"`
  - a grade given as the string `"1"` (strict)
- Write every Arabic test string as `\u` escapes in the Python source, never as literal Arabic characters. Some tools have turned escapes into literal characters before; check the diff.
