`OllamaChatModel` implements `ChatModel` on Ollama's `POST /api/chat`. `complete` and `stream` both work, and it passes every `CHAT_CHECKS` through `httpx.MockTransport`. Usage is honest: `PROVIDER` only when Ollama reports both counts.

## Change
- Edit `adapters/ollama.py`:
  - `ollama_chat_profile(id="local-chat", model="gemma4:e4b")`:
    - `kind=chat`, `local=True`, `streaming=True`, `context_window=131072` (128K per FREE_MODELS), zero cost rates as in 03;
    - `tool_calling`, `structured_output` and `vision` are `False`, because this adapter does not implement them in P2.2 even though the model card lists tools and vision. Say so in the docstring.
  - `OllamaChatModel(profile, *, api_base, timeout_s=120.0, transport=None, clock=time.perf_counter)`. The constructor raises `ProviderError` if the profile declares `tool_calling`, `structured_output` or `vision` as `True`; there is no silent downgrade.
  - Request: `model`, `messages` as `[{role, content}]`, `stream`, and `think: false` if api.md documents it (thinking text is never returned as answer text). `options.num_predict` / `options.temperature` are sent only when set. Never send `tools` or `format`.
  - `complete`: `check_chat_request(..., streaming=False)`, then `post_json` from 03. `text = message.content`.
  - `stream`: `check_chat_request(..., streaming=True)`. Use `client.stream("POST", "/api/chat", ...)` with the per-call `httpx.Timeout` and iterate `aiter_lines()`; each line is one JSON object.
    - Yield non-empty `message.content` deltas.
    - On `done: true`, yield one final `ChatChunk(delta="", usage=...)`.
    - An `{"error": ...}` line, invalid JSON, or a stream that ends without `done: true` raises `ProviderCallError(bad_response)`.
    - Close the response and client in `finally`, so an early consumer `break` / `aclose()` closes the response.
    - Latency is measured to the end of the stream.
  - `done_reason`: `stop` → `stop`, `length` → `length`; any other value or a missing one raises `ProviderCallError(bad_response)`.
  - Usage: `PROVIDER` only when `prompt_eval_count` and `eval_count` are both non-negative ints. Otherwise estimate both sides with `estimate_tokens` (input = all message contents, output = text) and mark it `ESTIMATED`. A non-empty unknown count is never 0. Operation is `chat` or `chat_stream`.
- Create `tests/providers/test_ollama_chat.py` (`MockTransport`, canned JSON and NDJSON shaped as in api.md):
  - Parametrize `CHAT_CHECKS` for the default profile; the handler answers stream and non-stream requests by the `stream` flag.
  - Request body: no `tools`/`format`; options only when set; per-call timeout present.
  - Usage with and without counts (cover the case where Ollama omits `prompt_eval_count`); the Arabic input estimate is > 0.
  - `length`; an unknown `done_reason` → error; an error line mid-stream → error; a stream that ends without `done` → error.
  - Early `break`: the transport's response stream is closed (assert on a closable test stream).
  - The constructor refuses a profile with `tool_calling=True`; `tools` in the request → `MissingCapabilityError`.
