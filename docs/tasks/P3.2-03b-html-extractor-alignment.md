## Goal
A deterministic HTML extractor parses with a pinned library and builds its offset map by aligning text nodes with the decoded source. Anything it cannot align raises `ExtractionAlignmentError` (`alignment_failed`); offsets are never guessed.

## Change
- **Verify first** (ADR-0010 "Evidence", table as in ADR-0009): `selectolax` using `selectolax.lexbor.LexborHTMLParser` explicitly (not the Modest backend); fallbacks `html5lib`, then `lxml` (list its advisory history). Check official docs, PyPI JSON, GHSA, OSV, OSI-permissive license compatible with Apache-2.0/MIT (bundled native code included), release at least two weeks old, wheels for Windows and Linux on Python 3.12 and 3.13, maintenance, and the APIs used (parse a str, walk nodes in document order, text nodes, tag names). Use the first candidate that passes and record why others were skipped. **Stop and report** if none passes.
- `extract/html.py` (`html`, version `1+<lib>==<pin>+py<python_version>`; Python because `html.unescape` is used). No network, script execution or external entity/DTD loading (lxml: `no_network=True`, `resolve_entities=False`, `load_dtd=False`). Walk text nodes in document order; skip `head`, `script`, `style`, `template`, `noscript` content.
- Alignment (cursor over the decoded source). For each text node character, try in order:
  1. CP: the source character equals it. Source `\r\n` or `\r` against node `\n` is one `ATOMIC` segment. Source U+0000 is allowed only as a detached deletion or as a `CP` match to U+FFFD (follow the library's actual behaviour).
  2. Entity: anchored regex `&(#[0-9]+;?|#[xX][0-9a-fA-F]+;?|[A-Za-z][A-Za-z0-9]*;?)` at the cursor whose `html.unescape` equals the next node characters -> one `ATOMIC` segment.
  3. Skip: otherwise skip one markup token or one whitespace character the parser dropped (detached deletion), then retry. Anything else -> `alignment_failed`.
- Skipper. A markup token starts only at `<` + ASCII letter, `</` + ASCII letter, `<!` or `<?`; any other `<` is literal text.
  - Tags end at `>` outside quoted attribute values (single or double quotes may contain `>`).
  - Comments `<!-- ... -->`, also `<!-->`, `<!--->` and ending `--!>`; other `<!...>` up to `>`.
  - Bogus comments `<?...>` and `</` + non-letter up to `>`.
  - Raw text and RCDATA elements `script, style, title, textarea, noscript, xmp, iframe, noembed`: content of skipped elements is skipped up to `</name` (case-insensitive) followed by whitespace, `/` or `>`. `title` and `textarea` text nodes, if the library emits them, align normally.
  - After the last node, the rest of the source must be fully skippable, else `alignment_failed`.
  - Known limits (script double-escaping, CDATA in svg/math) must raise `alignment_failed`, never mis-align.
- Blocks: `p, div, li, pre, blockquote, h1-h6, td, th, section, article, header, footer, br` end a block; separators `\n\n` are insertions; whitespace runs outside `pre` collapse to one space (`ATOMIC`); headings use the Markdown `section_path` rule; then `base.finish(...)`.
- Tests `tests/ingestion/test_extract_html.py`:
  - Exact source offsets for: `<a title="hello">hello</a>`; `<!--hello-->hello`; `<title>hi</title><p>hi`; `<p title='a>b'>b</p>`; `<script>x</script>x`; literal `a < b` and `a<3`; `<pre>\n\nx` and `<textarea>\nx` (first LF dropped by the parser, text aligns to the second LF or to `x` as asserted); CDATA inside `<svg>` (alignment or `alignment_failed`, asserted).
  - Per `raw_map` segment: `CP` slices equal; entity segments equal `html.unescape(source slice)`; whitespace segments whitespace on both sides; deletions are markup or dropped whitespace.
  - Entities `&amp;`, `&#x627;`, `&nbsp;`, `&#0;`, `&#xD800;`, `&#x110000;`, `&#x80;`, `&ampx`, `&notit;` (expected = `html.unescape` of the matched slice, or `alignment_failed` if the library decodes differently; asserted). NUL in text (actual library behaviour asserted). CR and CRLF.
  - Foster parenting `<table><tr><td>a</td></tr>x</table>`: `alignment_failed`, or correct alignment if the library keeps source order (assert which). Head without `</head>`; unclosed tags; Arabic and mixed headings.
  - Same bytes twice give equal results; 1 MiB pathological HTML (unterminated `<` runs, deep nesting) finishes under 5 s.

- Deviations: (1) Entity is tried before CP when the source char is `&` (an entity whose `html.unescape` is a prefix of the node text wins), so `&amp;amp;` aligns correctly; otherwise CP-first as specced. (2) `<pre>\n\nx` aligns the text LF to the first source LF and drops the second as whitespace (spec allowed either). (3) Text under svg/math raises `alignment_failed` only when the source contains `<![CDATA[` anywhere (the check is global, not per element). (4) A typed stub is registered when the `html` extra is missing (same as PDF). (5) Library limit: selectolax/Lexbor parsing is quadratic on one huge run of `<` (1 MiB: 5.5 s) and on very deep nesting (60k nested divs: 4.5 s). The pathological test therefore uses about 1 MiB of bounded mixed parts. No guard was added (no error code fits); owner/planner should decide a size or depth guard.
- Review round 1 fixes: (a) entities are decoded only when the nearest open element is not raw text (script, style, xmp, iframe, noembed, noframes, noscript, plaintext keep `&amp;` literal; title and textarea decode); `noframes` and `plaintext` added to the raw-text tags. (b) Foster parenting (final rule after review round 2): any foster-parented text raises `alignment_failed`, i.e. whenever the skipper has consumed more `<table` start tags than the walk has entered after aligning a node. Even `<table>x<tr>` now fails, because the gap rule could not exclude swaps between equal texts (`<table>x<tr><td>y</td></tr>y</table>`). Normal tables (attribute values containing `<table`, caption, th, nested, pretty-printed) still align. (c) Fast path and CP matching no longer match a source `<` that starts markup, except right after a raw-text start tag or inside raw-text elements, so `<textarea>&lt;</textarea>` aligns (canonical 0..1 maps to source 10..14).
- Note: the full Python patch version in `extractor_version` is intentional and conservative (`html.unescape` tables can change between patch releases).
- Known false failures (safe): any foster-parented text; literal markup inside textarea or title content (for example `<textarea><b>x</b></textarea>`) fails. `<select><table></select><table>...` aligned in the test.
- Not done on purpose: parser-cost guard (owner decision pending); see deviation 5.
