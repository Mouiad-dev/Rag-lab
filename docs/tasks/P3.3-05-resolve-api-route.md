A scoped HTTP route resolves a bounded batch of anchors and returns `AnchorResolveResponse` v1.0. The API only reads stored payloads; it never extracts (ADR-0010 D4).

## Change
- `apps/api/pyproject.toml`: direct `rag-foundry-contracts` workspace dependency; `uv lock`.
- `settings.py`: `provider_namespace: str = "rag-foundry-local"`, pattern `^[a-z0-9][a-z0-9._-]{0,63}$`.
- `apps/api/src/rag_foundry_api/anchors.py`: handler takes `AnchorResolveRequest` JSON; `scope = auth.scope_for(project_id)`; `app.state.anchor_service` None -> 503 `storage_unavailable`; returns `AnchorResolveResponse`. Registered with `add_api_route` (same pattern as documents). Test: an anchor with a 257-char `anchor_id` returns 422 (request validation), not 500.
- `errors.py`: an `AnchorError` handler (more specific than any `IntakeError` handler): `too_many_views` -> 422 with code `too_many_views` in the standard error envelope; other `AnchorError` codes -> 422 with their code. Message carries no text.
- `limits.py`: every POST that is not an upload path gets a 1 MiB cap (Content-Length and streamed count) -> 413 `request_too_large`; upload paths keep their current limit and behavior.
- `main.py`: `create_app(..., anchor_service=None)`; when built from settings, also build `SqlExtractionRepository` (same sessionmaker) and `AnchorService(LocalObjectStore(...), views, provider_namespace=settings.provider_namespace)`.
- `tests/api/test_anchors.py` (TestClient, in-memory repos + LocalObjectStore; view made with `ExtractionService`, anchors with `AnchorService`): exact en and ar results (Arabic text round-trips as code points); a tampered anchor -> 200 with `mismatch/quote_mismatch`; unknown project -> 404; `environment=prod` -> 401; 101 anchors -> 422; 11 views -> 422 with envelope code `too_many_views`; body over 1 MiB -> 413 `request_too_large` before the service is called (and the same cap on another non-upload POST path); uploads still accept bodies over 1 MiB up to their limit; major version 2 -> 422; service missing -> 503; response contains no object key or filesystem path; the literal `:resolve` path routes (no fallback path).

## Constraints
- Scope only from auth; anchor `source` fields are never authority. Unknown and out-of-scope views look the same.
- No text in logs. No new third-party dependency. Do not change upload routes or their limits.
