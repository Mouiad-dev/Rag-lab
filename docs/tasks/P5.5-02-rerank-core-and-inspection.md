## Goal
Two pure, offline-tested modules that R19/R20 and the lab will use:
- `rerank.py` reorders or drops given candidates, never adds one, and records before/after ranks per hit.
- `inspection.py` builds a scope-checked, read-only inspection object with per-stage candidates and rank changes. It dumps to JSON and loads back from it.

HTTP is deferred. `apps/api` has only `POST /runs`, and no retrieval run is stored anywhere. There is no run table or repository, and `RunResponse` holds evidence only. So there is nothing to read back over HTTP yet.

## Change
- `errors.py`: add these `IndexingError` codes: `rerank_invalid_input`, `rerank_too_many_candidates`, `rerank_invalid_order`, `rerank_added_candidate`, `rerank_wrong_model_kind`, `inspection_empty`, `inspection_version_mismatch`.
- Create `rag_foundry_indexing/rerank.py` with frozen pydantic models (`extra="forbid"`):
  - `RankChange`: `chunk_id`, `extraction_view_id`, `start`, `end`, `before_rank: int | None`, `after_rank: int | None`, `before_score: float | None`, `after_score: float | None`, and `moved: int | None` (before minus after; positive means it moved up; None if either rank is None).
  - `RerankTrace`: `technique_id`, `input_technique_id`, `status: Literal["applied", "rejected"]`, `reason: str | None`, `profile_id`, `model`, `input_count`, `output_count`, `dropped: tuple[str, ...]` (chunk ids), `unranked: tuple[str, ...] = ()`, `usage: tuple[Usage, ...]`, `prompt_sha256: str | None = None`.
  - `RerankedRetrieval`: `trace`, `input: RetrievalResult`, `result: RetrievalResult`, `changes: tuple[RankChange, ...]`.
  - `rank_changes(before, after, *, allow_added: bool)`:
    - Returns one row per chunk in `before`, in before order, then any added chunks.
    - If `allow_added` is False and `after` has a chunk id that is not in `before`, raise `rerank_added_candidate`.
    - If a shared chunk id has a different view, start or end, also raise `rerank_added_candidate`.
  - `apply_order(input, order, *, technique_id, scoring)`:
    - `order` is a sequence of `(input_index, score, extra_components)`. Indices outside range or repeated raise `rerank_invalid_order`.
    - Each output hit copies every provenance field of its input hit unchanged: `chunk_id`, view, start, end, `block_ids`, `text`, `distance`, parent span.
    - Each output hit gets rank 1..n and the new score. Its components are the input components, then `ScoreComponent(name="input_rank", value=float(rank), source=input.technique_id, source_rank=rank)`, then the extras.
    - `grounding` and `index_version_id` stay unchanged.
    - Returns `(result, changes, dropped_ids)`.
  - `check_rerank_input(result, max_candidates)`: run `check_single_input`, and map its error to `rerank_invalid_input`. More hits than `max_candidates` raises `rerank_too_many_candidates`.
- Create `rag_foundry_indexing/inspection.py`:
  - `InspectionStage`: `name: Literal["retrieve", "fuse", "select", "transform", "rerank"]`, `technique_id`, `scoring`, `candidates: tuple[RetrievedChunk, ...]`, `changes: tuple[RankChange, ...]`.
  - `RetrievalInspection`: `inspection_version: Literal["1"] = "1"`, `index_version_id`, `question`, `stages`.
  - `async def inspect_retrieval(scope, index, question, stages: Sequence[tuple[str, RetrievalResult]])`:
    - No stages raises `inspection_empty`. Any stage that is not corpus-grounded, or that has a different index version, raises `inspection_version_mismatch`.
    - Then `await index.get_index_version(scope, version_id)` rechecks scope. A foreign scope propagates the repository error.
    - The first stage has empty `changes`. Every later stage has changes against the previous stage, with `allow_added = name != "rerank"`.
    - The function never mutates its inputs.
- Export the new names from `__init__.py`.

## Tests (`tests/indexing/test_rerank_core.py`, `test_inspection.py`)
- Input: hits a (rank 1, score 3.0), b (rank 2, score 2.0), c (rank 3, score 1.0), all from technique `R02`. Apply `apply_order` with order `[(2, 0.9, ()), (0, 0.5, ())]`. Expected:
  - result ids `["c", "a"]`, ranks `[1, 2]`, scores `[0.9, 0.5]`;
  - `dropped == ("b",)`;
  - changes as `(id, before_rank, after_rank, moved)`: `[("a", 1, 2, -1), ("b", 2, None, None), ("c", 3, 1, 2)]`;
  - `input_rank` values `[3.0, 1.0]` with `source == "R02"`;
  - every provenance field equal to the input hit.
- Index 3 (out of range) raises `rerank_invalid_order`, and so does a repeated index.
- `rank_changes` with an added id and `allow_added=False` raises `rerank_added_candidate`. A same-id hit with a changed `start` also raises it.
- Inspection over `ready_index`:
  - stages `retrieve` → `rerank` (built with `apply_order`): `RetrievalInspection.model_validate(json.loads(x.model_dump_json())) == x`, and stage 2 changes equal `rank_changes`.
  - The `stranger` scope raises the repository's not-found error.
  - A forged rerank stage with an extra chunk raises `rerank_added_candidate`.
  - A mixed index version raises `inspection_version_mismatch`.
