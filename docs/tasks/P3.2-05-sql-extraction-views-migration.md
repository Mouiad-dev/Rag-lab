## Change
- Migration `0002_extraction_views` (down_revision `0001_document_intake`):
  - `UNIQUE(tenant_id, project_id, document_id, id)` on `document_versions` (FK target).
  - Table `extraction_views` with all `ExtractionView` fields; `warnings text[]`; composite FK `(tenant_id, project_id, document_id, document_version_id)` -> `document_versions`; `UNIQUE(document_version_id, extractor, extractor_version, profile_id, unicode_version)`; CHECKs: sha256 formats, `char_count >= 1`, `block_count >= 1`, `page_count IS NULL OR page_count >= 1`, `payload_schema_version = 1`, extractor pattern; index `(tenant_id, project_id, document_version_id, created_at)`; `created_at` default `clock_timestamp()`.
  - Trigger raising on any `UPDATE` of `extraction_views` (same style as 0001). Downgrade drops trigger, table and the added constraint.
- `models.py`: ORM model matching the migration (same names).
- `sql/extraction_repository.py` `SqlExtractionRepository(sessionmaker)`: one session per call; every query filters by tenant and project; `find_view` by identity key; `create_view_or_get` takes `pg_advisory_xact_lock(hashtextextended('view:' || :document_version_id, 0))`, re-reads by key inside the lock, checks the version exists in scope (else `NotFoundError`), inserts; malformed IDs -> `NotFoundError` (or `None` from `find_view`).
- Its factory returns the `(DocumentRepository, ExtractionRepository)` pair built from one sessionmaker.
- `create_view_or_get` checks the version together with its document (scoped) before inserting and raises `NotFoundError`; it does not rely on the FK.
- Tests `tests/storage/test_sql_extraction_repository.py` (`db` marker, skipped without `RAGF_TEST_DATABASE_URL`): migrate to head; factory truncates and seeds scopes; run every check; `UPDATE extraction_views` raises; another scope's version is rejected by the FK; `downgrade 0001_document_intake` then `upgrade head`.
