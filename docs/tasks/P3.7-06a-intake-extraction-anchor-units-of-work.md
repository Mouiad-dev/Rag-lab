## Goal
`IntakeService`, `ExtractionService` and `AnchorService` take a `UnitOfWorkFactory` instead of repositories and own their transaction boundaries (ADR-0015 D6). No UoW is open while bytes stream or during any object-store call. The 00 tests pass unchanged.

## Change
- `IntakeService(store, uow, *, max_bytes)`: one read UoW for `project_exists` + `get_document`, closed before staging; stream and object-store `stage`/`commit`/`discard` with no UoW; one write UoW for `create_document_or_get` / `add_version_or_get`, committed before returning; discard-on-error unchanged. New `get_version(scope, document_id, version_id)` (read UoW) used by the `get_version` route; delete `get_document_repository`, `DocumentsDep` and `AppContainer.documents`.
- `ExtractionService(store, uow, ...)`: keep today's order; reads (document version, existing view) in a read UoW closed before reading the original bytes, extraction work and payload storage; `create_view_or_get` in its own write UoW after the payload is stored.
- `AnchorService(store, uow, *, provider_namespace)`: each public method first reads all view rows it needs in one read UoW (for `resolve`, collect the distinct view ids, then read them), closes it, then reads payloads from the object store and computes anchors. Same results and error codes, same order of checks per anchor.
- Wiring: `container.py`, `extract_cli.py`, `ask_cli.py`, `index_cli.py` construct these services with `db.uow` (no `per_call_documents` / `per_call_extractions` left for them).
- Tests: update constructions in `tests/ingestion/*`, `tests/api/test_documents.py`, `test_anchors*.py`, the 00 `_build` (wrap the existing in-memory repos with `InMemoryUnitOfWorkFactory(...)`; assertions unchanged). New cases with the in-memory counters and a recording object store: `open_now == 0` inside the upload iterator and inside every `ObjectStore.stage`, `commit`, `discard`, `open_read` call (ingest, extraction, all three anchor methods); intake for an unknown project never opens a write UoW; each successful ingest commits exactly once; an extraction failing after the payload write opens no write UoW for the view; `resolve` over 3 anchors from 2 views opens exactly 1 read UoW.

## Constraints
