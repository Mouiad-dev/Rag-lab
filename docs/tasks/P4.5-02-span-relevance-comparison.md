## Goal
A deterministic, model-free report compares chunkers on a bilingual local fixture by how well their chunk spans cover labelled relevant source spans (rule 20: chunk IDs change between indexes, so relevance is by source span). Same inputs give byte-identical JSON and Markdown; a committed report is checked for drift.

## Change
- Create fixture `tests/fixtures/span_relevance/v1/` (UTF-8, LF, no BOM, NFC): `guide.md` (~3000-5000 code points; Markdown with `#`/`##` headings; English sections, Arabic sections with diacritics and Arabic punctuation, one mixed section; one fact repeated in two places), `cases.json` = `{"version": 1, "cases": [{"case_id", "cohort": "en"|"ar"|"mixed"|"unanswerable", "query", "relevant": [{"doc": "guide.md", "quote": str, "occurrence": int = 0}]}]}` with >= 12 cases: >= 3 per answerable cohort, >= 2 cases with two relevant spans, >= 1 relevant span longer than 400 code points, 1 unanswerable case (`relevant: []`). `chunkers.json`: `[{"label", "technique_id", "config"}]` for C01 (400 chars), C02, C03, C04, C05, C06, C07, C08, C21 at a comparable size (~400 code points; state the unit of each in the label), C18 (`parent_size` 1600, `child_size` 400), and C15, C16, C17, C19 with `{}`.
- Create `packages/chunking/src/rag_foundry_chunking/comparison.py`:
  - `load_span_fixture(dir) -> (docs: dict[str, str], cases, chunkers)`: each quote is located by exact match at the given `occurrence`; a missing quote or an occurrence index past the last match raises `ValueError` naming the case (no fuzzy matching). Offsets are code points.
  - Pure span metrics per relevant span `r` and chunk list: `best_coverage = max |c intersect r| / |r|`, `best_precision = |c intersect r| / |c|` of that best chunk (tie: shorter chunk), `contained` (one chunk covers `r` fully), `pieces` (chunks overlapping `r`).
  - `LexicalOverlapRanker`: tokens = `re.findall(r"\w+", view)` on the `normalize_with_map` view, casefolded; score = shared distinct query tokens / sqrt(distinct chunk tokens); ties by chunk start. Docstring and report call it "lexical token overlap (not BM25)". Do not use the fake embedding provider for ranking (hash vectors carry no meaning).
  - Ranked metrics at k in (1, 3, 5), with `min_coverage = 0.8`: a relevant span is covered at k when the union of the top-k chunks covers >= 80% of it. `span_recall@k` = covered spans / relevant spans of the case; `hit@k` = 1 if any span covered; `mrr` = 1 / first k at which any span is covered (0 if none by k=5); `context_chars@k` = total code points of the top-k chunks. Unanswerable cases report only `context_chars@k` and top-1 score; they are excluded from recall/hit/MRR denominators, and the report says so.
  - A chunker whose plugin has `chunk_hierarchy` also gets a row `"<label> + parent expansion"`: ranked children mapped to their parents (dedupe, keep order) before metrics. Detect by attribute, not by technique ID. Label it "offline span metric, not R22/R25".
  - `compare_chunkers(docs, cases, chunkers, registry) -> ComparisonReport` (pydantic, frozen): per case x chunker rows; per chunker x cohort means with explicit `n`; status per chunker: `ok`, `not_applicable` (`StructureParseError` code), `requires_models` (`TechniqueUnavailableError`). Never drop a chunker.
  - `render_markdown(report) -> str`: method, fixture version, metric definitions and denominators, a per-cohort table, per-case table, and a "Limits" section (one small authored fixture, lexical ranker, no answer quality). Deterministic: floats rounded to 4 places, sorted keys.
  - CLI `python -m rag_foundry_chunking.comparison <fixture_dir> --catalogue config/techniques.json --out <dir>` writes `span_comparison.json` and `span_comparison.md` (UTF-8, LF).
- Run the CLI and commit the output to `docs/evidence/P4.5/`.
- Create `tests/chunking/test_comparison.py`: hand-computed metrics on a 3-chunk toy text (coverage, precision, contained, pieces, recall@k with two relevant spans, mrr, an unanswerable case); missing quote and bad occurrence raise; Arabic NFD query matches NFC chunk tokens; ranker ties by start; `requires_models` for C15 and `ok` for C18 plus its parent-expansion row; two runs give identical JSON; committed `docs/evidence/P4.5/span_comparison.json` and `.md` equal a fresh run (drift message says to rerun the CLI).
