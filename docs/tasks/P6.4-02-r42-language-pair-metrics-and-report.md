## Goal

- The P6.1 `aggregate()` output and the existing evidence files do not change.

## Change
- **`dataset.py`:** add `"name"`, `"negation"` and `"number"` to the `tags` Literal. This is additive only. Do not add them to the `aggregate` group names.
- **`metrics.py`:** move the body of the per-group loop into `summarize_group(split, group, members, ks) -> GroupSummary`. `aggregate` calls it, and its output must stay identical.
- **Create `packages/evaluation/src/rag_foundry_evaluation/languages.py`:**
  - `script_language(text) -> Literal["en", "ar", "mixed", "unknown"]`:
    - only characters in general categories `Lu`, `Ll`, `Lt` or `Lo` count; `Lm` (so tatweel), marks and digits are ignored;
    - `a` = letters whose `unicodedata.name` contains `ARABIC`; `l` = letters whose name contains `LATIN`;
    - `a + l == 0` gives `unknown`; the share `a/(a+l) >= 0.8` gives `ar`; `<= 0.2` gives `en`; anything between gives `mixed`;
    - docstring: "Latin script is labelled en; this is script detection, not language identification."
  - `document_language(case)`: `none` when the case is unanswerable. Otherwise take the set of `script_language(span.quote)`: one value is returned as is; several values give `mixed`.
  - `language_pair(case) -> str`: `f"{case.language}->{document_language(case)}"`.
  - `aggregate_language_pairs(rows, ks) -> tuple[GroupSummary, ...]`: for each split present (order dev, validation, held_out), one `summarize_group` per pair, sorted by the pair string, with `group=f"pair:{pair}"`.
  - `language_pair_summaries(results: dict, dataset) -> dict[str, tuple[GroupSummary, ...]]`: recompute `case_metrics` from the hits in `results["cases"]`, using the config `ks` and `coverage_threshold`, per label in config order. Error rows count as errors.
  - `render_language_pairs(results, dataset) -> str`:
    - a `## Language pairs` heading and one definition line;
    - per label, a `### <label>` table with the columns `split | pair | n_cases | n_answerable | n_unanswerable | n_errors | HitRate@k... | Recall@k... | MRR`. The pair cell drops the `pair:` prefix. Use `_num` / `_at` / `_table` from `report.py`;
    - then a `### Per case` table with the columns `case | label | pair | tags | found_ranks | RR`.
- Export the new names.
