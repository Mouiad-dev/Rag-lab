## Goal
`rag_foundry_core.settings.Settings` loads typed configuration from init arguments, `RAG_FOUNDRY_*` environment variables and an optional `.env` file. Unknown keys are rejected, a test proves it, and the code contains no secrets.

## Read only these files
- `pyproject.toml` (root workspace, from P1.1-01)
- `packages/core/pyproject.toml`
- `packages/core/src/rag_foundry_core/__init__.py`
- pydantic-settings docs: `SettingsConfigDict`, `extra`, `env_prefix`, `env_file`, `SecretStr` (docs.pydantic.dev/latest/concepts/pydantic_settings/)

## Change
- Edit `packages/core/pyproject.toml`. Add the runtime dependencies `pydantic` and `pydantic-settings` with `>=` the currently resolved versions, then run `uv lock`.
- Create `packages/core/src/rag_foundry_core/settings.py`:
  - `class Settings(BaseSettings)` with `model_config = SettingsConfigDict(env_prefix="RAG_FOUNDRY_", env_file=None, extra="forbid", frozen=True)`.
  - Fields with safe defaults only:
    - `environment: Literal["dev", "test", "prod"] = "dev"`
    - `log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = "INFO"`
    - `api_host: str = "127.0.0.1"`
    - `api_port: int = Field(8000, ge=1, le=65535)`
    - `worker_poll_seconds: float = Field(5.0, gt=0)`
  - `def load_settings(env_file: str | None = None) -> Settings`. Passing `_env_file` lets tests and the apps choose a file explicitly.
  - Add a module docstring stating that future secrets must be `SecretStr` fields read from the environment and must never get defaults.
- Create `tests/core/test_settings.py` with these tests:
  - Defaults load when no environment is set. Use `monkeypatch` to clear `RAG_FOUNDRY_*`.
  - An env override works (`RAG_FOUNDRY_API_PORT=9001` gives `9001`).
  - **An unknown init key raises `ValidationError`.**
  - **An unknown key in an env file (`tmp_path/.env` with `RAG_FOUNDRY_NOT_A_FIELD=1`) raises `ValidationError`.**
  - An invalid value (`api_port=0`, `environment="staging"`) raises `ValidationError`.
  - Settings are frozen: assigning to a field raises.

## Constraints
- No secret fields, no default credentials, no database URL yet (P1.3 adds them).
- Check against the docs whether unknown *process* env vars with the prefix are rejected or ignored under `extra="forbid"`. Record the actual behaviour in the module docstring and under Deviations. Do not claim behaviour you have not tested.
- No vendor or model SDKs. Do not import FastAPI in core.
