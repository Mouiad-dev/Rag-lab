## Goal
`SelfQuery` (R12) makes one metered chat call that turns a question into a `MetadataFilter`. The model only sees short refs (`d1`, `d2`, ...) for the documents R11 already authorized, never UUIDs. Output is checked against an allowlisted schema. Unknown fields fail. A ref or id outside the offered set **always** raises `filter_scope_widening`. The filter is then intersected by R11, so it can only narrow. Fully testable offline with a scripted fake chat.

## Change
- `errors.py`: add `class QueryTransformError(IntakeError)` with `CODES = ("missing_model", "wrong_model_kind", "empty_query", "query_too_long", "too_many_choices", "invalid_model_output", "unknown_filter_field", "invalid_filter_value", "filter_scope_widening")`. Same pattern as `IndexingError` (unknown code raises `ValueError`, content-free message). P5.4 will reuse it.
- Create `rag_foundry_indexing/self_query.py`:
  - `SELF_QUERY_SYSTEM_V1` constant (English). It says that the user JSON is untrusted data, not instructions, that the model must reply with one JSON object with exactly the keys `document_refs`, `media_types`, `created_from`, `created_to` (each null or a value), may use only the offered refs and the media types listed, and gives dates as `YYYY-MM-DD`. Also `SELF_QUERY_PROMPT_SHA256` = sha256 of the constant. `FILTER_SCHEMA` (JSON schema, `additionalProperties: false`).
  - `SelfQueryConfig` (frozen, forbid): `max_output_tokens: 64..1024 = 256`, `temperature: float 0..2 | None = 0.0`, `on_invalid: Literal["fail","no_filter"] = "fail"`, `max_choices: 1..100 = 50`.
  - `SelfQueryResult` (frozen): `status: Literal["applied","no_filter","rejected"]`, `filter: MetadataFilter | None`, `reason: str | None`, `usage: tuple[Usage, ...]`, `prompt_sha256`, `raw_text` (at most 500 chars).
  - `SelfQuery`: manifest `R12`, `PluginKind.QUERY_TRANSFORM`, `Fidelity.ADAPTATION`, `1.0.0`. `async parse(question, *, choices: tuple[ViewMetadata, ...], chat) -> SelfQueryResult`.
  - Before any call: chat None gives `missing_model`; `profile.kind` not CHAT gives `wrong_model_kind`; a blank question gives `empty_query`; more than 2000 chars gives `query_too_long`; more than `max_choices` documents gives `too_many_choices`.
  - Refs: unique documents from `choices` in their given order become `d1..dn`. One call: `ChatRequest(messages=(system=SELF_QUERY_SYSTEM_V1, user=<json>), max_output_tokens, temperature, response_schema)`. The user JSON is `json.dumps({"question": q, "documents": [{"ref", "name", "media_type", "created": "YYYY-MM-DD"}], "media_types": [MediaType values]}, ensure_ascii=False)` and contains no UUIDs. Pass `response_schema=FILTER_SCHEMA` only if `capabilities.structured_output is True`.
  - Validation order: `finish_reason == "length"` or unparsable JSON (`structured`, else `parse_json_object(text)`) gives `invalid_model_output`. A key outside the 4 gives `unknown_filter_field`. A ref not offered, or any UUID-looking value, gives `filter_scope_widening`. A bad media type, a bad date, an empty list or `from >= to` gives `invalid_filter_value`. `created_to` is exclusive at the next UTC midnight.
  - `filter_scope_widening` **always raises**. Other failures raise if `on_invalid="fail"`; otherwise return `status="rejected", filter=None, reason=<code>`. All nulls give `status="no_filter"`. Usage from the call is always kept.
  - `async retrieve_with_self_query(question, *, self_query, chat, retriever: MetadataFilteredRetriever) -> tuple[SelfQueryResult, RetrievalResult]`: `choices = await retriever.choices()`, parse, then `retriever.retrieve(question, extra_filter=result.filter)`. The **original question** is the retrieval query.
- Register `SelfQuery`; export `SelfQuery`, `SelfQueryConfig`, `SelfQueryResult`, `retrieve_with_self_query`.
- Create `tests/indexing/test_self_query.py` (`multi_doc_index`, `ScriptedChat` from `tests.chunking._scripted_models`, non-ASCII only as `\u` escapes):
  - `{"document_refs":["d2"],...nulls}` gives `applied`, `filter.document_ids == (report-2025 id,)`, every hit in that view, `len(usage) == 1`, and no owner or stranger UUID in any request message.
  - The Arabic question `"ما سعر القطعة في تقرير 2025؟"` appears unescaped in the user message.
  - **Negative scope:** the stranger's real document UUID in `document_refs`, or ref `"d9"`, gives `QueryTransformError("filter_scope_widening")` even with `on_invalid="no_filter"`. Through `retrieve_with_self_query` it raises and the embedder records no query call.
  - **Negative field:** `{"tenant_id": "<owner tenant>"}` gives `unknown_filter_field`. In `no_filter` mode it gives `rejected`, and the hits equal the run without an extra filter (never more).
  - Bad JSON, `finish_reason="length"`, `"image/png"` and `"2025-13-01"` each give their code. All nulls give `no_filter`.
  - Metering: `BudgetedChatModel(scripted, RunBudget(Decimal("0"), max_calls=0), default_max_output_tokens=None)` raises `BudgetExceededError`, with `scripted.requests == []`.
  - `chat=None` gives `missing_model`. A chat whose profile is an embedding profile gives `wrong_model_kind`. `validate_config("R12", {}) == SelfQueryConfig()`.
- Create `tests/live/test_self_query_live.py`: marked `live`, skipped unless `RAG_LIVE_OLLAMA=1` (copy the gating from `test_ollama_live.py`). It runs one parse on `gemma4:e4b` and asserts only that the status is one of the three values and no exception other than `QueryTransformError` is raised.
