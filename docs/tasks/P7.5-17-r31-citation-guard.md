## Goal
An R31 answer cites a passage only when the model's own reflection tokens say the passage is relevant and supports the answer. The official short-form selection (best total score) is unchanged; only the citation is guarded. Motivation: in the P7.5-16b llama.cpp live run the unanswerable and Arabic answers cited the only chunk although the model generated `[Irrelevant]` and no support token (`docs/evidence/P7.5/self_rag_live.md`, "Losing case").

## Change
- `SelfRagConfig.citation_guard: bool = True` (owner decision 2026-11-24; a documented deviation from the official procedure, stated in the module docstring).
- After the official selection of the best candidate, when `citation_guard` is on, cite it only if both hold, judged from the tokens the model generated in that candidate (id match when ids are present, else text, as elsewhere in the module):
  1. the relevance token generated at position 0 is `[Relevant]`;
  2. a support token was generated and it is `[Fully supported]` or `[Partially supported]`.
- If the guard fails: `status="answered"`, the answer text unchanged (reflection tokens stripped as today), `grounding="ungrounded"`, `citations=()`. The trace gets `citation_guard: {"enabled": true, "cited": false, "reason": "irrelevant" | "no_support_token" | "not_supported"}` (`irrelevant` wins when both fail; `not_supported` = `[No support / Contradictory]`) and `answer_grounding: "ungrounded"`. When it passes: `{"enabled": true, "cited": true, "reason": null}`. When off: `{"enabled": false, ...}` and today's behaviour.
- No change to scoring, candidate selection, counters or the rule (d) metrics.

## Tests (`tests/answering/test_self_rag.py`)
- Chosen candidate `[Irrelevant]` + `[Fully supported]` -> no citation, reason `irrelevant`, grounding ungrounded, answer text kept.
- `[Relevant]` with no support token -> no citation, reason `no_support_token`.
- `[Relevant]` + `[No support / Contradictory]` -> reason `not_supported`.
- `[Relevant]` + `[Partially supported]` -> cited (exactly one citation, the chosen hit's view and offsets).
- `citation_guard=False` -> the `[Irrelevant]` case is cited as before.
- Id mode: a generated token with text `[Relevant]` but a non-reflection id does not satisfy rule 1.
- Selection unchanged: with two hits where the higher total fails the guard, the answer is still that candidate's text, uncited (no re-selection).
