## Goal

## Change
- `errors.py`: add `"html_too_complex"` to `ExtractionError.CODES` and to the class docstring. This is the only code enumeration: no SQL check, JSON schema, contract or API mapping lists extraction codes (API falls back to 422 by class; worker CLI prints `exc.code`). `tests/domain/test_extraction.py` loops over `CODES`, so it needs no edit.
- `html.py`: add `_check_complexity(src: str) -> None` and call it in `extract` right after `decode_text` and before `LexborHTMLParser(src, ...)`, with the same `src` object. Module constants `_MAX_LT_RUN = 256`, `_MAX_DEPTH = 4096`. Message is fixed text (for example "HTML structure is too complex to parse"), never content. Leave `extractor_version` unchanged (accepted output does not change). Update the module docstring with one line about the guard.
  1. Run: `"<" * _MAX_LT_RUN in src` -> raise. (`str.__contains__`, linear; no regex.)
  2. Depth estimate: one forward pass. Jump between tags with `src.find("<", pos)`; the position only moves forward.
     - `<!--`: skip past `-->` or `--!>` (also `<!-->` and `<!--->`), or to the end of the input. Other `<!`, `<?`, or `</` + non-letter: skip past the next `>`.
     - `</` + ASCII letter: end tag (reuse the quote-aware `_tag` logic; refactor it to a module function if needed, no behaviour change for `_Aligner`). If the name is counted, `depth = max(0, depth - 1)`. `svg`/`math` also decrement a `foreign` counter (clamped at 0).
     - `<` + ASCII letter: start tag. Not counted if the name is void (`area base basefont bgsound br col embed frame hr img input keygen link meta param source track wbr`) or has an optional end tag (`html head body p li dt dd option optgroup tr td th thead tbody tfoot colgroup caption rb rt rtc rp`). A tag ending in `/>` is not counted when `foreign > 0` or the name is `svg`/`math` (closed in foreign content); elsewhere the slash is ignored, as HTML does. Otherwise `depth += 1` (and `foreign += 1` for `svg`/`math`); if `depth > _MAX_DEPTH` raise at once.
     - After a counted raw-text start tag (`_RAW_TEXT_TAGS`), jump to `_raw_end(name).search(src, end)`; if none, stop scanning.
     - Any other `<` is literal: continue at `pos + 1`.
  - Linear time, no backtracking regex (only `str.find`, `in`, and the existing anchored, non-nested patterns).
- `test_extract_html.py`: update the comment in `test_pathological_inputs_finish_quickly` (inputs with long `<` runs now fail with `html_too_complex`; the test stays). Add tests:
  - `"a" + "<" * 255 + " b"` does not raise `html_too_complex`; `"<" * 256` inside text does.
  - `"<div>" * 4096 + "x"` passes the guard; `"<div>" * 4097 + "x"` raises. Same with closing tags: `("<div>" * 4096 + "x" + "</div>" * 4096) * 3` passes.
  - Not counted: 10,000 each of `<br>`, `<img src=a>`, `<p>x`, `<li>x`, `<td>x`; `<svg>` + `<path d='1'/>` * 10,000 + `</svg>`; `<div>` * 5,000 inside `<script>`, `<textarea>` and `<!-- -->`. `<div/>` * 4097 outside svg raises.
  - `"</div>" * 5000 + "<div>" * 4097` raises (no negative depth credit).
  - 5 MiB: with `ExtractionLimits(max_chars=6 * 2**20)`, `"<" * (5 * 2**20)` and `"<div>" * 2**20` raise `html_too_complex` in under 1 s, and `html_mod.LexborHTMLParser` (monkeypatched to fail) is never called. With default limits, `"<div>" * 999_000` raises `html_too_complex`.
  - Same text: bytes `b"\xef\xbb\xbf" + b"<" * 256` with `text_encoding="utf-8-sig"` raise; a spy shows the guard and the parser get the identical `src` object.
  - `_check_complexity` on `"<div>a</div>" * 400_000` returns in under 5 s.
- ADR-0010: amend D11, add "Amended 2026-11-06 (owner): HTML is rejected with `html_too_complex` before parsing when it has a run of 256+ `<` or an estimated nesting depth above 4096 (start minus end tags; void, optional-end and foreign self-closing tags not counted; comments and raw-text content skipped). Reason: Lexbor is quadratic on these (1 MiB `<` run 5.5 s, 60k nested divs 4.5 s). The estimate can be wrong in both directions; it is a cost guard, not a validator." Add `html_too_complex` to the Evidence line pointing at the new tests.
