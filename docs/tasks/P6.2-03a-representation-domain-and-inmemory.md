## Goal
- Synthetic representations are defined per chunk: R23 summaries and questions, R24 context prefixes. They are linked to one original chunk of one index version, always labelled synthetic, and scope-checked.
- A shared conformance check proves the rules on the in-memory store. P6.2-03b runs the same check on PostgreSQL.

## Change
- Create `docs/decisions/ADR-0018-chunk-representations.md` (short). It records:
  - Representations are synthetic, never evidence, and keyed by `representation_key` = sha256 of the generator config.
  - They are embedded with the index's own embedding profile.
  - They are immutable, and scoped through the chunk foreign key.
  - Search returns the original chunk text.
- Edit `docs/decisions/README.md`: add rows for ADR-0017 (`ADR-0017-sparse-encoder-port.md`, "Sparse encoder port", accepted) and ADR-0018 ("Chunk representations", accepted).
- Create `packages/domain/src/rag_foundry_domain/representations.py`:
  - `RepresentationKind = Literal["summary","question","context_prefix"]`.
  - `RepresentationSet(representation_key: ^[0-9a-f]{64}$, technique_id: ^R[0-9]{2}$, generator_json: str of at most 8000 chars)`.
  - `NewRepresentation(chunk_id, kind, ordinal 0..15, text 1..4000 chars, text_sha256, embedded_input_sha256, embedding)`. Validators: `text_sha256` matches; `summary` and `context_prefix` require ordinal 0.
  - `RepresentationRecord`: the same fields without the embedding, plus `index_version_id`, `tenant_id`, `project_id`, `representation_key` and `synthetic: Literal[True] = True`.
  - `ScoredRepresentation(chunk: ChunkRecord, representation: RepresentationRecord, distance, rank)`.
  - `representation_key_for(payload: dict) -> str` (sha256 of canonical JSON: sorted keys, compact separators, `ensure_ascii=False`).
- Edit `ports.py`: add a runtime-checkable `RepresentationStore` with:
  - `add_representations(scope, index_version_id, rep_set, rows)`;
  - `get_representation_set(scope, index_version_id, key)`;
  - `representation_search(scope, index_version_id, key, query, k)`.

  Do NOT add these to `IndexRepository`.
- Rules shared by every implementation (`IndexingError` codes):
  - **Scope and readiness.** The index must be in scope (NotFoundError) and ready (`not_ready`).
  - **Row checks.** At most 500 rows per call (`too_many_rows`); 0 rows is allowed and writes nothing, not even the set. Every `chunk_id` must be in this version and scope (NotFoundError). The embedding length must equal `embedding_dim` (`dimension_mismatch`).
  - **Sets and duplicates.** The same key with a different technique_id or generator_json raises `representation_set_conflict`. A duplicate (chunk, key, kind, ordinal) raises `duplicate_representation`.
  - **Search.** `k` must be in 1..100 (`invalid_k`). A known key with no rows raises `representations_unavailable`; an unknown key raises NotFoundError. Order is by cosine distance, then chunk ordinal, then kind (string order), then ordinal.
- Edit `index_testing.py`:
  - `InMemoryIndexRepository` implements the port.
  - Add `check_representations(factory)` and `REPRESENTATION_STORE_CHECKS = (check_representations,)`.
  - The check uses dim 4, chunks A and B, and rows A summary (1,0,0,0), B question 0 (0,1,0,0), B question 1 (0.6,0.8,0,0). Query (1,0,0,0), k=3 -> order A/summary, B/question/1, B/question/0, with distances approx 0.0, 0.4, 1.0. k=2 -> the first two.
  - Every rule above is exercised once, including a stranger scope, and the check asserts `synthetic is True` on returned records.
- Create `tests/domain/test_representations.py`: model validators (hash mismatch, a summary with ordinal 1, a bad key and a bad technique_id are rejected) and `REPRESENTATION_STORE_CHECKS` on the in-memory repository, built like `tests/domain/test_indexing.py` does for `INDEX_REPOSITORY_CHECKS`.
