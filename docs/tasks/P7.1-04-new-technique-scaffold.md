## Goal
`uv run python scripts/new_technique.py <ID> --kind <kind> --fidelity <f> --out <dir>` writes a plugin package skeleton and a contract test for a catalogue ID that already exists. It never edits the catalogue. It refuses invalid input with exit code 2.

## Read only these files
- `examples/plugins/rag_foundry_sample_plugin/pyproject.toml` and `src/rag_foundry_sample_plugin/__init__.py` (the shape to generate)
- `packages/techniques/src/rag_foundry_techniques/contract.py`, `catalogue.py` (`kinds_for`), `kinds.py` lines 88-193 (`Chunker`, `Retriever`, `Fusion` signatures)
- `scripts/human_labels.py` (argparse/exit-code style of an existing script)

## Change
- Create `scripts/new_technique.py` with `main(argv=None) -> int`.
  - Arguments:
    - `technique_id` (positional);
    - `--kind` (required unless the category allows exactly one kind);
    - `--fidelity` (required; `faithful|adaptation|simulation`; no default);
    - `--out` (required);
    - `--package` (optional; default `rag_foundry_plugin_<id lower>`; must match `re.fullmatch(r"[a-z][a-z0-9_]{2,60}", ...)`);
    - `--catalogue` (default `config/techniques.json`, resolved to an absolute path).
  - Exit with code 2 and one stderr line when:
    - the ID is unknown (case-sensitive, so `c05` is refused);
    - the catalogue `status` is `implemented` or `validated`;
    - the kind is not in `kinds_for(ID)`;
    - `--out` exists and is not empty;
    - the package name is invalid;
    - a built-in plugin already exists for the ID. Check this by registering the chunking and indexing built-ins into a fresh registry; the message says that discovery would fail with `DuplicatePluginError`.
  - It writes, in ASCII only:
    - `pyproject.toml`, with the entry point `<ID> = "<pkg>:Plugin"`;
    - `src/<pkg>/__init__.py`, containing `Config(extra="forbid")` with no fields, `Plugin` with the manifest (ID, kind, `0.1.0`, the given fidelity), and `__init__(self, config)`. The kind method:
      - for `chunker`: `chunk`;
      - for `retriever`: `async retrieve`;
      - for `fusion`: `fuse`;
      - for other kinds: no method, plus a comment that the kind protocol is not frozen yet;
      - the body always raises `TechniqueUnavailableError("<ID> scaffold: not implemented")`.
    - `tests/test_contract.py`:
      - It reads the catalogue path from `os.environ.get("RAG_FOUNDRY_CATALOGUE", "<absolute --catalogue path written at generation time>")`.
      - It calls `check_plugin_contract(Plugin, load_catalogue(path), sample_config={})`.
      - Only for `chunker`, `retriever` and `fusion` does it also assert that the method raises `TechniqueUnavailableError`. For kinds with no method (for example `graph_builder`), the generated test runs only the contract check.
    - `README.md`, pointing to `docs/templates/TECHNIQUE.md` and to the trusted-code note.
  - It prints the files it created. It opens `config/techniques.json` read-only, through `load_catalogue`.
- Create `tests/techniques/test_new_technique_script.py`. Load the script with `importlib.util.spec_from_file_location`. Cases:
  - generate C11 `chunker` and R38 `graph_builder` into `tmp_path`; the files exist and are ASCII;
  - the sha256 of `config/techniques.json` is unchanged;
  - the generated module, imported through `syspath_prepend` with `monkeypatch.delitem(sys.modules, <pkg>, raising=False)`, passes `check_plugin_contract`. The C11 `chunk` raises `TechniqueUnavailableError`;
  - the generated test file passes `compile()`;
  - for both generated packages, the generated test passes in `subprocess.run([sys.executable, "-m", "pytest", "-q", "tests/test_contract.py"], cwd=<out>, env={**os.environ, "PYTHONPATH": <out>/src, "RAG_FOUNDRY_CATALOGUE": <repo catalogue>})`; the exit code is 0;
  - each refusal returns 2:
    - X99;
    - c05;
    - R02 (implemented);
    - C05 (implemented, and a built-in exists);
    - a wrong kind;
    - a non-empty out dir;
    - a bad package name.

## Constraints
