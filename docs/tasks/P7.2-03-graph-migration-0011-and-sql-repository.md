## Goal

## Change
- Create `.../versions/0011_entity_graphs.py` (revision `0011_entity_graphs`, down `0010_chunk_representations`).
  - Raw SQL, following the 0003-0010 index-table convention; no ORM models.
  - Every table has `tenant_id, project_id, index_version_id, graph_key`. Every child FK carries all four scope columns.
  - `entity_graphs(technique_id varchar(8), generator_json text, created_at)`:
    - PK `(index_version_id, graph_key)`; `UNIQUE (graph_key)`; `UNIQUE (tenant_id, project_id, index_version_id, graph_key)`;
    - FK `(tenant_id, project_id, index_version_id)` to `index_versions`;
    - checks: key `^[0-9a-f]{64}$`, technique `^R[0-9]{2}$`, generator length at most 8000;
    - ready-only insert trigger.
  - `graph_entities(entity_id varchar(20), name text, type varchar(64))`:
    - PK `(index_version_id, graph_key, entity_id)`; `UNIQUE (tenant_id, project_id, index_version_id, graph_key, entity_id)`;
    - FK on the four scope columns to `entity_graphs`;
    - checks: `^ent_[0-9a-f]{16}$`, name length 1-500, type length 1-64.
  - `graph_relations(relation_id varchar(20), source_id, target_id, label varchar(200))`:
    - PK `(index_version_id, graph_key, relation_id)`; `UNIQUE (tenant_id, project_id, index_version_id, graph_key, relation_id)`;
    - FK on the four scope columns to `entity_graphs`;
    - FKs `(tenant_id, project_id, index_version_id, graph_key, source_id)` and the same with `target_id`, to the `graph_entities` unique;
    - checks: `^rel_[0-9a-f]{16}$`, label length 1-200.
  - `graph_spans(owner_kind varchar(8), owner_id varchar(20), ordinal smallint, chunk_id uuid, extraction_view_id uuid, start_cp int, end_cp int, quote text)`:
    - PK `(index_version_id, graph_key, owner_kind, owner_id, ordinal)`;
    - FKs: the four scope columns to `entity_graphs`; `(tenant_id, project_id, index_version_id, chunk_id)` to `chunks`; `(tenant_id, project_id, index_version_id, extraction_view_id)` to `index_version_views`;
    - checks: `owner_kind IN ('entity','relation')`, `0 <= start_cp < end_cp`, `char_length(quote) = end_cp - start_cp`, ordinal 0-49.
  - Trigger `graph_spans_validate_insert` (BEFORE INSERT) raises `integrity_constraint_violation` unless all of these hold:
    - (a) `extraction_view_id` equals the chunk's view;
    - (b) `chunk.start_cp <= start_cp AND end_cp <= chunk.end_cp`, using the real chunk offset column names from 0003;
    - (c) `quote = substr(chunk.text, start_cp - chunk.start + 1, end_cp - start_cp)`;
    - (d) `owner_id` exists in `graph_entities` (for `entity`) or `graph_relations` (for `relation`) with the same scope and `graph_key`.
  - Scope indexes on the child tables. No-update triggers on all four tables reuse `reject_index_update()`.
  - The downgrade drops the triggers, the 0011 functions, the indexes and the tables in reverse order. It must **not** drop `reject_index_update()`: 0003 owns it.
- `index_repository.py`: `add_entity_graph` and `get_entity_graph`, matching the in-memory semantics and codes.
  - Lock and check the version as `add_representations` does.
  - Check spans against chunk text before insert (`graph_source_mismatch`).
  - Insert graph, entities, relations, then spans, all in one transaction. A unique violation on the key becomes `graph_exists`.
  - `get` filters every query by tenant, project and version, and rebuilds a sorted `EntityGraph`.
