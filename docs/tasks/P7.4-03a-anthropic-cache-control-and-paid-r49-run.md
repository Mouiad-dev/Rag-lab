## Goal
A chat request can ask for a cache breakpoint after the system prefix. Only profiles that declare the capability accept it; the Anthropic adapter sends `cache_control: {"type": "ephemeral"}` (5-minute TTL) on the system block and records cache read/creation tokens. One opt-in paid test runs the R49 probe on Haiku 5.5 under a budget guard that refuses to start above USD 0.05.

Precondition (orchestrator, verified 2026-11-22 at https://platform.claude.com/docs/en/build-with-claude/prompt-caching and the models overview; re-check if the run is later than 2026-11-29): `cache_control` goes on content blocks (system blocks allowed), max 4 breakpoints, default 5-minute TTL refreshed on hit (`"ttl": "1h"` exists; not used); minimum cacheable length for Claude Haiku 5.5 is 512 tokens and shorter prompts are silently not cached; usage has `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens` and nested `cache_creation.{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}`. Model `claude-haiku-5-5`; per MTok (prompt <= 100k): input 0.10, 5m write 0.125, 1h write 0.20, cache read 0.01, output 0.50 USD.
