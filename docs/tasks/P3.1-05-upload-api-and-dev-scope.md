## Goal
`/api/v1` routes accept a document upload, a new version of an existing document, and return version metadata, scoped by an `AuthContext` dependency. Over HTTP: re-uploading the same bytes returns the existing version (200, `deduplicated: true`); changed bytes create version n+1 (201). Size is enforced while the body streams.

## Change
- **Verify first (ADR-0009 "Evidence")**: from python-multipart docs, PyPI and GHSA/OSV only: current stable version at least two weeks old, Python 3.12 support, every past advisory with first fixed version; and in the locked Starlette: `Request.form(max_files=, max_fields=, max_part_size=)` exists, which exceptions it raises (400) and where it spools file parts. Pin python-multipart exact (`==`) in `apps/api/pyproject.toml`; add `rag-foundry-ingestion`, `rag-foundry-storage[sql]`.
- `rag_foundry_api/limits.py`: pure ASGI middleware for the two upload paths. `Content-Length` > `max_upload_bytes + MULTIPART_OVERHEAD` (64 KiB constant) → 413 before reading. Otherwise it wraps `receive`, counts `http.request` body bytes (works for chunked bodies) and, once the total exceeds that bound, raises an internal error that the middleware turns into the 413 envelope (if the response has not started). `limits.py` sits outside any catch-all `Exception` handler so that error always reaches the middleware.
- `rag_foundry_api/auth.py`: `AuthContext(tenant_id, project_ids)`; in `dev`/`test` returns `LOCAL_DEV_SCOPE`; in `prod` 401 `auth_not_configured`. A path `project_id` not in `project_ids` → 404 identical to unknown.
- `rag_foundry_api/documents.py` router under `/api/v1`:
  - `POST /projects/{project_id}/documents` and `POST /projects/{project_id}/documents/{document_id}/versions`: `async with request.form(max_files=1, max_fields=0) as form`; exactly one `UploadFile` named `file`; its `content_type` is passed raw to `IntakeService` (parsing is 03's job), its filename as `filename`; chunks read via `await upload.read(1 MiB)`. Starlette's 400 for too many files/fields or a bad body, missing `file`, non-multipart → 422.
  - `GET /documents/{document_id}/versions/{version_id}`: tries each scope from `AuthContext` in sorted `project_id` order; first hit wins; none → the same 404.
  - Response: `document_id`, `version_id`, `version_number`, `sha256`, `size_bytes`, `media_type`, `text_encoding`, `original_filename`, `created_at`, `deduplicated`. No object key or paths. 201 created, 200 dedup.
- `rag_foundry_api/errors.py`: one envelope `{"error": {"code", "message", "request_id", "retryable"}}` with `request_id` a per-request UUID4. Handlers: `RequestValidationError` → 422, `HTTPException` → its status, `IntakeError` subclasses → 413/415/422/404, `ObjectStoreError` → 500 with a fixed safe message, no `database_url` → 503 `storage_unavailable`.
- `main.py`: `create_app(settings, *, intake_service=None)`. Without injection: if `database_url` is set, build `LocalObjectStore(settings.object_store_root)` + `SqlDocumentRepository` and, in dev/test, call `ensure_local_scope(LOCAL_DEV_SCOPE)` at startup; if unset, skip both and upload/GET routes return 503. `/health` unchanged.
- Tests `tests/api/test_documents.py` (TestClient, injected `IntakeService(LocalObjectStore(tmp_path), InMemoryDocumentRepository([LOCAL_DEV_SCOPE]))`): done-criterion flow; Arabic filename round trip; 413 by `Content-Length`; 413 for an oversize **chunked** body (generator body, no `Content-Length`); two file parts → 422; extra text field → 422; non-multipart → 422; 415; other project → 404; prod → 401; no `database_url` and nothing injected → 503 and `/health` still 200; every error has the envelope and a UUID4 `request_id`; no `object_key` in responses. One `db` test (needs `RAGF_TEST_DATABASE_URL`) end to end with the SQL repository.
