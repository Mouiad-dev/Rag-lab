## Goal
The Anthropic adapter has a safe base. The API key is read only from `ANTHROPIC_API_KEY` and held as a `SecretStr`. Every request carries the verified headers, and every HTTP or Anthropic error maps to a typed `ProviderCallError` that never contains the key, request text or the provider's message.

## Change
- Edit `errors.py`:
  - Extend `ProviderCallReason` with `auth`, `rate_limited`, `overloaded`, `server_error`, `invalid_request` and `refused`.
  - Add `MissingCredentialError(ProviderError)`. Its message names the variable only, for example "environment variable ANTHROPIC_API_KEY is not set or empty".
  - `AdapterDependencyError(extra: str = "ollama")`, so the message names the right extra; the existing message is unchanged.
- Edit `pyproject.toml`: add `anthropic = ["httpx==0.28.1"]`, then run `uv lock`.
- Create `adapters/_anthropic_http.py`:
  - `read_api_key(env_var="ANTHROPIC_API_KEY") -> SecretStr` reads `os.environ` at call time. Empty or whitespace-only values raise `MissingCredentialError`.
  - `build_headers(key: SecretStr) -> dict[str, str]` sets `x-api-key`, `anthropic-version` (the verified value as a module constant with its source URL) and `content-type`.
  - `anthropic_status_error(profile_id, status, body_bytes)` maps per the P2.3-01 table: 400 → `invalid_request`, 401/403 → `auth`, 404 → `model_not_found`, 413 → `input_too_long`, 429 → `rate_limited`, 500 → `server_error`, 529 → `overloaded`, other non-2xx → `bad_response`. It may read `error.type` to refine the mapping but never copies `error.message`.
  - `post_messages(api_base, payload, *, key, timeout_s, transport, profile_id) -> dict` uses the same client rules as `post_json`: `trust_env=False`, no redirects, no retries, httpx errors mapped via `map_http_error`.
- Create `tests/providers/test_anthropic_http.py` (MockTransport, sentinel key `sk-ant-TEST-SENTINEL-<uuid4>` set via `monkeypatch.setenv`):
  - Headers are present; the key appears only in the `x-api-key` header of the outgoing request.
  - Missing, empty or whitespace key raises `MissingCredentialError` without the value.
  - Each status in the table maps to its reason. A body whose `error.message` contains a canary string does not leak it.
  - Leak check: capture the root logger at DEBUG, including `httpx`, `httpcore` and `h11`, for success, 401, 429, 529 and connection-error paths. The sentinel is absent from all log records, `str()`/`repr()` of errors, and `traceback.format_exception` of the raised errors including causes.
  - With `ANTHROPIC_API_KEY` set, `load_settings()` succeeds and no `Settings` field contains the sentinel. `RAG_FOUNDRY_ANTHROPIC_API_KEY` is still rejected as unknown.
