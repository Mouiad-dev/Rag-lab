## Goal
A pipeline declares what each stage needs; `resolve_pipeline` rejects it before any adapter is built or any key is read when a bound profile lacks a capability (for example `tool_calling`) or is the wrong kind. `build_registry` binds adapters for the bound profiles only. One test runs two stages on two providers.

## Change
- Edit `errors.py`: `UnboundStageError(ProviderError)` listing every stage the pipeline needs that config does not bind (names only).
- Edit `adapters/anthropic.py`: `AnthropicChatModel(..., api_key_env: str = "ANTHROPIC_API_KEY")` passed to `read_api_key`; nothing else changes.
- Create `rag_foundry_providers/pipeline.py`:
  - `StageNeed(kind: ModelKind, required: frozenset[Capability] = frozenset())` (frozen, accepts strings).
  - `resolve_pipeline(config, needs: Mapping[str, StageNeed]) -> dict[str, StageRequirement]`: raises `UnboundStageError` first; then builds a profiles-only `ProviderRegistry` and calls `validate_requirements` with each stage's `required` plus its kind capability (`chat`/`embeddings`/`reranking`), so kind and capability gaps come back in one `MissingCapabilityError`. Reads no env var, constructs no adapter.
  - `build_registry(config, *, stages: Iterable[str], transports: Mapping[str, Any] | None = None, clock=None) -> ProviderRegistry`: registers all profiles, constructs and binds adapters only for profiles bound to `stages`, keyed by endpoint adapter (`fake` → `FakeChatModel/FakeEmbeddingModel/FakeReranker(profile, clock=...)`; `ollama`, `anthropic`, `openai_compatible` with `api_base=endpoint.base_url`, `api_key_env=endpoint.api_key_env`, `transport=transports.get(endpoint.id)`). Unknown adapter/kind pair (for example Anthropic embeddings) → `ProviderUnavailableError`. A missing key raises `MissingCredentialError` naming only the variable; unbound paid profiles need no key.
- Create `tests/providers/test_pipeline_selection.py` (network guard active):
  - **Done 1:** a `generator` stage needing `tool_calling` bound to `local-chat` (declared `False`) is rejected with `MissingCapabilityError` naming stage, profile and capability; same with `declared=None`; no adapter constructed (use a transport that fails if called).
  - **Done 2:** config with `generator` → fake chat and `embedder` → Ollama embedding (MockTransport); `build_registry` then one `complete` and one `embed` call succeed; `Usage.provider` differs (`fake` vs `ollama`).
  - Kind mismatch (embedding profile on a chat stage), unbound stage, `local` requirement rejecting a non-local profile, all gaps listed together, missing key for a bound Moonshot-style profile (sentinel absent from the error), unbound paid profile needs no key.
  - `REGISTRY_CHECKS` pass on a registry from `build_registry`.
- Edit `README.md`: "Config and per-stage selection (P2.4)": file format, `api_key_env`, OpenAI-compatible endpoints, capabilities not implemented yet.
- Edit ADR-0001: "Update 2026-11-xx (P2.4)": JSON config (not YAML), direct OpenAI-compatible adapter, tool-calling and structured-output success paths deferred (owner's chosen steps), LiteLLM status.
