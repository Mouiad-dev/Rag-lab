## Goal
`HybridRetriever` (R06) runs one lexical branch (R03 offline, or R04 with Postgres) and the R02 dense branch on the same scope and index version, fuses them with R07 or R08, and returns hits that show both branches' evidence. If a branch fails, the whole retrieval fails. It never falls back silently.

## Change
- Create `rag_foundry_indexing/hybrid.py`:
  - `HybridConfig` (frozen, `extra="forbid"`): `k: 1..50 = 5`, `branch_k: 1..50 = 20` (each branch's own k), `lexical: Literal["R03","R04"] = "R03"`, `fts_operator: Literal["and","or"] = "or"` (used only for R04), `fusion: Literal["R07","R08"] = "R07"`, `rrf_k: 1..1000 = 60`, `lexical_weight: float 0.0..1.0 = 0.5` (R08 only; dense weight = 1 - lexical_weight).
  - `HybridRetriever` manifest `R06`, `PluginKind.RETRIEVER`, `Fidelity.ADAPTATION`, `1.0.0`. Constructor `(config, *, scope, index_version, index, embedder, full_text=None)`. `lexical="R04"` with `full_text is None` raises `IndexingError("fts_unavailable")` here, in the constructor. It builds `BM25Retriever(BM25Config(k=branch_k))` or `FtsRetriever(FtsConfig(k=branch_k, operator=fts_operator))`, plus `DenseRetriever(DenseConfig(k=branch_k))`, all with the same scope and index_version.
  - `retrieve(query)`: first `index.get_index_version(scope, id)` (NotFoundError passes through). The state must be `ready`, or `IndexingError("not_ready")`. Then run the branches **sequentially**, lexical first then dense (never `gather`: a repository session must not be shared by concurrent tasks). Any branch error propagates unchanged. Fuse `[lexical_result, dense_result]` with `RrfFusion(RrfConfig(k=k, rrf_k=rrf_k))` or `WeightedFusion(WeightedConfig(k=k, weights={lex: lexical_weight, "R02": 1 - lexical_weight}))`. The two weights always sum to 1. Return the fused hits unchanged, with `technique_id="R06"` and `scoring` = `hybrid[R03+R02]/R07:rrf-k60` or `hybrid[R03+R02]/R08:weighted-minmax:wl=0.50` (use the actual IDs and values).
- `retrievers.py` `register_builtin_plugins`: register `HybridRetriever`. `__init__.py`: export `HybridConfig`, `HybridRetriever`.
- Create `tests/indexing/_inmemory_index.py` (test helper, reused by P5.2-03): `async def ready_index(paragraph_spans, embedder)`, where `paragraph_spans` is a list of `(start, end, text)`. It creates owner and stranger scopes, an `InMemoryDocumentRepository`, an extraction view and an index version from `make_new_index_version((view.id,), dim=embedder.profile.capabilities.embedding_dim).model_copy(update=...)`. The update sets `embedding_profile_id`, `embedding_provider`, `embedding_model` and `embedding_key=embedding_key_for(provider, model, dim)` from `embedder.profile`. It adds one `NewChunk` per span (ordinal i, real start/end, `block_ids=("b00000",)`, text sha256, embedding from `await embedder.embed([text], input_type="document")`), calls `mark_ready`, and returns `(owner, stranger, index, version)`. Add `ready=False` to stop before `mark_ready` and return the building version.
- Create `tests/indexing/test_hybrid.py` using `ready_index` and `LexicalTestEmbedder` (non-ASCII only as `\u` escapes):
  - Texts: `"the tidal observatory records sea levels"`, `"رقم القطعة AB-1234"`, `"رقم القطعة AB-1243"`, `"chess club meets on tuesday"`. Spans are consecutive offsets joined by `"\n\n"`.
  - Query `AB-1234`, default config: rank 1 is the AB-1234 chunk. Its components include `bm25_term` term `ab-1234` with `source="R03"`, a `cosine_similarity` with `source="R02"`, and two `rrf_contribution` that sum to `score`. `result.technique_id == "R06"`, and `index_version_id` equals the version id.
  - Fused chunk_ids are a subset of the union of the R03 and R02 results run separately with `k=branch_k`.
  - R08 with `lexical_weight=1.0`: on the chunks both branches return, the hit order is the R03 order. With `0.0`: the R02 order.
  - A stranger scope gets NotFoundError. A building version (`ready=False`) gives `not_ready`, and the embedder records no query call. `lexical="R04"` without `full_text` gives `fts_unavailable` at construction. `lexical="R04"` with `full_text=index` (the in-memory repo raises `fts_unavailable` on search) gives `fts_unavailable`, not dense-only hits.
  - A punctuation-only query `"?!"` gives `no_query_terms` from the R03 branch (no dense-only fallback). The embedder records no query call (lexical runs first).
  - Registry: `validate_config("R06", {}) == HybridConfig()`; `{"lexical": "R05"}` is rejected.
