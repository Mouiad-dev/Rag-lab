## Goal
Three pure, deterministic chunker plugins on the P3.4 `Chunker` interface, registered under their catalogue IDs: C01 cuts at a code-point budget, C02 at a word count, C03 at a token count. All three share one unit-packing core so C04 (P4.1-02) can add overlap on top of it. Offsets are code points on the canonical (NFC) text, like C05.

## Change
- Create `packages/chunking/src/rag_foundry_chunking/_units.py`:
  - `Unit = tuple[int, int]` (code-point `start`, `end`).
  - `char_units(text) -> tuple[Unit, ...]`: clusters; a new unit starts at index `i > 0` only when a cut before `i` is safe, using the same rule as C05: unsafe when `text[i]` is a combining mark (`unicodedata.combining != 0`), U+200D, U+FE0E, U+FE0F, or `text[i-1] == "\r"` and `text[i] == "\n"`. Units cover the whole text, contiguous, in order. Do not import the private helper from `recursive.py`; write the rule here (do not edit `recursive.py`).
  - `word_units(text)`: maximal runs of non-whitespace code points (`str.isspace` is the only separator; this is the documented "whitespace word" assumption: punctuation such as U+060C, U+061F stays attached to its word; text without spaces is one word).
  - `Tokenizer` Protocol: `name: str`; `token_spans(self, text: str) -> tuple[Unit, ...]` (ascending, non-overlapping, never containing whitespace).
  - `LabRegexTokenizer` (`name = "lab-regex-v1"`): an offline stand-in for a model tokenizer, documented as such in its docstring. Tokens: a maximal run of letters and marks (unicode category starting with `L` or `M`); a run of decimal digits (category `Nd`) split into pieces of at most 3; every other non-whitespace code point alone; whitespace is never part of a token. Simple loop over code points, no regex required.
- Create `packages/chunking/src/rag_foundry_chunking/_windows.py`:
  - `pack_windows(text, units, weights, size, overlap) -> tuple[ChunkSpan, ...]`. Window from unit `i` takes units while the summed weight stays `<= size` (always at least one unit). The next window starts at the earliest unit `j` with `i < j <= window_end_index` such that the weight of units `j..window_end_index` is `<= overlap` and the window from `j` would include at least one unit after `window_end_index`; if none, it starts right after the window. Stop after the window that reaches the last unit. Each span is `units[first].start .. units[last].end`, trimmed of edge whitespace (`str.isspace`); drop empty spans and spans whose end is `<= ` the previous emitted end. `split_level=0`. Output sorted by `(start, end)`. Must stay linear-ish: 1M code points with `size=800` in < 5 s.
- Create `packages/chunking/src/rag_foundry_chunking/fixed.py` with three plugins (all `PluginKind.CHUNKER`, version `1.0.0`, frozen `extra="forbid"` configs, store `self.config`):
  - C01 `FixedCharChunker` / `FixedCharConfig(chunk_size: int = 800, ge=8, le=8000)`, `Fidelity.FAITHFUL`: `pack_windows` over `char_units`, weight = unit length in code points, overlap 0. A span is longer than `chunk_size` only when one cluster alone is longer.
  - C02 `FixedWordChunker` / `FixedWordConfig(words_per_chunk: int = 150, ge=1, le=2000)`, `Fidelity.FAITHFUL`: over `word_units`, weight 1, overlap 0.
  - C03 `FixedTokenChunker` / `FixedTokenConfig(tokens_per_chunk: int = 256, ge=8, le=8192; tokenizer: Literal["lab-regex-v1"] = "lab-regex-v1")`, `Fidelity.ADAPTATION` (not a real model tokenizer yet). `__init__(self, config, tokenizer: Tokenizer | None = None)`: default is `LabRegexTokenizer()`; an injected tokenizer is used as given (for tests and later real tokenizers). Over `tokenizer.token_spans(text)`, weight 1, overlap 0.
  - All three ignore `doc.blocks`.
- Edit `packages/chunking/src/rag_foundry_chunking/__init__.py`: import and export the three chunkers and configs, `Tokenizer`, `LabRegexTokenizer`; `register_builtin_plugins` registers them after `RecursiveChunker` (add lines only; keep the existing lines unchanged).
- Create `tests/chunking/test_fixed.py` (all non-ASCII as `\u` escapes; build Arabic samples NFC and assert `unicodedata.is_normalized("NFC", text)`):
  - C01: offsets exact (`text[s.start:s.end]` is the chunk), deterministic, sorted, no overlap between adjacent spans, every non-whitespace code point covered exactly once, every span `<= chunk_size`; a sentence cut in half: an English sentence with `chunk_size=16` gives a span that ends inside a word (letter on both sides of `end`) - assert this as the documented behavior; a run of `بَ` is never cut before `َ`; ZWJ, VS16 and CRLF never split (same cases as `test_recursive.py`); whitespace-only text gives `()`.
  - C02: each span has `<= words_per_chunk` whitespace words and the words of all spans, in order, equal `text.split()`; Arabic `،` and `؟` stay attached to the preceding word (span text ends with them when the chunk ends there); a mixed-script token without space (Latin letters directly followed by Arabic letters) counts as one word; spans never start or end with whitespace.
  - C03: with the default tokenizer each span re-tokenizes to `<= tokens_per_chunk` tokens and the total over spans equals the token count of the whole text; Arabic text with harakat keeps marks inside letter tokens (`بَا` is one token); digits `"2026"` give tokens `"202"`, `"6"`; a test shows character and token counts differ for the same text (English sentence vs. its token count); an injected fake tokenizer (one token per code point, `name="fake"`) is used instead of the default; config rejects `tokenizer="gpt2"` and unknown keys.
  - Registry: `register_builtin_plugins` then `validate_config` for C01, C02, C03 with `{}` equals the default configs; `registered_ids()` contains `C01`..`C05`.
  - Seeded random property test (300 texts over an alphabet with spaces, `\t`, `\n`, `\r`, Arabic letters, `َ`, `‍`, `.`, digits) for all three: strictly increasing starts and ends, no span contained in the previous one, no edge whitespace, size limits hold, every non-whitespace code point covered.
