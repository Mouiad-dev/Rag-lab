## Goal
One metered chat call generates up to n query variants. R14 retrieves with the original plus the variants and merges by best rank (expansion without fusion). R18 retrieves the same way and fuses with the R07 reciprocal-rank formula (expansion plus fusion), so a later ablation can separate the two. Each hit shows which query found it at which rank.

## Change
- `fusion.py`: add `def rrf_contribution(rank: int, rrf_k: int) -> float` (`1 / (rrf_k + rank)`) and make `RrfFusion.fuse` use it. Split `check_inputs` so its per-result checks (contiguous ranks `fusion_invalid_ranks`, `fusion_duplicate_candidate`, `fusion_candidate_conflict`, corpus/version `fusion_version_mismatch`) are callable without the distinct-branch-id and `>= 2` rules, e.g. `check_inputs(results, *, distinct_branches=True, min_branches=2)`. No behaviour change for R07/R08.
- Create `rag_foundry_indexing/multi_query.py`:
  - `MULTI_QUERY_SYSTEM_V1` (untrusted-data sentence; write up to n different search queries for the same need in the question's language; keep every number, identifier, quoted phrase and negation; reply `{"queries": [...]}`) and its sha256.
  - `MultiQueryConfig`: `n_variants 1..5=3`, `k 1..50=5`, `max_output_tokens 64..1024=256`, `temperature 0..2|None=0.0`, `drop_lossy_variants: bool = True`, `on_invalid: fail|original = "fail"`.
  - `async generate_variants(question, *, chat, config, technique_id) -> QueryTransformTrace`: one `call_json` call.
    - More than `n_variants` items gives `too_many_queries`; a non-string or empty item gives `invalid_model_output`.
    - Duplicates of the original or of each other (NFC, casefold, trimmed) are dropped and counted in `duplicates_dropped`.
    - Each variant records its `lost_constraints`; lossy variants are dropped when `drop_lossy_variants` is set.
    - `retrieval_queries` is the original first, then the kept variants.
  - `async retrieve_all(queries, retriever) -> tuple[RetrievalResult, ...]`: sequential, in order. It then runs `check_inputs(results, distinct_branches=False, min_branches=1)`: same index version and corpus grounding, contiguous ranks, no duplicate candidates, no field conflicts.
  - `MultiQueryExpansion` (R14, `QUERY_TRANSFORM`, `ADAPTATION`), `async run(question, *, chat, retriever) -> TransformedRetrieval`.
    - Union merge by chunk id: order by best rank, then first query index, then chunk id; `score = 1 / best_rank`.
    - Per occurrence `ScoreComponent(name=f"q{i}_rank_score", value=hit.score, source=<inner technique_id>, source_rank=hit.rank)`.
    - `technique_id="R14"`, `scoring="multi-query-union-best-rank"`; `per_query` in query order.
    - Put the merge in a reusable `merge_best_rank(per_query, *, technique_id, scoring, k)`.
- Create `rag_foundry_indexing/rag_fusion.py`: `RagFusionConfig` (same fields plus `rrf_k 1..1000=60`), `RagFusion` (R18, `QUERY_TRANSFORM`, `ADAPTATION`) uses `generate_variants` and `retrieve_all`, then sums `rrf_contribution(hit.rank, rrf_k)` per chunk with components `name=f"q{i}_rrf"`; tie rule as `fusion._result`; `technique_id="R18"`, `scoring=f"rag-fusion-rrf-k{rrf_k}"`.
- `rejected` (with `on_invalid="original"`) retrieves with the original only. Register both; export.
- Create `tests/indexing/test_multi_query.py` and `tests/indexing/test_rag_fusion.py`:
  - Calls: 3 variants give 4 retrieval calls, original first and byte-identical; exactly 1 chat request; `trace.original_question` is exact.
  - Variant filtering: a case/NFC duplicate of the original is dropped (`duplicates_dropped == 1`, 3 calls). A variant missing `AB-1234` is dropped and listed. 6 items with `n_variants=5` give `too_many_queries`.
  - R14: a chunk found only by a variant appears with its `q{i}` component.
  - R18 RRF: one score equals the hand-computed `1/61 + 1/63`.
  - R14 vs R18 on the same inputs: R18 ranks a chunk at rank 2 in all 3 lists above a chunk at rank 1 in one list; R14 puts the rank-1 chunk first.
  - Input checks: mixed `index_version_id` raises `fusion_version_mismatch`. An inner result with ranks `1,3` raises `fusion_invalid_ranks`. The same chunk id twice in one list raises `fusion_duplicate_candidate`.
  - `BudgetedChatModel` with `max_calls=0` raises `BudgetExceededError`, and `retriever.queries == []`. `validate_config` defaults for R14 and R18.
