## Goal

## Change
- **Verify first** (ADR-0010 "Evidence", same table as ADR-0009): official docs, PyPI JSON API, GHSA (`api.github.com/advisories?ecosystem=pip&affects=pypdfium2`) and OSV. Check license (pypdfium2, PDFium, and every bundled third-party notice in the wheel, listed by name and license), release at least two weeks before the task date, Python 3.12 and 3.13 wheels for win_amd64 and manylinux x86_64/aarch64, no advisory affecting the pin (also PDFium CVEs named in the changelog), and the exact APIs: open from bytes, password error code (`FPDF_ERR_PASSWORD`), page count, per-page text, close, and how text is decoded (lone surrogates kept, replaced or dropped). Pin `==` under extra `pdf` of `packages/ingestion/pyproject.toml`; add `rag-foundry-ingestion[pdf]` to the dev group. **Stop and report** on any advisory, license doubt or API mismatch.
- `extract/pdf.py` (`name = "pdf-pypdfium2"`, `version = "1+pypdfium2==<pin>"`):
  - A module-level `threading.Lock` held around every PDFium call (open, count, text, close); PDFium is not thread-safe.
  - Open from bytes. Needs a user password (`FPDF_ERR_PASSWORD`) -> `pdf_encrypted`; owner-password-only PDFs open normally. Other open failures -> `pdf_malformed` (library message never included).
  - Page count above `max_pages` -> `too_many_pages` before reading text. Collect pages in order, checking the running length against `max_chars` after each page (`text_too_long`).
  - Lone surrogates -> U+FFFD one-for-one (`CP`), warning `invalid_text:<page_index>`. Empty page -> warning `page_without_text:<page_index>`; all empty -> `no_text_layer`.
  - Raw text = pages joined by `\n\n` (insertions in `raw_map`, identity elsewhere); `page_starts` = raw offsets; `source_space = "pdf_page_text"`; one block per page with `page_index`. Handles closed in `finally`. No OCR, geometry or rendering.
- Register in `EXTRACTORS` only when the import works; else `unsupported_extractor` naming the missing `pdf` extra.
- Tests `tests/ingestion/test_extract_pdf.py`, PDFs built in the test from raw PDF syntax (Standard-14 Helvetica, ASCII, correct xref offsets):
  - 2 text pages plus one empty page: blocks, `page_index`, warnings, map invariants, two runs equal.
  - Real Standard security handler (V1/R2, 40-bit RC4; key and `/O`, `/U` per PDF 1.7 algorithms 2-4 with stdlib MD5 and a small RC4 in the test): user password set -> `pdf_encrypted`; empty user password with owner password -> text extracted.
  - Garbage bytes -> `pdf_malformed`; `max_pages`; `max_chars`; lone-surrogate handling via a stubbed page text if the library cannot produce one.
  - Threads: 4 concurrent `to_thread` extractions give identical results.
  - Arabic PDF: `skip("needs owner-supplied fixture (ADR-0010 D9)")`.

## Constraints
