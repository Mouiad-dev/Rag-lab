## Change
- Create `packages/domain/src/rag_foundry_domain/settings_store.py`:
  - `NewSettingOverride`: `level`, `scope: Scope | None` (global = None; tenant and project levels need a scope; tenant level uses only `scope.tenant_id`), `key`, `value | None`, `created_by` (`^[A-Za-z0-9._:@-]{1,128}$`), `reason` (1..500 chars). Wrong shape -> `SettingsError("invalid_override")`.
  - `SettingOverride`: `id: int`, `level`, `tenant_id | None`, `project_id | None`, `key`, `value`, `version: int`, `created_by`, `reason`, `created_at: datetime`.
  - `validate_override(new)`: key in `ALLOWED_KEYS`, level in `KEY_SCOPES[key]`, value checked by the resolver of its section on defaults; strings and dicts with non-number values rejected.
  - `SettingsOverrideRepository` Protocol: `async append(new) -> SettingOverride` (calls `validate_override` first; version = current max + 1 for (level, tenant, project, key)); `async current(scope: Scope | None) -> tuple[SettingOverride, ...]` (latest version per (level, key) for global, plus `tenant_id == scope.tenant_id` tenant rows, plus project rows matching BOTH `scope.tenant_id` and `scope.project_id`; ordered global, tenant, project, then key); `async history(level, scope: Scope | None, key)` (version order, same tenant/project filtering).
  - `InMemorySettingsOverrideRepository`.
  - `RuntimeSettingsService(base: RuntimeSettings, *, file_keys=frozenset(), repo=None)`: `base` property; `async run_snapshot(scope: Scope | None) -> RunSnapshot` and `async indexing(scope: Scope | None) -> IndexingSettings` (no repo -> base only; else `repo.current(scope)` -> `resolve_run` / `resolve_indexing`); `async set_override(new) -> SettingOverride`. The service never logs `reason`, `created_by` or values.
- Create `packages/domain/src/rag_foundry_domain/settings_testing.py`: `SETTINGS_REPOSITORY_CHECKS` (async checks taking a factory that returns a repo for given scopes, like `INDEX_REPOSITORY_CHECKS`): versions 1, 2, 3 per key; reset row; `current` returns the latest per level; rows of another tenant and of the same project UUID under another tenant are excluded from `current` and `history`; invalid key, level, value, string value and dict with a string value rejected with nothing stored; `created_at` set.
- Tests `tests/domain/test_settings_store.py`: the suite on the in-memory repo; service layering (global, tenant and project overrides; another project unaffected); a stored bad indexing pair breaks `indexing()` but not `run_snapshot()`; error messages carry no values or reasons.
