## Goal
- An offline demo writes `docs/evidence/P6.4/conversation_demo.md`. It shows R28 success and losing cases with scripted chat and is byte-identical across runs.
- Two opt-in live tests, gated by `RAG_LIVE_OLLAMA=1`:
  - R28 on `gemma4:e4b` over 3 conversations (EN, AR, mixed).
  - R42: the frozen runner on the cross-language dataset with `bge-m3` dense retrieval. This is the first real cross-script measurement.

## Change
- **Demo** `docs/techniques/lessons/demos/p64_conversation_demo.py`: ASCII source with `\u` escapes, public APIs, `ScriptedChat`, no timing values.
  - Header line: the command, the date, and "offline; scripted chat; no model; shows plumbing and guards, not resolution quality".
  - Sections, all using the P6.4-01 test inputs:
    1. **EN follow-up:** the history window, the standalone question, the `synthetic` flags and the retrieval query.
    2. **AR follow-up.**
    3. **Mixed** with Arabic-Indic digits: applied.
    4. **Losing case (a), `unsupported_fact`:** the assistant-only "17" is blocked, so retrieval falls back to the raw follow-up "How often does it record them?", a weak query. Show this as the cost of the guard.
    5. **Losing case (b), `constraint_loss`:** "2025" and "not" are lost.
    6. **Window:** 8 turns with `max_turns=3`, 5 dropped.
    7. **Usage:** chat calls per case (`no_history` = 0).
  - End with `## Live run (orchestrator)` and `<orchestrator>` placeholders. The demo output must equal the file up to that heading.
- **R28 live test** `tests/live/test_conversation_live.py`:
  - Use the `pytestmark` gating and the `OllamaChatModel(ollama_chat_profile(model="gemma4:e4b"), api_base=..., timeout_s=300)` construction from the query-transform smoke, wrapped in `RecordingChatModel` with a `UsageLedger`.
  - Use `ConversationalRewriter(ConversationConfig(on_invalid="original"))`, so a malformed model reply gives `rejected` (metered) instead of raising.
  - Run three conversations from `test_conversation.py`, with their exact histories:
    - test 1 (EN, `t0` + `t1`);
    - test 4 (AR, `t0`);
    - test 5 (mixed, history `(S0,)`).
  - Every one has at least one used user turn, so each makes exactly one call.
  - Assert only invariants:
    - the status is in {`applied`, `rejected`, `constraint_loss`, `unsupported_fact`};
    - `original_question` equals the turn;
    - `generated[0].synthetic is False`;
    - any `rewrite` entry is `synthetic`;
    - `ledger.totals().calls == 3`.
  - Print, per conversation: the status, the standalone text (or `-`), `introduced_constraints`, `lost_constraints`, the tokens and `latency_ms`.
  - Async: `def test_x(): asyncio.run(...)`.
- **R42 live test** `tests/live/test_cross_language_live.py`:
  - Use the same gating and `OllamaEmbeddingModel(ollama_embedding_profile(model="bge-m3"), ...)`.
  - Build `bound_index(RecordingEmbeddingModel(embedder, build_ledger))`.
  - Run the frozen runner on `cross_language_dataset()` with labels R02 (the Ollama embedder), R03 and R06, and `code_version=git_code_version(ROOT)`.
  - Assert that:
    - the run completes;
    - every case has a row per label;
    - the per-pair section lists the 8 pairs.
  - Print `render_language_pairs(...)`, the `run_id` and the index-build usage totals.
  - Module comment: "Ollama embeddings are not guaranteed bit-identical across runs; this live run is not a frozen reproducible result".

## Constraints
- No package code changes. No assertions on model quality (ranks, statuses beyond the allowed set) in live tests. `\u` escapes only.
- Do not append to `cross_language_pairs.md`: the P6.4-03 test compares that whole file. The live R42 output goes to the new file `docs/evidence/P6.4/cross_language_live.md`, written by the orchestrator.
